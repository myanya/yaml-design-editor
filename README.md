# YAML Design Editor

Kotlin + Compose for Desktop + Material 3 製の**スキーマ駆動・汎用 YAML エディタ**。
YAML で設計項目（要求・設計・課題など）を管理するためのツールです。

- 外部のスキーマ定義（`_schemas/*.yaml`）に沿って、YAML ファイルごとに適切なフォームビューを自動生成
- スキーマがないファイルも**汎用ビュー**（再帰的なツリーエディタ）で編集可能
- ワークスペース内の **ID を横断的に索引化**し、参照（ref）のリンクジャンプ・補完・未解決検出・バックリンク表示に対応
- フォーム／ソース／差分の3モード編集、スキーマ検証、ID検索
- 外部変更の自動検出、ファイル／ディレクトリ操作、リサイズ可能な左右ペイン
- `_schemas` 専用のスキーマ設計画面と、`definitions` / `$ref` による再帰定義
- Undo/Redo、保存ショートカット、未保存終了確認、復元されるペインレイアウト
- ライト／ダークを切り替えられるMaterial 3テーマ（選択状態は次回起動時に復元）
- ワークスペース一覧・絞り込み・一括編集、参照グラフ、差分表示、コマンドパレット、最近開いたファイル
- **AIによる作成支援**（OpenAI連携）: フィールド単位・配列への候補追加・文書全体のたたき台生成。スキーマ準拠の構造化出力＋適用前プレビューと検証

---

## 1. ビルドと起動

要件: **JDK 17以上**。Gradle Wrapper（Gradle 9.3.0）を同梱しています。

```bash
cd yaml-design-editor
./gradlew run                                  # サンプルワークスペースで起動
./gradlew run --args="/path/to/your/workspace" # 任意のワークスペースを指定して起動
```

配布物の作成:

```bash
./gradlew packageDistributionForCurrentOS # dmg / msi / deb
```

起動時にカレントディレクトリの `sample-workspace/` が存在すれば自動で開きます。ツールバーの「開く」から任意のディレクトリに切り替えられます。

## 2. 画面構成

```
┌────────────────────────────────────────────────────────────────────────┐
│ 開く 再読込 │ 文書 一覧 グラフ 履歴 │ ID検索 Ctrl+K │ Theme │ ペイン切替 │
├─────────────┬──────────────────────────────────┬───────────────────────┤
│ ファイルツリー │ ファイル名 / スキーマ  Undo Redo 保存 すべて保存 │ 検証│参照│被参照 │
│ 新規・改名    ├──────────────────────────────────┤                       │
│ 削除・展開    │ フォーム │ ソース │ 差分             │                       │
│ ● 未保存      │ 構造化フォーム / YAML / 比較表示     │                       │
├─────────────┴──────────────────────────────────┴───────────────────────┤
│ ステータスバー                                                           │
└────────────────────────────────────────────────────────────────────────┘
```

- ファイル名横の `●` は未保存の編集を表します。ファイルを切り替えても編集内容はメモリ上に保持されます（「保存」「すべて保存」で書き出し）。
- 「フォーム」タブが構造化編集、「ソース」タブがテキスト編集です。ソース固有の「変更を反映」はテキストを内部のYAMLツリーへ取り込み、文書ヘッダーの「保存」はそのツリーをファイルへ書き出します。ソース編集中の `Ctrl+S` は反映と保存を続けて実行します。
- `Ctrl+S` で現在のファイルを保存、`Ctrl+Shift+S` ですべて保存、`Ctrl+Z` / `Ctrl+Y` で編集を元に戻す／やり直すことができます。
- 右ペインは「検証」「参照」「被参照」のタブで切り替えます。object、array、mapはフォーム内で折りたためます。
- 左右ペインはドラッグでリサイズでき、開閉状態・幅・テーマは次回起動時に復元されます。
- ファイルペイン上部からYAML／ディレクトリの作成、名前変更、削除を実行できます。新規YAMLは配置先に適用されるスキーマから初期値を生成します。
- ウィンドウ終了時とワークスペース切替時には未保存確認を表示します。

### 操作の役割

- **変更を反映**（ソースタブ）: 編集中の文字列を解析して内部YAMLツリーへ取り込みます。
- **保存**（文書ヘッダー）: 内部YAMLツリーを現在のファイルへ書き込みます。
- **ソース編集中の `Ctrl+S`**: 反映と保存を続けて実行します。
- **Undo/Redo**: 内部YAMLツリーの編集履歴を最大100件保持します。

### ショートカット

| キー | 操作 |
|---|---|
| `Ctrl+S` | 現在の文書を保存。ソース編集中は反映後に保存 |
| `Ctrl+Shift+S` | ソースを反映後、未保存文書をすべて保存 |
| `Ctrl+Z` | 元に戻す |
| `Ctrl+Y` / `Ctrl+Shift+Z` | やり直す |
| `Ctrl+K` | コマンドパレット |

## 3. ワークスペースの構成

任意のディレクトリを「ワークスペース」として開きます。

```
my-workspace/
├── _schemas/            # スキーマ定義（このディレクトリ名は固定）
│   ├── requirement.yaml
│   └── design-item.yaml
├── requirements/        # 以下は自由な構成。*.yaml / *.yml が対象
│   ├── req-001.yaml
│   └── req-002.yaml
├── designs/
│   └── dsn-001.yaml
└── notes/
    └── memo.yaml        # スキーマにマッチしない → 汎用ビュー
```

各 YAML ファイルには、`_schemas/` 内のスキーマのうち `match`（glob）がワークスペース相対パスに最初にマッチしたものが適用されます（ファイル名の昇順で評価）。どれにもマッチしなければ汎用ビューになります。

## 4. スキーマ定義リファレンス

`_schemas/*.yaml` に 1 ファイル 1 スキーマで配置します。

```yaml
id: requirement                       # 安定したスキーマID（省略時はスキーマファイル名）
name: 要求                             # 表示用のスキーマ名
match: "requirements/**/*.{yaml,yml}" # 適用対象の glob（**, *, ?, {a,b} に対応）
root:                                 # ルートのフィールド定義（通常 type: object）
  type: object
  fields:
    - key: id
      label: 要求ID
      type: id
      required: true
      description: 論理要素を識別するID（同一文書内で一意）
    - key: status
      type: enum
      values: [draft, review, approved, deprecated]
      default: draft
    - key: relates_to
      type: array
      item:
        type: ref
        idPattern: "REQ-*"            # 利用者定義のID体系で候補を限定
        scope:
          schemaIds: [requirement]    # 安定したスキーマIDで探索範囲を限定
```

### フィールド定義のプロパティ

| プロパティ | 説明 |
|---|---|
| `key` | 親オブジェクト内のキー名（ルート・配列要素では不要） |
| `label` | フォームでの表示名（省略時は `key`） |
| `type` | 下表の型（省略時 `string`） |
| `required` | `true` で必須。未設定は検証エラー |
| `values` | `enum` の選択肢 |
| `item` | `array` の要素定義（フィールド定義を再帰的に記述） |
| `value` | `map` の値定義（必須。フィールド定義を再帰的に記述） |
| `fields` | `object` の子フィールド定義のリスト |
| `unknownFields` | `object` のスキーマ外項目を `allow` / `warning` / `error` で扱う（省略時 `warning`） |
| `idPattern` / `idPatterns` | `ref` の参照先IDをglob（`*`, `?`）で限定。複数指定はOR |
| `scope.schemaIds` | 参照先を特定スキーマIDに限定。配列内はOR |
| `scope.documentIds` | 参照先を特定ドキュメントIDに限定。配列内はOR |
| `default` | 「追加」「作成」時の初期値 |
| `description` | フォームに表示される説明文 |

### 型一覧

| type | フォーム表現 | 検証 |
|---|---|---|
| `string` | 1 行テキスト | required |
| `text` | 複数行テキスト | required |
| `int` | テキスト（整数変換） | 整数であること |
| `number` | テキスト（数値変換） | 数値であること |
| `boolean` | チェックボックス | 真偽値であること |
| `enum` | ドロップダウン | `values` に含まれること |
| `date` | テキスト | `YYYY-MM-DD` 形式（警告） |
| `id` | テキスト＋重複警告＋被参照数 | 必須チェック、重複検出 |
| `ref` | テキスト＋候補ドロップダウン＋ジャンプボタン | 参照解決 |
| `array` | 要素の追加・削除・並べ替え | 要素ごとに `item` を再帰検証 |
| `map` | 任意キーの追加・削除＋型付き値エディタ | 各キーの値を `value` で再帰検証 |
| `object` | 枠付きのネストフォーム | `fields` を再帰検証 |

`object` / `array` / `map` は任意の深さでネストできます（例: サブ項目の配列の中に `id` を持たせて、サブ項目単位で参照させることも可能）。

`object` にスキーマ外のキーがある場合、既定ではそのキーの位置に警告を1件表示します。`unknownFields: error` ならエラー、`allow` なら通知しません。未知キーの配下はスキーマ検証およびID・参照索引の対象外とし、配下の各要素へ同じ問題を重複表示しません。ルートの予約項目 `_document` はこの検査から除外されます。

### 任意キーのMap

任意の文字列キーを持つ連想配列は `map` で定義します。`value` は必須で、Map内のすべての値に同じフィールド定義が適用されます。

```yaml
root:
  type: object
  fields:
    - key: inputs
      label: 入力
      type: map
      value:
        type: string
```

上記のスキーマでは、次のようなデータをフォームから追加・編集でき、各値が `string` として検証されます。

```yaml
inputs:
  username: ユーザ名
  password: パスワード
  email: メールアドレス
```

`value` には `object`、`array`、`ref`、別の `map` など、すべての型を再帰的に指定できます。

フォームではMapの件数と各キーが表示されます。「キーを追加」で任意のキーを作成し、値は `value` で指定した型のエディタで編集します。キーの重複と空文字は追加できず、不要なキーは行ごとに削除できます。Mapフィールド自体が未作成の場合は「Mapを作成」から空のMapを作成します。

`value` を省略したスキーマはスキーマ定義エラーになります。また、データ側がYAMLマッピングでない場合や、Map内の値が `value` の型に一致しない場合は検証エラーになります。

値をオブジェクトにする場合は、次のように定義します。

```yaml
- key: environments
  type: map
  value:
    type: object
    fields:
      - key: endpoint
        type: string
        required: true
      - key: enabled
        type: boolean
```

```yaml
environments:
  development:
    endpoint: http://localhost:8080
    enabled: true
  production:
    endpoint: https://example.com
    enabled: false
```

ルート定義に `type: map` を指定することもできます。

### 名前付き定義と再帰スキーマ

共通または再帰的な構造は `definitions` に置き、`$ref` で参照できます。

```yaml
name: outline
match: "outlines/**/*.yaml"
definitions:
  node:
    type: object
    fields:
      - key: title
        type: string
        required: true
      - key: children
        type: array
        item:
          $ref: node
root:
  $ref: node
```

`_schemas` 配下のファイルを開くと「スキーマ設計」タブが表示され、名前付き定義や参照を構造化UIで編集できます。

スキーマ設計画面には次の確認機能があります。

- **メタスキーマ検証**: 必須情報、フィールドキー重複、arrayの要素定義、enumの選択肢、未解決の `$ref` を保存前に検出
- **プレビュー**: スキーマからサンプルYAMLを生成し、実際のフォームまたはYAMLとして確認
- **サンプル生成**: 生成したYAMLをクリップボードへコピー
- **適用対象**: `match` に一致するワークスペース内のファイルを一覧表示し、他スキーマとの競合も表示

スキーマファイルを保存すると、メタスキーマ検証結果は通常の右側「検証」パネルにも表示されます。

## 5. ワークスペース横断機能

ツールバーのビュー切替から、次の横断ビューを利用できます。

- **一覧ビュー**: ID、タイトル、状態、担当、種別、ファイルを表形式で表示し、文字列・種別・状態で絞り込み
- **一括編集**: 選択した複数ファイルのルート `status` または `owner` を確認後に一括更新
- **参照グラフ**: ワークスペース内の参照関係をノード／エッジと一覧で表示し、参照先IDへ移動
- **差分**: 文書の「差分」タブで、ディスク上の保存済み内容と編集中内容を左右比較
- **最近開いたファイル**: ツールバーの履歴アイコンから直近12ファイルを再度開く。履歴はワークスペース単位で保存
- **コマンドパレット**: `Ctrl+K` で開き、ビュー切替、保存、ファイル検索、ID移動をキーボード中心で実行

一括編集は対象に未保存文書が含まれる場合は実行されません。実行前には確認ダイアログを表示し、変更後は索引と画面を再読込します。

## 6. ID とリンクの仕組み

### ID の索引化

ワークスペース内のYAMLをスキャンし、`id -> [(ファイル, パス, タイトル, schemaId, documentId)]` の索引を構築します。IDとして認識されるのは:

- スキーマで `type: id` と定義されたフィールドの値
- スキーマの有無に関わらず、キー名が **`id`** であるスカラー値（ネストした要素でも可）

同じIDは複数ドキュメントに定義できます。それらは段階的詳細化された同一論理要素の複数出現として索引化されます。同一ドキュメント内の重複だけが検証エラーです。ジャンプ時に複数出現がある場合は選択ダイアログを表示します。

スキーマの `id` は参照スコープに使う安定識別子、`name` は表示専用です。`id` を省略した場合はスキーマファイル名（拡張子なし）を使います。

ドキュメントIDは任意で次のように宣言できます。省略時はワークスペース相対パスを使います。

```yaml
_document:
  id: system-overview
  name: システム構想
  description: |
    システムの目的、利用者、主要な機能領域を定義する文書。
    後続の要求・設計文書が前提とする全体像を示す。
```

`name` は画面の文書ヘッダーに表示する任意の文書名です。省略時は従来どおりワークスペース相対パスを表示します。
`description` は、全文を読まずに文書の目的と内容を判断するための任意の概要です。フォーム先頭の「文書メタデータ」で文書名と概要を編集できます。これらは将来、LLMへ文書コンテキストを渡す際の要約情報としても利用できます。

### 参照候補の絞り込み

`type: ref` ではID体系と探索範囲を独立して指定できます。

```yaml
type: ref
idPatterns: ["ACTOR-*", "ROLE-*"]
scope:
  schemaIds: [system-concepts, actor-detail]
  documentIds: [system-overview]
```

`idPatterns`、`schemaIds`、`documentIds`の各配列内はOR、異なる条件間はANDです。IDパターンは大文字・小文字を区別します。条件は候補表示だけでなく参照検証にも適用されます。ID自体が存在しても条件外なら検証エラーになります。条件を省略するとワークスペース全体が対象です。

### 参照（リンク）の認識

- スキーマで `type: ref` と定義された位置の値（配列要素含む）
- スキーマ外のキーに対する**命名規約ヒューリスティクス**:
  - キー名 `ref` または `*_ref` のスカラー値
  - キー名 `refs` / `*_refs` / `depends_on` / `relates_to` 配下のスカラー配列

### リンクの機能

- **ジャンプ**: ref フィールドの「→」ボタン、右パネルの「参照」クリックで定義元ファイルを開き、該当要素をハイライト表示＆自動スクロール
- **補完**: ref フィールドのドロップダウンで、IDパターン、スコープ、入力文字列（ID・タイトル部分一致）により候補を選択
- **未解決検出**: 索引にも編集中ドキュメントにも存在しない ID への参照は、赤枠＋検証パネルにエラー表示
- **バックリンク**: 開いているファイルの ID を参照している箇所を「被参照」に一覧表示（クリックで参照元へジャンプ）
- **ID 検索**: ツールバーの検索ボックスから ID・タイトルで横断検索してジャンプ

> **索引の更新タイミング**: 索引はディスク上のファイルに基づき、ワークスペースを開く、再読込、保存、外部変更検出、一括編集のタイミングで更新されます。未保存の編集は他ファイルからの解決・被参照にはまだ反映されませんが、編集中文書内のIDは保存前でも解決されます。

## 7. 検証

右パネルの「検証」に以下が表示され、クリックで該当箇所にジャンプします。

- 必須項目の未設定（`required: true`）
- 型不一致（int / number / boolean / object / array / map）
- `enum` の選択肢外の値
- `date` の形式逸脱（警告）
- 未解決の参照
- ID の重複（同一ファイル内。異なるファイルの同一IDは許容）
- スキーマファイルの構造、未知の型、フィールドキー重複、array/mapの子定義不足、未解決の `$ref`

## 8. 外部変更・競合・安全性

- ワークスペース内のYAMLを約1秒間隔で監視します。
- 未編集のファイルが外部変更された場合は自動的に再読込します。
- 未保存文書が外部変更された場合は自動上書きせず、競合バナーを表示します。
- 競合時は「ディスク版を読み込む」または「編集内容を維持」を選択できます。
- 未保存文書を含む名前変更・削除・一括編集は拒否されます。
- ファイル削除は確認ダイアログを経由します。

## 9. テーマ

Material 3ベースのライト／ダークテーマを搭載しています。深いティール、シアン、バイオレットをアクセントとし、ツールバー、ペイン、エディタ、入力欄、選択状態、警告色を共通トークンで管理しています。ツールバーのテーマアイコンから切り替えられ、選択は保存されます。

```
    ├── FormView.kt      # スキーマ駆動フォーム＋汎用エディタ（中核）
    ├── SourcePane.kt    # テキスト編集
    ├── DiffPane.kt      # 保存済み内容と編集中内容の差分
    ├── AiGenerationDialog.kt # AI生成ダイアログ（指示入力→生成→プレビュー→適用）
    ├── WorkspaceViews.kt# 一覧・一括編集・参照グラフ
    ├── SchemaEditor.kt  # スキーマ設計・プレビュー・適用対象
    └── SidePanel.kt     # 検証・参照・被参照
```

設計上のポイント:

- **ツリーが単一の正**: `OpenDocument.root: YNode` が source of truth。フォームはツリーを直接書き換え、`version` カウンタのインクリメントで再コンポーズを駆動する。ソース編集は「反映」時にパースしてツリーへ取り込む。
- **Slot 抽象**: マップのキー／配列の要素／ドキュメントルートを同一インターフェースで編集できるようにし、スキーマフォームと汎用エディタでエディタ部品を共有。
- **パス（YPath）ベースのナビゲーション**: `List<Any>`（String = キー、Int = インデックス）で要素位置を表現し、ハイライト・ジャンプ・検証結果の紐付けに共通利用。

## 11. AIによる作成支援

スキーマが適用された文書では、OpenAI API を使って内容のたたき台を生成できます。入口は3か所です。

- **フィールド単位**: フォームの各フィールドラベル横の ✨ アイコン
- **配列への候補追加**: 配列エディタの「AIで候補追加」（既存項目を残して追加／配列全体を置き換えを選択可能）
- **文書全体**: 文書ヘッダーの「AIで作成」ボタン（`_document` メタデータは保持されます）

流れは「指示を入力 → 生成 → プレビューで現在値と比較 → 適用」です。

- 生成結果は、対象フィールドのスキーマから変換した JSON Schema による構造化出力（Structured Outputs）で受け取るため、型・enum・必須キーがスキーマに準拠します（`map` 型を含む場合のみ strict モードを無効化）。
- プレビューには、提案を適用した場合のスキーマ検証結果（エラー・警告数）を表示します。適用は Undo 可能で、自動保存はされません。
- 生成中は「生成を中止」でキャンセルできます。
- モデルに送信されるのは、指示、現在の文書、対象フィールドのスキーマ、ワークスペース内の既存ID（最大500件）です。

接続設定:

- **APIキー**: ダイアログで入力するか、環境変数 `OPENAI_API_KEY` を設定します。キーはメモリ上にのみ保持され、ディスクには保存されません。
- **モデル**: 既定は `gpt-5.1`。変更すると端末の設定（Preferences）に保存されます。Structured Outputs 対応モデルが必要です。

## 12. 既知の制約

- **コメント・アンカー・スタイルは保持されません。** 保存時に SnakeYAML でブロックスタイル・インデント 2 に正規化されます。Git 管理下ではエディタ導入直後に一度全ファイルを保存して正規化コミットを作ると差分が安定します。
- 外部変更は約1秒間隔で検出します。未編集ファイルは自動反映され、未保存の編集がある場合は競合バナーからディスク版または編集中の内容を選択できます。
- 汎用ビューでのキー名変更は「削除 → 追加」で行います。
- 複数ドキュメント（`---` 区切り）の YAML は先頭ドキュメントのみ対象です。
- ソース編集は簡易エディタです。行番号、文書内検索、パースエラーの行・列表示に対応していますが、構文ハイライトや置換には対応していません。
- 差分ビューは行単位の比較です。挿入・削除を検出して左右を整列し、空行だけの差は控えめな背景と「· 空行」で表示しますが、Gitの履歴や文字単位差分ではありません。
- 参照グラフは表示量を抑えるため、描画対象ノードを先頭40件、一覧を先頭500参照に制限します。
- 一覧ビューの一括編集対象はルートの `status` と `owner` です。

## 13. 拡張のヒント

- 型の追加: `FieldType` に enum を足し、`Validator.checkField` と `FormView.ValueEditor` に分岐を追加するだけで完結します。
- コメント保持が必要な場合は、`YamlIO` を SnakeYAML の Node API（`LoaderOptions.setProcessComments(true)`）ベースに差し替えるのが正攻法です（ツリー変換層が `YamlIO` に隔離されているため影響範囲は限定的です）。
- 横断ビューを追加する場合は、`AppState.workspaceRecords()` と `IdIndex` をデータソースとして利用できます。
