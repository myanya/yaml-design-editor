# テンプレート

新しいワークスペースの出発点です。アプリの「新しいワークスペースを作る…」と CLI の `init` が、ここにある 1 フォルダを 1 つのテンプレートとして展開します。
ビルド時に資源へ写すので、配布版でも同じものが使えます。

| 場所 | 役割 |
|---|---|
| `templates/` | 業務を限定しない出発点です。少数に保ちます |
| `samples/` | 特色の紹介です。増えてかまいません |
| `labs/` | 試作の実験場です |

## テンプレートの書き方

- フォルダ名がテンプレートの ID です。`template.yaml` に `name`（表示名）と `description`（説明）を書きます。
- それ以外のファイルは、ワークスペースへそのまま写します。`.yde/` 構成で書き、台帳のフォルダは `.yde/workspace.yaml` の `ledger:` で宣言します。
- 台帳の中のファイルはサンプルデータです。利用者が「サンプルデータを含めない」を選ぶと写さず、`match` が 1 つのファイルを指すスキーマのぶんだけ、スキーマの初期値で空の文書を作ります。
- `template.yaml` に `params:`（操作の `params` と同じ、項目の定義の配列）を書くと、問いを持つテンプレートになります。
  - 答えを「いまの場所」として、YAML ファイルを変換定義のひな型（`$copy`・`$format`・`$each`・`$when` など）で組み立てます。`$名前` は答えそのものです。
  - ファイル名と Markdown の中の `{名前}` は、答えの文字で埋めます。
  - 組み立てた結果が空のファイルは作りません。
- 問いを持たないテンプレートは「テンプレートから」に並び、問いを持つ `basic-list` は「自分の項目で」の実体です。問いを持つテンプレートはサンプルデータを持たず、データのファイルは空の一覧として書きます。
- 問いの名前に `key` と `index` は使えません（繰り返しの中で `$key` / `$index` が予約されています）。
- 繰り返し（`$each`）の中で答えを文字のひな型に差し込むときは、`$with` で渡します（例 `{ $format: "{code}-grid", $with: { code: $code } }`）。繰り返しの中の「いまの場所」は要素だからです。
- 追加したテンプレートは `WorkspaceTemplatesTest` が自動で拾い、サンプルデータの有無の両方で検証エラー 0 とダッシュボードの解決を確かめます。
