# ユーザ管理システム

ユーザ管理システムを題材に、少人数での実践投入に向けて設計書とテストケースのひな形を育てるYDEワークスペースです。
利用者が以前開発したシステムの記憶と、会社で作ったAIネイティブ向けのシンプルな設計体系をもとに整備します。

## 設計体系

| 工程 | 配置・状態 |
|---|---|
| 仕様書 | `10_specs/` から着手 |
| 設計書 | 未着手 |
| コンポーネント設計 | 未着手 |
| 単体テスト | 未着手 |
| 結合試験 | 未着手 |
| 総合試験 | 未着手 |

仕様書の体系は [仕様書の入口](10_specs/README.md)、工程の管理単位と参照方針は [共通記述規約](10_specs/WRITING.md) に従います。
後続工程の未決事項は [TODO](TODO.md) で管理します。

## 構成

```text
user-man/
├── .yde/
│   ├── workspace.yaml   # 台帳の対象は 10_specs
│   ├── schemas/         # 文書のスキーマ
│   └── views/           # 一覧・フロー図・文書表示の定義
├── 10_specs/
│   ├── README.md        # 文書体系と参照先の入口
│   └── WRITING.md       # 共通の記述規約
├── OPERATIONS.md        # YDEの操作・ビュー・検証手順
├── AGENTS.md            # 外部コーディングエージェント向けの指示
├── TODO.md              # 追加検討事項・進捗・セッションの再開位置
└── README.md
```

種類ごとの作成ガイドは [仕様書のREADME](10_specs/README.md) から参照できます。
命名・ID・参照の共通規則は [共通記述規約](10_specs/WRITING.md)、操作・検証は [操作・検証ガイド](OPERATIONS.md) に記載します。
業務・システム仕様の追加検討事項と進捗は [TODO.md](TODO.md) で管理し、セッション開始時は「再開位置」を確認します。

## 作業の進め方

1. [共通記述規約](10_specs/WRITING.md)と種類ごとの作成ガイドに沿って、利用者の説明から文書の形と内容を決めます。
2. 外部のコーディングエージェントでYAMLとスキーマを作成・更新します。
3. YDEで閲覧・編集・検証し、人間が内容と差分を確認します。

YDE内蔵のエージェント機能は当面使用しません。

## 開き方と検証

起動・編集・CLI検証と、各文書・ビューの確認手順は [操作・検証ガイド](OPERATIONS.md) を参照してください。
