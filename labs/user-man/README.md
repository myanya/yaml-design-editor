# ユーザ管理システム

ユーザ管理システムを題材に、少人数での実践投入に向けて設計書とテストケースのひな形を育てるYDEワークスペースです。
利用者が以前開発したシステムの記憶と、会社で作ったAIネイティブ向けのシンプルな設計体系をもとに整備します。

## 設計体系

| 工程 | 配置・状態 |
|---|---|
| 仕様書 | `10_specs/` から着手 |
| 設計書 | 未着手 |
| コンポーネント設計 | 未着手 |
| 単体テスト | 未着手 |
| 結合試験 | 未着手 |
| 総合試験 | 未着手 |

設計以下の工程は、サブドメイン単位で管理します。
後続工程のディレクトリ名、文書の詳細な項目、工程間の参照関係は未決定です。

## 構成

```text
user-man/
├── .yde/
│   ├── workspace.yaml   # 台帳の対象は 10_specs
│   └── schemas/         # 文書のスキーマ
├── 10_specs/
│   └── README.md        # 仕様書の作成方針
├── AGENTS.md            # 外部コーディングエージェント向けの指示
└── README.md
```

仕様書の構成・命名・ID体系・未決事項は、[仕様書のREADME](10_specs/README.md) にまとめています。

## 作業の進め方

1. [仕様書の作成方針](10_specs/README.md)に沿って、利用者の説明から文書の形と内容を決めます。
2. 外部のコーディングエージェントでYAMLとスキーマを作成・更新します。
3. YDEで閲覧・編集・検証し、人間が内容と差分を確認します。

YDE内蔵のエージェント機能は当面使用しません。
外部エージェントの直接編集はYDEの承認経路を通らないため、Git差分と検証結果を確認します。
同じ文書をGUIと外部エージェントで同時に編集せず、作業を引き渡す前に保存します。

## 開き方と検証

YDEのスタート画面で、この `labs/user-man` ディレクトリをワークスペースとして選択します。
本リポジトリのルートからは、次のコマンドも使えます。

```powershell
.\gradlew.bat run --args="labs/user-man"
.\gradlew.bat runCli -q --args="catalog labs/user-man"
.\gradlew.bat runCli -q --args="validate labs/user-man --sources"
```

文書を作成・更新したら、カタログでスキーマの適用を確認し、検証結果を確認します。
検証では終了コードだけでなく、`schemaErrors`・`errors`・`warnings`・`withheld` を確認します。
文書や検査がない状態で指摘が出ないことは、仕様の完成を意味しません。
