# 業務フロー

ユースケースには、次の2つの粒度があります。

| 種類 | 役割 | サブドメインとの関係 |
|---|---|---|
| 概要ユースケース（業務フロー） | `40_business_flows/` で業務全体の流れを記述 | 複数のサブドメインをまたぐ |
| 詳細ユースケース | `50_usecases/` でユーザとシステムとのインタラクションを具体化 | 1つのコンテキストに所属し、サブドメインとは業務上の対応を持つ |

一般的なユースケース定義書の内容を記述し、粒度に応じてインタラクションを具体化します。
画面・API・エンティティの仕様を詳細化するための基礎とします。
業務フローは以下の草案形式で具体化します。詳細ユースケースの項目と、概要から詳細への対応方法は今後定めます。

業務全体の流れとコンテキスト内の振る舞いを分けると、それぞれの記載粒度と管理範囲を明確にできます。

## 業務フローの草案形式

[業務フロー一覧](0000-business-flow-lists.yaml)にID・タイトル・概要を置き、同じIDの個別文書に内容を記述します。
最初の具体例は、[ユーザ登録から利用開始](BZFL-0001-ユーザ登録から利用開始.yaml)です。
形式と内容は草案として確認し、未解決の業務仕様は [TODO](../../TODO.md) で管理します。

| 個別文書の項目 | 内容 |
|---|---|
| `id`・`status` | 業務フローIDと草案／確定の区別 |
| `purpose` | 対象とする業務と範囲 |
| `actors` | 関与する主体と役割 |
| `preconditions` | 開始に必要な条件 |
| `basic_flow` | 手順ごとの見出し・実行主体・内容・状態変化・関与する領域と境界・根拠のルール |
| `variations` | 条件による分岐・例外と根拠の個別ルール |
| `outcome` | 業務の到達点 |
| `rule_refs` | 業務フロー全体の根拠となる個別ルールへの参照 |

手順内の `subdomains` は関与するサブドメインを、`rule_refs` は根拠を表し、業務フロー自体の所属は指定しません。
手順内の `contexts` は関与するコンテキストを表します。担当領域全体の対応から自動推測せず、その手順で関与する境界を指定します。
手順の配列順は業務の流れを表します。全手順を同期処理や単一トランザクションで実行する指定ではありません。
スキーマは [business-flow-list.yaml](../../.yde/schemas/business-flow-list.yaml) と [business-flow-detail.yaml](../../.yde/schemas/business-flow-detail.yaml) です。

共通の命名・ID・参照方針は [共通記述規約](../WRITING.md)、操作と確認は [操作・検証ガイド](../../OPERATIONS.md) を参照してください。
