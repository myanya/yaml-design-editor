# 仕様書の共通記述規約

仕様書を作成・更新するときに共通して守る、配置・命名・ID・参照・状態の規約です。
文書体系と種類ごとの作成ガイドは [仕様書の入口](README.md)、未決事項と進捗は [TODO](../TODO.md) を参照してください。

## 原本と更新先

業務仕様と設計内容の原本は `10_specs/` のYAML文書です。Markdownの案内へ同じ内容を重複して管理しません。
スキーマは `.yde/schemas/`、ビュー定義は `.yde/views/` に置きます。ビューは原本の参照・属性から表示を導出し、データを二重入力しません。
共通規約は本書、種類ごとの項目・例は各ディレクトリのREADME、操作・確認は [操作・検証ガイド](../OPERATIONS.md) に記述します。
文書形式は利用者との検討で具体化し、未決定の業務仕様を確定した内容として補完しません。

## 配置と命名

概要を除く各定義は、一覧と個別ドキュメントの構成を基本とします。

| 種類 | ファイル名 | 配置 |
|---|---|---|
| 一覧 | `0000-xxx-lists.yaml` | 定義の種類ごとのディレクトリ内 |
| 個別ドキュメント | `<ID>-<名称>.yaml` | 一覧と同じディレクトリ内 |

`xxx` は定義の種類を表します。採用済みの綴りは、各作成ガイドから参照する一覧ファイルに従います。
例えばルールの個別ドキュメントは `20_rules/RULE-0001-<名称>.yaml` の形です（名称はプレースホルダー）。
個別ドキュメント用の別ディレクトリは設けません。
概要は例外として `10_overview/` 内に種類ごとのファイルを置きます（現在は `overview.yaml`）。

## 一覧と詳細

一覧はID・タイトル・概要を持ち、詳細文書は同じIDと本文を持ちます。タイトル・文書全体の概要を二重に入力しません。
本文の部分ごとの見出しや概要は、その部分を説明するために記載できます。
一覧を定義出現、個別文書を同じ論理IDの詳細化出現として扱い、スキーマ・索引・ビューで対応付けます。

## ID体系

| 定義の種類 | ID形式 |
|---|---|
| ルール | `RULE-nnnn` |
| 個別ルール（本文項目） | `RITM-nnnn` |
| サブドメイン | `SDOM-nnnn` |
| 境界づけられたコンテキスト | `BCTX-nnnn` |
| コンテキスト間の連携 | `CMAP-nnnn` |
| 概要ユースケース（業務フロー） | `BZFL-nnnn` |
| 詳細ユースケース | `USCS-nnnn` |
| 画面定義 | `SCRN-nnnn` |
| API定義 | `APID-nnnn` |
| エンティティ定義 | `ENTY-nnnn` |

`nnnn` は4桁の数字です。概要を含め、上表にない定義のID体系は未決定です。
ルールは `RULE-0001` から作成順に採番し、内容の順序と番号をそろえるために採番を止めません。
番号順の整備は、後でツールのリファクタリング機能を用いて行います。
個別ルールは文書をまたいで一意に採番し、文書IDや親子関係を番号に含めません。
初回は文書ID順・本文の記載順で `RITM-0001` から採番します。通常の並べ替えや文書間の移動ではIDを維持します。
サブドメインの草案は `SDOM-0001` から採番します。
業務フローの草案は `BZFL-0001` から採番します。
コンテキストと連携は、それぞれ `BCTX-0001`・`CMAP-0001` から採番します。
その他の定義の採番開始値、欠番・廃止した番号の扱い、名称変更時のファイル名の扱いは今後定めます。

## 参照と所属

文書間の関係は対応するIDへの参照で表し、逆方向は逆参照で表示します。両側に同じ関係を手入力しません。
ルール文書と個別ルールを区別し、具体的な判断の根拠は個別ルールへの参照で記録します。
関係ごとの意味と参照の記録先は、各種類の作成ガイドと関係レジストリに従います。

詳細ユースケース・モデルの主な所属先は一つのコンテキストとし、サブドメインとは業務上の対応を持たせます。
共通ルールは所属の対象外です。業務フローは複数の境界を横断できます。
設計以下の工程もコンテキストを主な管理単位とします。物理的な配置・デプロイ単位は後続設計で定めます。

## 状態と変更

「草案」は具体化・確認中、「確定」は本文の方針への合意を表します。仕様の確定は詳細設計・実装・試験の完了を意味しません。
サブドメインの戦略的な分類と、文書の確定状態は別に管理します。
ルール本文の作成日・更新日・版の記録は [ルールの作成ガイド](20_rules/README.md) に従います。
スキーマや文書形式を変える場合は、参照するビューも確認し、[検証手順](../OPERATIONS.md#cliによる検証)に従って確かめます。
