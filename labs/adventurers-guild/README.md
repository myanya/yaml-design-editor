# 冒険者ギルドの運営（試作）

架空の冒険者ギルドの運営を題材に、業務のオントロジー（何があり、どうつながり、どんな状態が正しいか）を YDE のワークスペースで定義する試作です。
冒険者・依頼・パーティのような概念を型に、つながりを関係レジストリに、運営の決まりを検査に、状態の変え方を操作に書き、架空の運営データで確かめます。

いまは核の概念と関係、運営の決まりの検査、一覧と集計のビュー、依頼を受付から精算まで進める操作、受付のダッシュボードを定義し、架空の運営データを置いたところです（依頼の受付から精算までが一周しました）。進め方・決まったこと・オーナーが決めることは [計画](PLAN.md) にあります。

## オントロジーを書く場所

オントロジーの要素を、YDE の定義のどこに書くかの対応です。別の形式（OWL など）や概念辞書を持たず、YDE の定義そのものをオントロジーとして育てます（オーナーの決定）。

| オントロジーの要素 | YDE で書く場所 |
|---|---|
| 概念（クラス） | オブジェクト型の `entity`（`.yde/schemas/` の型と文書スキーマ） |
| 属性 | 項目の定義（型・選択肢・範囲・必須） |
| 関係 | 参照（`type: ref` の `relation`）と、関係レジストリ `.yde/schemas/relations.yaml`（表示名・両端の型・多重度・非循環） |
| 全体と部分 | 保有（入れ子で書き、関係レジストリに名前を宣言する） |
| 公理・運営の決まり | 検査（多重度・パターン制約 `constraints`・型の検査・遷移検証 `flow`） |
| 個体 | 台帳 `guild/` の YAML 文書（架空の運営データ） |
| 状態の変化 | 操作（`actions`）と依頼の履歴、ダッシュボードの業務の流れ |

書き方の詳細はリポジトリの [利用者マニュアル](../../docs/manual/README.md)（[スキーマ](../../docs/manual/schema.md)・[検証](../../docs/manual/checks.md)・[ID とリンク](../../docs/manual/ids.md)・[操作](../../docs/manual/actions.md)）にあります。

## 配置

| 場所 | 内容 |
|---|---|
| `.yde/workspace.yaml` | 構成です。台帳は `guild/` の中だけです |
| `.yde/schemas/common.yaml` | 共通の型です。番号・参照・金額・日付・状態・操作の名前の型と、概念のオブジェクト型（`entity`）を持ちます |
| `.yde/schemas/relations.yaml` | 関係レジストリです。概念の表示名と、関係の向き・表示名・多重度を持ちます |
| `.yde/schemas/` のほか | 文書スキーマです（支部・ランク一覧・冒険者・パーティ・依頼者・依頼・精算・精算の月）。線を辿る検査（パターン制約）と操作（`actions`）も持ちます |
| `.yde/views/` | ダッシュボード（[ダッシュボード](#ダッシュボード)）と、一覧・クロス集計・チャートです（[ビュー](#ビュー)） |
| `guild/branch.yaml` | ギルド支部です。町の名前・通貨の単位・手数料率を持ちます |
| `guild/ranks.yaml` | ランク一覧です（SS・S・A・B・C・D・E・F）。上下は順位の数 `order` で比べ、同時に受けられる依頼の数 `maxConcurrent` を持ちます（A 以上は書かない＝制限なし） |
| `guild/adventurers/ADV-<番号>.yaml` | 冒険者です。1 人 1 ファイルです |
| `guild/parties/PTY-<番号>.yaml` | パーティです。パーティのランク・リーダー・構成員（役割つき）を持ちます |
| `guild/clients/CLT-<番号>.yaml` | 依頼者です |
| `guild/quests/QST-<番号>.yaml` | 依頼です。受付支部を参照し、受注の記録（受け手・受注日・完了報告）と履歴（日付・操作・前後の状態・理由）を中に持ちます |
| `guild/payments/PAY-<番号>.yaml` | 精算です。受注・計上月を参照し、報酬・手数料率・手数料・支払額を持ちます |
| `guild/payment-months.yaml` | 精算の月（`PAYM-年-月`）の一覧です。月ごとの合計はここから集めます |
| `PLAN.md` | 決まったこと・オントロジーの表・段階・オーナーが決めること・再開位置です |
| `AGENTS.md` | エージェント向けの決まりです |

## 検査

運営の決まりは、指摘を誤りにしています（「期限を過ぎてからの報告」と「履歴の無い依頼」だけ警告）。どの決まりをどの書き方で書いたかは [計画](PLAN.md)「運営の決まり（検査）」にあります。

- 参照の切れと、参照する種類の誤り（受注の受け手は冒険者かパーティ）
- 関係の数: 冒険者とパーティのランクは 1 つ・構成員は 1〜6 人・リーダーと依頼者と受付支部と計上月は 1 つ・精算は受注 1 件につき 1 回まで
- パーティのリーダーは構成員の 1 人で、構成員はほかのパーティに入っていないこと
- 受け手のランクが、依頼の受注できるランクの下限以上であること（個人は個人の、パーティはパーティのランク）
- 休業・引退・除名・消息不明の冒険者が、遂行中の依頼を受けていないこと
- 遂行中の依頼の数が、受け手のランクの上限（F 1・E 2・D 3・C 4・B 5、A 以上は制限なし）までであること。個人とパーティで別に数えます
- 依頼の状態と、受注・完了報告・精算の有無が合っていること（掲示し直した依頼は、前の未達の受注を持てます）
- 日付の前後（期限・受注日は受付日以降、報告日は受注日以降、支払日は報告日以降）と、期限を過ぎてからの報告（警告）
- 精算の金額（報酬は依頼と同じ、手数料＝報酬 × 手数料率 ÷ 100、支払額＝報酬 − 手数料）と、報酬は 10 の倍数であること（手数料に端数が出ないように）
- 計上月は支払日の年月で、精算の月の番号は「PAYM-」と年月であること

## 操作

依頼の状態は操作で進めます。どの操作も履歴に 1 行（日付・操作・前後の状態・理由）を残します。

| 操作 | 状態の移り方 | 止まるとき |
|---|---|---|
| 依頼を受け付ける | （作る）→ 受付 | — |
| 依頼を掲示する | 受付・失敗 → 掲示中 | 期限を過ぎている |
| 依頼を受注する | 掲示中 → 受注済み（受注 A1、A2 … を足す） | 期限を過ぎている・受け手のランクが下限に届かない・同時に受けられる数を超える・受け手が休業などで受注できない |
| 完了を報告する | 受注済み → 報告済み（達成）・失敗（未達） | — |
| 報酬を精算する | 報告済み → 精算済み（精算 PAY- を作る） | 支払日の年月の精算の月が無い |
| 依頼を却下する | 受付 → 却下 | — |
| 依頼を取り消す | 受付・掲示中・受注済み → 取消 | — |
| 依頼を期限切れにする | 掲示中・受注済み → 期限切れ | 期限がまだ過ぎていない・期限が無い |

ほかに「精算の月を足す」「冒険者を登録する」「パーティを組む」があります。

- 依頼の操作は、ダッシュボードの業務の流れの工程・業務詳細・依頼のエンティティページの ⋮・一覧の行の ⋯ から、ワークスペースの操作（受け付ける・登録する・組む・月を足す）はダッシュボードの「操作」とコマンドパレット（Ctrl+K）から呼びます。
- 状態が合わないときと期限の条件は、操作の前提が理由を出して止めます。
- ランク・同時に受けられる数・受注できない状態・構成員の重なり・精算の月の無いことは、「確認」で出る適用後の検証の誤りが止めます（適用ボタンが押せません）。
- 精算の手数料率は依頼の受付支部の率を写し、手数料と支払額を計算します。精算の月は先に「精算の月を足す」で足しておきます。

## ダッシュボード

ワークスペースを開くと、ダッシュボード「ギルドの受付」（`guild-dashboard`）が出ます。

- **業務の流れ**: 掲示待ち（受付）→ 掲示中 → 遂行中 → 精算待ち → 精算済み の段と、工程（掲示する・受注する・報告する・精算する）の流れ図です。段を押すとその段の依頼の一覧、工程を押すとその段の依頼が「いま操作できる／できない（理由）」に分かれて並び、行から操作できます。入口の線は「依頼を受け付ける」です。
- **状況**: 流れの段の区画と、「期限を過ぎた掲示中・遂行中」（基準日で判定。期限切れにする候補）です。
- **流れの外**: 失敗（掲示し直せる）・期限切れ・却下・取消の区画です。流れ図には置きません。
- **精算**: 今月の精算（支払日の年月が基準日の年月）と、月ごとの精算の図です。
- **名簿**: 冒険者の名簿とパーティの編成です。
- **操作**: 依頼を受け付ける・冒険者を登録する・パーティを組む・精算の月を足す。
- 依頼の番号を押すと業務詳細が開き、上部の「流れの中の位置」に、いる段・次にできること・履歴が出ます。

## ビュー

台帳スペースの「ビュー」タブから開きます。

| ビュー | 内容 |
|---|---|
| 依頼の掲示板（`quest-board`） | 依頼を新しい順に、種別・状態・依頼者・下限ランク・報酬・期限・受け手と並べます。「新規行」で依頼を作れます |
| 冒険者の名簿（`adventurer-roster`） | ランク・状態・所属するパーティと、個人で遂行中の数・同時に受けられる数・個人で達成した数です |
| パーティの編成（`party-roster`） | ランク・リーダー・構成員・人数と、パーティで遂行中の数・同時に受けられる数です |
| 精算の記録（`payment-ledger`） | 精算ごとに、支払日・依頼・受け手・報酬・手数料率・手数料・支払額を支払日の順に並べます |
| 月ごとの精算（`monthly-payments`） | 精算の月ごとの、精算の件数と報酬・手数料・支払額の合計です |
| 月ごとの精算（手数料と支払額）（`monthly-payments-chart`） | 上の表の積み上げ棒です。棒の高さが報酬の合計です |
| ランク × 種別（`rank-by-kind`） | 受注できるランクの下限ごとの、種別の依頼の件数です。下限の無い依頼は数えません |
| 受付月 × 状態の報酬（`monthly-quests`） | 受け付けた年月ごとの、いまの状態ごとの報酬の合計です |
| 受付月ごとの報酬（状態別）（`monthly-quests-chart`） | 上の表の積み上げ棒です。棒を押すと、数えた依頼が下に並びます |

## 開き方と検証

リポジトリのルートで実行します。

```bash
./gradlew run --args="labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="validate labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="schema-graph labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="action labs/adventurers-guild"
```

- `validate` は全文書の検証です。指摘の件数を [計画](PLAN.md)「いまの姿」に記録します。
- `schema-graph` は型と関係の図の材料（レンズの「型」の段と同じもの）で、オントロジーの全体を文字で確かめられます。画面では、台帳スペースの「レンズ」で型の段に切り替えると図で見られます。
- `action` は操作の一覧です。`action labs/adventurers-guild accept-quest --on QST-0006 --param taker=PTY-001 --param date=2026-11-08` のように名前と値を渡すと、計画と適用後の検証を出します（`--apply` で書きます）。原本を変えずに試すなら、このフォルダを写してから使います。

## 試し方

ワークスペースを写してから開くと、原本を変えずに試せます。どの手順も `Ctrl+Z` 1 回で戻せます。

1. 写したフォルダを YDE で開くと、ダッシュボード「ギルドの受付」が出ます。業務の流れは 掲示待ち 1・掲示中 2・遂行中 2・精算待ち 1・精算済み 2 です。
2. 基準日を 2026-11-16 にすると「期限を過ぎた掲示中・遂行中」に `QST-0005`（期限 2026-11-15）が入ります。2026-11-24 なら 3 件です。基準日を今日に戻します。
3. 流れ図の「完了を報告する」の線を押すと、遂行中の 2 件が並びます。`QST-0004` の行から操作を開き、結果「達成」で適用すると、精算待ちが 2 件になります。続けて「報酬を精算する」の線から `QST-0004` を支払日 `2026-11-10` で精算すると、`guild/payments/PAY-0003.yaml`（報酬 150・手数料 15・支払額 135）ができ、精算済みが 3 件になります。
4. 依頼の番号を押して業務詳細を開き、「流れの中の位置」の履歴に、受け付けから精算までの行が並ぶのを見ます。
5. 台帳スペースの「レンズ」を型の段にします。依頼が依頼者・ランク・受付支部・受注を指し、受注が冒険者かパーティを、精算が受注と精算の月を指す形が見えます。依頼から受注へは保有の線（ひし形）です。
6. 流れ図の「依頼を受注する」の線から `QST-0006`（掲示中・下限 A）の操作を開き、受け手に `PTY-003`（朝露の旗・ランク F）を入れて「確認」を押します。「依頼の下限 A に届きません」の誤りが出て、適用ボタンが押せません（手順 3 の前に試すと、「遂行中の依頼は 2 件で、ランク F の上限 1 件を超えています」も出ます）。受け手を `PTY-001`（銀の轍・ランク B）に変えても届かないので、`ADV-0001`（オルド・ヴァレン・ランク A）にすると適用できます。
7. 「流れの外」の「失敗」から `QST-0009`（期限 2026-10-25）を開き、「依頼を掲示する」を選ぶと、「期限を過ぎているため掲示できません」と理由が出ます。
8. 「精算」の「月ごとの精算」で、2026-11 の棒に精算した分が足されていることを見ます。

## データについて

- 登場する人物・団体・地名・魔物・品物は、すべて架空のオリジナルです。名前は実在のものや既存の作品と重ならない造語にします。
- 既存の作品の設定（固有の用語・ランクの呼び名の体系・登場人物）を写しません。
