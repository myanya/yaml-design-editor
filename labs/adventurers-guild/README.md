# 冒険者ギルドの運営（試作）

架空の冒険者ギルドの運営を題材に、業務のオントロジー（何があり、どうつながり、どんな状態が正しいか）を YDE のワークスペースで定義する試作です。
冒険者・依頼・パーティのような概念を型に、つながりを関係レジストリに、運営の決まりを検査に、状態の変え方を操作に書き、架空の運営データで確かめます。

いまは核の概念と関係、運営の決まりの検査、一覧と集計のビュー、依頼を受付から精算まで進める操作、受付のダッシュボードを定義し（依頼の受付から精算までが一周しました）、世界（場所・魔物・素材・職能）と、運営（職員・規約・処分・昇格審査・素材の買取）と育成（職業訓練と資格）を足し、冒険者の管理と昇格審査にも業務の流れを作り、会計を閉じたところです（お金と物の動きから在庫と現金を導き、月末に棚卸と締めで確かめます。1 年の収支は [計画](PLAN.md)「会計の作りと 1 年の収支」）。進め方・決まったこと・オーナーが決めることは [計画](PLAN.md) にあります。

## オントロジーを書く場所

オントロジーの要素を、YDE の定義のどこに書くかの対応です。別の形式（OWL など）や概念辞書を持たず、YDE の定義そのものをオントロジーとして育てます（オーナーの決定）。

| オントロジーの要素 | YDE で書く場所 |
|---|---|
| 概念（クラス） | オブジェクト型の `entity`（`.yde/schemas/` の型と文書スキーマ） |
| 属性 | 項目の定義（型・選択肢・範囲・必須） |
| 関係 | 参照（`type: ref` の `relation`）と、関係レジストリ `.yde/schemas/relations.yaml`（表示名・両端の型・多重度・非循環） |
| 全体と部分 | 保有（入れ子で書き、関係レジストリに名前を宣言する） |
| 公理・運営の決まり | 検査（多重度・パターン制約 `constraints`・型の検査・遷移検証 `flow`） |
| 個体 | 台帳 `guild/` の YAML 文書（架空の運営データ） |
| 状態の変化 | 操作（`actions`）と、依頼・冒険者・昇格審査の履歴、ダッシュボードの業務の流れ |

書き方の詳細はリポジトリの [利用者マニュアル](../../docs/manual/README.md)（[スキーマ](../../docs/manual/schema.md)・[検証](../../docs/manual/checks.md)・[ID とリンク](../../docs/manual/ids.md)・[操作](../../docs/manual/actions.md)）にあります。

## 全体の概観

業務の領域ごとの概念と、主なつながりです。台帳スペースの「レンズ」を型の段にし、見え方「全体の概観」（`guild-overview`）の絞り込みで領域を 1 つ選ぶと、その領域の型だけを図で見られます。

| 領域 | 概念 | 主なつながり |
|---|---|---|
| 人と組織 | 本部・支部・職員・冒険者・パーティ・依頼者 | 支部は本部に属し、職員と依頼は支部に属し、パーティは冒険者を構成員に持ちます。冒険者とギルドの関係は 現役・休業・脱退（理由つき）・除名 で、死亡は脱退の理由です。パーティは 活動中・リーダー不在・解散 で、脱退・除名・登録の失効で構成員は抜け、だれもいなくなると解散します |
| 区分 | ランク・職能 | 冒険者とパーティはランクを、冒険者は職能を持ちます |
| 依頼の流れ | 依頼・受注・精算 | 受注は依頼と受け手（冒険者かパーティ）を結ぶ記録で、精算が受注の報酬を払います |
| 世界 | 場所・魔物・素材 | 依頼は場所で行って魔物か素材を対象にし、魔物は場所に棲んで素材を落とし、植物と鉱物は産地で採れます |
| 育成（職業訓練） | 訓練の課程・受講・資格 | 課程は職能を身に付けさせ、職員か冒険者が教え、冒険者が受講料を納めて受講し（受講中 → 修了・中止）、修了すると初級の資格を得ます。主な職能の課程を修了すると、見習いは初級になります。依頼は職能を求められ、職能か資格で満たします |
| 評価と規律 | 規約・昇格審査・職能の審査・処分 | 昇格審査は受注の実績を根拠にし、合格すると対象のランクが 1 段上がります。職能の審査（試験）に合格すると、主な職能の段階が上がります。処分は規約の違反に対して冒険者かパーティに下し、受注停止の間は受注できず（パーティと構成員の両方に及びます）、除名なら冒険者は除名になります |
| 会計と在庫 | 預かり・返金・精算・委託契約と委託料・給与の支払い・経費・本部からの補填・素材の買取・売却・廃棄・棚卸・現金の締め | 依頼は預かりと返金を、委託契約は委託料を、職員は給与を、支部は経費と本部からの補填を持ちます。買取・売却・廃棄・棚卸は素材を指します。帳簿は持たず、在庫と現金は動きから導きます |

## 検査

運営の決まりは、指摘を誤りにしています（期限を過ぎてからの報告・履歴の無い依頼・討伐と納品の下限の目安・種別と対象と場所の整合・求める職能と段階・除名の処分の無い除名・安値の売却・棚卸と締めの差は警告）。どの決まりをどの書き方で書いたかは [計画](PLAN.md)「運営の決まり（検査）」にあります。

- 参照の切れと、参照する種類の誤り（受注の受け手は冒険者かパーティ）
- 関係の数: 冒険者とパーティのランクは 1 つ・構成員は 6 人まで・リーダーは 1 人まで・依頼者と受付支部は 1 つ・精算は受注 1 件につき 1 回まで
- パーティのリーダーは構成員の 1 人で、活動中のパーティの構成員は、ほかの活動中のパーティに入っておらず、現役か休業であること。活動中のパーティには構成員が 1 人以上いること。リーダー不在にはいなくなった日、解散には解散した日と理由があること。解散したパーティは遂行中の依頼を受けていないこと
- 解散したパーティ・リーダー不在のパーティは、解散した日・リーダーがいなくなった日から後に受注していないこと
- 遂行中の受注の受け手のランクが、依頼の受注できるランクの下限以上であること（個人は個人の、パーティはパーティのランク）
- 脱退・除名の冒険者が、遂行中の依頼を受けていないこと。脱退の冒険者には脱退の理由（引退・死亡・本人の都合・登録の失効）があること。休業の冒険者が、休業した日から後に受注していないこと
- 登録の有効期限: 冒険者の受注日は登録の有効期限の内であること。現役・休業の冒険者の有効期限は、納めた年会費の延びた有効期限のいちばん後と同じであること。年会費の額は登録した支部の年会費と同じであること。登録の年会費をまだ受け取っていない冒険者（警告）
- 遂行中の依頼の数が、受け手のランクの上限（F 1・E 2・D 3・C 4・B 5、A 以上は制限なし）までであること。個人とパーティで別に数えます
- 依頼の状態と、受注・完了報告・精算の有無が合っていること（掲示し直した依頼には、前の未達の受注があってよい）
- 日付の前後（期限・受注日は受付日以降、報告日は受注日以降、支払日は報告日以降）と、期限を過ぎてからの報告（警告）
- 精算の金額（報酬は依頼と同じ、手数料＝報酬 × 手数料率 ÷ 100、支払額＝報酬 − 手数料）と、報酬は 10 の倍数であること（手数料に端数が出ないように）
- 討伐依頼の受注できるランクの下限が、対象の魔物の討伐の目安のランクを下回らないこと（警告）。下限の無い討伐依頼は F とみなし、目安が F より上の魔物なら警告します。魔物の部位を納める納品依頼も、落とす魔物の目安で同じように確かめます
- 種別と対象の整合（警告）: 討伐には魔物があり、納品物はその魔物が落とす素材であること。採取の対象は魔物でも魔物の部位でもない素材、納品の対象は素材であること
- 討伐の場所が対象の魔物の生息地に、採取の場所が対象の素材の産地にあること（警告。場所のある依頼だけ）
- 求める職能のある依頼の受け手が、その職能かその職能の資格を持つこと（警告。パーティなら構成員の誰か）
- 昇格は 1 段ずつで、決まるまでの間は、審査のいまのランクが対象のいまのランクと同じであること。合格・不合格の審査には決めた日と決めた職員があること
- 受注停止の処分の間は受注していないこと（構成員の誰かが受注停止なら、そのパーティも。パーティが受注停止なら、その構成員も個人で）。除名の処分を受けた冒険者は除名の状態であること
- 職能の段階が初級なら、主な職能の訓練の課程を修了していること（見習いは段階を書かない）
- 職能の審査は対象の主な職能で、いまの段階は対象のいまの段階と同じ、目指す段階はそれより上の中級か上級であること。合格には、根拠の実績（対象かその属するパーティが達成した受注）と合格した実技試験の両方が要ること。実績は中級 10 件・上級 30 件が目安（警告）。審査官は、その職能の上級の職員か、引退した上級の冒険者であること
- 降格は 1 段で、降格の処分には前と後のランクがあること
- 求める段階（中級・上級）のある依頼の受け手が、その職能のその段階以上（主な職能の段階か資格の段階）であること（警告）
- 預かりと返金: 掲示から先の依頼には預かりがあり、預かった報酬は依頼の報酬と同じ・受付料は報酬の受付料率・受け取った額は報酬 ＋ 受付料。返金は却下・取消・期限切れの依頼だけで、預かりのあるそれらには必ずあり、返す額は預かった報酬（受付料は、受付のまま期限切れにしたときだけ返す）
- 在庫と現金: 在庫は素材ごとにまとめて数えます（依頼や買取の単位では分けません）。傷みやすい素材は月末の棚卸に残さないこと（警告）。売った・捨てた後の在庫が 0 より少なくならないこと。売る単価は基準の買取価格の 1.5 倍以上（警告）。棚卸と締めの数えた値が導いた値と同じ（警告）。受け取った委託料は月の委託料と同じ
- 受講: 休業の冒険者が休業した日から後に申し込んでいないこと・申し込んだ日は登録の有効期限の内・受講中の受講者は脱退か除名でない・納めた受講料は課程の受講料と同じ
- 受注停止の処分には終わる日があること。受講の結果と終えた日が合っていること。訓練の課程の修了で得る資格は初級であること。買取の代金は単価 × 数であること

## 操作

依頼の状態は操作で進めます。どの操作も履歴に 1 行（日付・操作・前後の状態・理由）を残します。

| 操作 | 状態の移り方 | 止まるとき |
|---|---|---|
| 依頼を受け付ける | （作る）→ 受付 | — |
| 依頼を掲示する | 受付・失敗 → 掲示中 | 期限を過ぎている |
| 依頼を受注する | 掲示中 → 受注済み（受注の記録 `QST-…-A1`、A2 … を作る） | 期限を過ぎている・受け手のランクが下限に届かない・同時に受けられる数を超える・受け手が休業などで受注できない |
| 完了を報告する | 受注済み → 報告済み（達成）・失敗（未達） | — |
| 報酬を精算する | 報告済み → 精算済み（精算 PAY- を作る） | — |
| 依頼を却下する | 受付 → 却下 | — |
| 依頼を取り消す | 受付・掲示中・受注済み → 取消 | — |
| 依頼を期限切れにする | 受付・掲示中・失敗 → 期限切れ（預かっていれば報酬を返す。受付のままなら受付料も返す） | 期限がまだ過ぎていない・期限が無い・遂行中（報告を待つか打ち切る） |
| 期限を延ばす | 変えない（受付・掲示中・受注済み・失敗。依頼者の同意を履歴に） | 新しい期限がいまの期限より前 |
| 遂行を打ち切る | 受注済み → 失敗（ギルドの打ち切りとして未達を書く） | 期限を過ぎて支部の打ち切りまでの日数（14）がたっていない（全滅の確認なら打ち切れる） |

冒険者と昇格審査の状態も操作で進め、それぞれの履歴に 1 行ずつ残します。

| 操作 | 状態の移り方 | 止まるとき |
|---|---|---|
| 冒険者を登録する | （作る）→ 現役（登録の有効期限は 1 年後。続けて「年会費を受け取る」） | — |
| 年会費を受け取る（登録・登録継続届） | 変えない（登録の年会費か、更新して有効期限を 1 年延ばす。額は登録した支部の年会費） | 現役でない・有効期限を過ぎている |
| 休業にする（休業届） | 現役 → 休業（遂行中の依頼があってもできる。休業の間は更新と年会費が免除され、受注できない） | 有効期限を過ぎている |
| 登録を失効させる | 現役 → 脱退（理由: 登録の失効） | 有効期限の内・個人で遂行中の依頼がある |
| 脱退にする | 現役・休業 → 脱退（理由: 引退・死亡・本人の都合） | 個人で遂行中の依頼がある（先に報告か打ち切り）・理由が登録の失効 |
| 現役に戻す（復帰届） | 休業 → 現役（年会費を受け取り、有効期限は戻った日から 1 年後） | 戻った日が休業した日より前 |
| 除名する | 現役・休業 → 除名（除名の処分 SNC- を作る） | 個人で遂行中の依頼がある |
| 処分を下す（注意・受注停止）（冒険者・パーティ） | 変えない（処分 SNC- を作る） | 受注停止に終わる日が無い |
| 全滅を記録する（パーティ） | 構成員をまとめて → 脱退（理由: 死亡）。パーティは → 解散（理由: 全滅） | パーティか構成員が遂行中の依頼を受けている |
| 降格する（冒険者・パーティ） | 変えない（降格の処分を作り、ランクを 1 段下げる） | いちばん下のランク・1 段でない |
| パーティを組む | （作る）→ 活動中 | 構成員がほかの活動中のパーティにいる・リーダーが構成員でない |
| 構成員を加える（パーティ） | 変えない | 活動中でない・ほかの活動中のパーティにいる・脱退か除名・7 人目 |
| 構成員が抜ける（パーティ） | 変えない（パーティで遂行中の依頼があっても抜けられる） | リーダー（先に替える）・最後の 1 人（解散する）・構成員でない |
| リーダーを決める（パーティ） | リーダー不在 → 活動中（替えるだけなら変えない） | 活動中でない・構成員でない |
| 解散する（パーティ） | 活動中・リーダー不在 → 解散（理由: 本人たちの都合） | パーティで遂行中の依頼がある |
| 脱退にする・除名する・登録を失効させる（冒険者） | 受講中の受講は中止になる。パーティからも外れる。リーダーならパーティは → リーダー不在、最後の 1 人なら → 解散（理由: 構成員がいなくなった） | 最後の 1 人が抜けて、遂行中の依頼のあるパーティが解散になる |
| 昇格審査の対象に決める | （作る）→ 審査の対象 | 1 段ずつでない・いまのランクが対象のランクと違う |
| 職能の審査の対象に決める → 試験を始める → 実技試験の結果を書く → 合格にする・不合格にする | 審査の対象 → 審査中 → 合格（主な職能の段階を上げる。何段でも）・不合格 | 職能が主な職能でない・いまの段階が違う・目指す段階が中級か上級でない・根拠の実績が対象のものでない・合格に実績か合格した実技試験が無い |
| 審査を始める | 審査の対象 → 審査中 | — |
| 合格にする | 審査中 → 合格（対象のランクを昇格先へ上げる） | 審査の間に対象のランクが変わった |
| 不合格にする | 審査中 → 不合格 | — |
| 受講を申し込む（訓練の課程） | （作る）→ 受講中（受講料を受け取る。番号は 課程の番号-E1、E2 …） | 休業の間・登録の有効期限を過ぎた・脱退か除名 |
| 修了にする（受講） | 受講中 → 修了（主な職能の課程なら、見習いを初級に） | 受講中でない・始めた日より前 |
| 中止にする（受講） | 受講中 → 中止（受講料は返さない） | 受講中でない・始めた日より前 |

お金と素材の操作は、状態の項目ではなく在庫と現金の数を動かします（素材の在庫の有る・無しは、動きから導いた在庫で決まる State で、素材の在庫の Lifecycle に書いています）。

| 操作 | 作るもの | 止まるとき |
|---|---|---|
| 報酬を預かる（依頼） | 依頼の中の預かり（報酬と受付料） | 受付の依頼でない・もう預かっている。掲示は預かってからです |
| 素材を一覧に足す（素材の一覧） | 素材 MAT-（在庫なしから始まる） | — |
| 素材を買い取る・売る・捨てる | 買取 BUY-・売却 SEL-・廃棄 DSP- | 売る・捨てる数が在庫より多い |
| 棚卸する | 棚卸 STK- | 導いた数が、いまの在庫と違う（在庫の一覧から写します） |
| 給与を払う・経費を払う・本部から補填を受ける・現金を締める（支部） | 職員ごとの給与 WAG-・経費 EXP-・補填 SUP-・締め CLS- | 締めの導いた現金が、いまの現金と違う（支部の現金から写します） |
| 委託料を受け取る（委託契約） | 委託料の受け取り RCP- | — |

却下・取消・期限切れの操作は、預かっていれば報酬を返します（受付料は返しません）。ほかに「パーティを組む」があります。

- 依頼・冒険者・昇格審査の操作は、ダッシュボードの業務の流れの工程・業務詳細・エンティティページの ⋮・一覧の行の ⋯ から、ワークスペースの操作（受け付ける・登録する・組む・対象に決める）はダッシュボードの「操作」とコマンドパレット（Ctrl+K）から呼びます。
- 状態が合わないときと期限の条件は、操作の前提が理由を出して止めます。
- ランク・同時に受けられる数・受注できない状態・構成員の重なりは、「確認」で出る適用後の検証の誤りが止めます（適用ボタンが押せません）。
- 精算の手数料率は依頼の受付支部の率を写し、手数料と支払額を計算します。

## ダッシュボード

ワークスペースを開くと、ダッシュボード「ギルドの受付」（`guild-dashboard`）が出ます。ほかに「冒険者の管理」「昇格審査」「職能の審査」「会計と在庫」があり、台帳スペースの「ビュー」タブから開きます。

- **業務の流れ**: 掲示待ち（受付）→ 掲示中 → 遂行中 → 精算待ち → 精算済み の段と、工程（報酬を預かる・期限を延ばす・掲示する・受注する・報告する・精算する）の流れ図です。打ち切り・期限切れは流れに置かず、依頼のページと区画の行から操作します。段を押すとその段の依頼の一覧、工程を押すとその段の依頼が「いま操作できる／できない（理由）」に分かれて並び、行から操作できます。入口の線は「依頼を受け付ける」です。
- **状況**: 流れの段の区画と、「期限を過ぎた依頼」（基準日で判定。受付・掲示中・失敗は期限切れにするか延ばす、遂行中は報告を待つか打ち切る）です。
- **流れの外**: 失敗（掲示し直せる）・期限切れ・却下・取消の区画です。流れ図には置きません。
- **会計**: 支部の現金・今月の精算（支払日の年月が基準日の年月）・月ごとの支払額の図・月ごとの手数料の表と、買取の記録・月ごとの買取額です。年・月は支払日・買い取った日から導きます。
- **名簿**: 冒険者の名簿とパーティの編成です。
- **世界**: 魔物・場所・素材の一覧です。
- **運営**: 職員・規約・処分の一覧、決まっていない昇格審査と昇格審査の一覧です。
- **育成**: 訓練の課程と資格の一覧です。
- **操作**: 依頼を受け付ける・冒険者を登録する・パーティを組む。
- 依頼の番号を押すと業務詳細が開き、上部の「流れの中の位置」に、いる段・次にできること・履歴が出ます。

「冒険者の管理」（`adventurer-desk`）は、登録 → 現役 ⇄ 休業 → 脱退（引退・死亡・本人の都合・登録の失効）・除名 の流れ図（年会費を受け取る・処分を下すは現役の段に留まる工程）と、登録（有効期限を過ぎた・30 日のうちに有効期限が来る・登録の年会費をまだ受け取っていない・年会費の一覧）・いま受注停止の処分・処分の一覧・資格と訓練の課程・受講（受講中・一覧）・パーティ（編成・リーダー不在・解散）の区画です。受講は課程の行から申し込み、受講の行から修了・中止にします。パーティの操作（構成員を加える・抜ける・リーダーを決める・解散する・全滅を記録する）は、パーティの行から選びます。
「会計と在庫」（`account-desk`）は、在庫なし ⇄ 在庫あり の流れ図（工程は 買い取る・売る・捨てる・棚卸する）と、現金（支部の現金・支部の収支・月ごとの入りと出・累計の図・種類別・手数料と受付料・締め）・委託と給与と経費・在庫の記録・冒険者の稼ぎの区画です。給与・経費・本部からの補填・締めは支部の行から、委託料は委託契約の行から操作します。
「職能の審査」（`job-exam-desk`）は、審査の対象 → 審査中 → 合格・不合格 の流れ図（入口は「職能の審査の対象に決める」）と、審査の材料（名簿・資格・訓練の課程）の区画です。
「昇格審査」（`promotion-desk`）は、審査の対象 → 審査中 → 合格・不合格 の流れ図（入口は「昇格審査の対象に決める」）と、審査の材料（名簿・編成・ランク × 種別）の区画です。

## 開き方と検証

```bash
./gradlew run --args="labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="validate labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="schema-graph labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="action labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="behavior-audit labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="behavior-scenarios labs/adventurers-guild labs/adventurers-guild/scenarios/lifecycles.yaml"
```

- `validate` は全文書の検証です。指摘の件数を [計画](PLAN.md)「いまの姿」に記録します。
- `schema-graph` は型と関係の図の材料（レンズの「型」の段と同じもの）で、オントロジーの全体を文字で確かめられます。画面では、台帳スペースの「レンズ」で型の段に切り替えると図で見られます。
- `behavior-audit` は振る舞いの宣言（State・Lifecycle）のつながりの点検です。いまは、行き先が 2 つある意図した分岐が、確かめてほしい点（`needs-review`）として 5 つ出ます。依頼の「報告する」（達成と未達）と、パーティの「脱退にする」「除名する」「登録を失効させる」「死亡が確かめられた」（外れたのがリーダーならリーダー不在、最後の 1 人なら解散）です。ほかに、記録専用の Event「依頼者が期限の延長に同意した」が Lifecycle に使われていないという知らせ（info）が出ます。`behavior-scenarios` は業務シナリオで遷移を確かめます（原本は変えません。書き方はリポジトリの [スキーマのマニュアル](../../docs/manual/schema.md)「業務の State と Lifecycle」）。いまは 53 件がすべて期待どおりで、到達率（`coverage`）は 48 の入口と遷移のすべてです。前段の操作が要る遷移のために、途中の状態のデータ（預かり済みの受付の依頼 `QST-0128`・期限前の失敗 `QST-0129`・審査の対象の `PRM-003` と `JEX-002`・実技試験に合格した審査中の `JEX-003`・休業の構成員のいる `PTY-004`）を置いています。
- `action` は操作の一覧です。`action labs/adventurers-guild accept-quest --on QST-0117 --param taker=PTY-001 --param date=2026-11-08` のように名前と値を渡すと、計画と適用後の検証を出します（`--apply` で書きます）。原本を変えずに試すなら、このフォルダを写してから使います。
