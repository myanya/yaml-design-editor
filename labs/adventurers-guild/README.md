# 冒険者ギルドの運営（試作）

架空の冒険者ギルドの運営を題材に、業務のオントロジー（何があり、どうつながり、どんな状態が正しいか）を YDE のワークスペースで定義する試作です。
冒険者・依頼・パーティのような概念を型に、つながりを関係レジストリに、運営の決まりを検査に書き、架空の運営データで確かめます。

いまは核の概念（支部・ランク・冒険者・パーティ・依頼者・依頼・受注）と関係を定義し、架空の運営データを置いたところです。検査・ビュー・操作はこれから足します。進め方・決まったこと・オーナーが決めることは [計画](PLAN.md) にあります。

## オントロジーを書く場所

オントロジーの要素を、YDE の定義のどこに書くかの対応です。別の形式（OWL など）や概念辞書を持たず、YDE の定義そのものをオントロジーとして育てます（[計画](PLAN.md)「オーナーに決めてほしいこと」で確かめます）。

| オントロジーの要素 | YDE で書く場所 |
|---|---|
| 概念（クラス） | オブジェクト型の `entity`（`.yde/schemas/` の型と文書スキーマ） |
| 属性 | 項目の定義（型・選択肢・範囲・必須） |
| 関係 | 参照（`type: ref` の `relation`）と、関係レジストリ `.yde/schemas/relations.yaml`（表示名・両端の型・多重度・非循環） |
| 全体と部分 | 保有（入れ子で書き、関係レジストリに名前を宣言する） |
| 公理・運営の決まり | 検査（多重度・パターン制約 `constraints`・型の検査・遷移検証 `flow`） |
| 個体 | 台帳 `guild/` の YAML 文書（架空の運営データ） |
| 状態の変化 | 操作（`actions`・`methods`）と、ダッシュボードの業務の流れ |

書き方の詳細はリポジトリの [利用者マニュアル](../../docs/manual/README.md)（[スキーマ](../../docs/manual/schema.md)・[検証](../../docs/manual/checks.md)・[ID とリンク](../../docs/manual/ids.md)）にあります。

## 配置

| 場所 | 内容 |
|---|---|
| `.yde/workspace.yaml` | 構成です。台帳は `guild/` の中だけです |
| `.yde/schemas/common.yaml` | 共通の型です。番号・参照・金額・日付・状態の型と、概念のオブジェクト型（`entity`）を持ちます |
| `.yde/schemas/relations.yaml` | 関係レジストリです。概念の表示名と、関係の向き・表示名・多重度を持ちます |
| `.yde/schemas/` のほか | 文書スキーマです（支部・ランク一覧・冒険者・パーティ・依頼者・依頼） |
| `.yde/views/` | 一覧・クロス集計・チャート・レンズの見え方・ダッシュボードを置きます（段階 3 で作ります） |
| `guild/branch.yaml` | ギルド支部です。町の名前と通貨の単位を持ちます |
| `guild/ranks.yaml` | ランク一覧です（SS・S・A・B・C・D・E・F）。上下は順位の数 `order` で比べます |
| `guild/adventurers/ADV-<番号>.yaml` | 冒険者です。1 人 1 ファイルです |
| `guild/parties/PTY-<番号>.yaml` | パーティです。リーダーと構成員（役割つき）を参照で持ちます |
| `guild/clients/CLT-<番号>.yaml` | 依頼者です |
| `guild/quests/QST-<番号>.yaml` | 依頼です。受注の記録（受け手・受注日・完了報告）を中に入れ子で持ちます |
| `PLAN.md` | 決まったこと・オントロジーの表・段階・オーナーが決めること・再開位置です |
| `AGENTS.md` | エージェント向けの決まりです |

## 開き方と検証

リポジトリのルートで実行します。

```bash
./gradlew run --args="labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="validate labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="schema-graph labs/adventurers-guild"
```

- `validate` は全文書の検証です。指摘の件数を [計画](PLAN.md)「いまの姿」に記録します。
- `schema-graph` は型と関係の図の材料（レンズの「型」の段と同じもの）で、オントロジーの全体を文字で確かめられます。
- 画面では、台帳スペースの「レンズ」で型の段に切り替えると、オントロジーを図で見られます。

## 試し方

1. このフォルダを YDE で開きます（上の `./gradlew run`）。ダッシュボードはまだ無いので、編集スペースで開きます。
2. 台帳スペースの「レンズ」を開き、型の段に切り替えます。依頼が依頼者・ランク・受注を指し、受注が冒険者かパーティを指す形が見えます。依頼から受注へは保有の線（ひし形）です。
3. 実体の段に戻し、起点を `QST-0001` にします。依頼 → 受注 → パーティ「銀の轍」→ 構成員の冒険者、とつながりを辿れます。
4. 台帳スペースの「エンティティ」で `ADV-0001` を開きます。関係の欄に、逆向きの名前（「率いるパーティ」「所属するパーティ」）が出ます。
5. 編集スペースで `guild/quests/QST-0004.yaml` を開き、受注の「受け手」を依頼者の番号（`CLT-001`）に変えると、検証パネルに誤りが出ます。確かめたら `Ctrl+Z` で戻します。

## データについて

- 登場する人物・団体・地名・魔物・品物は、すべて架空のオリジナルです。名前は実在のものや既存の作品と重ならない造語にします。
- 既存の作品の設定（固有の用語・ランクの呼び名の体系・登場人物）を写しません。
