# 冒険者ギルドの運営（試作）

架空の冒険者ギルドの運営を題材に、業務のオントロジー（何があり、どうつながり、どんな状態が正しいか）を YDE のワークスペースで定義する試作です。
冒険者・依頼・パーティのような概念を型に、つながりを関係レジストリに、運営の決まりを検査に、状態の変え方を操作に書き、架空の運営データで確かめます。

いまは核の概念と関係、運営の決まりの検査、一覧と集計のビュー、依頼を受付から精算まで進める操作、受付のダッシュボードを定義し（依頼の受付から精算までが一周しました）、世界（場所・魔物・素材・職能）と、運営（職員・規約・処分・昇格審査・素材の買取）と育成（職業訓練と資格）を足し、冒険者の管理と昇格審査にも業務の流れを作り、会計を閉じたところです（お金と物の動きから在庫と現金を導き、月末に棚卸と締めで確かめます。1 年の収支は [計画](PLAN.md)「会計の作りと 1 年の収支」）。進め方・決まったこと・オーナーが決めることは [計画](PLAN.md) にあります。

## オントロジーを書く場所

オントロジーの要素を、YDE の定義のどこに書くかの対応です。別の形式（OWL など）や概念辞書を持たず、YDE の定義そのものをオントロジーとして育てます（オーナーの決定）。

| オントロジーの要素 | YDE で書く場所 |
|---|---|
| 概念（クラス） | オブジェクト型の `entity`（`.yde/schemas/` の型と文書スキーマ） |
| 属性 | 項目の定義（型・選択肢・範囲・必須） |
| 関係 | 参照（`type: ref` の `relation`）と、関係レジストリ `.yde/schemas/relations.yaml`（表示名・両端の型・多重度・非循環） |
| 全体と部分 | 保有（入れ子で書き、関係レジストリに名前を宣言する） |
| 公理・運営の決まり | 検査（多重度・パターン制約 `constraints`・型の検査・遷移検証 `flow`） |
| 個体 | 台帳 `guild/` の YAML 文書（架空の運営データ） |
| 状態の変化 | 操作（`actions`）と、依頼・冒険者・昇格審査の履歴、ダッシュボードの業務の流れ |

書き方の詳細はリポジトリの [利用者マニュアル](../../docs/manual/README.md)（[スキーマ](../../docs/manual/schema.md)・[検証](../../docs/manual/checks.md)・[ID とリンク](../../docs/manual/ids.md)・[操作](../../docs/manual/actions.md)）にあります。

## 全体の概観

業務の領域ごとの概念と、主なつながりです。台帳スペースの「レンズ」を型の段にし、見え方「全体の概観」（`guild-overview`）の絞り込みで領域を 1 つ選ぶと、その領域の型だけを図で見られます。

| 領域 | 概念 | 主なつながり |
|---|---|---|
| 人と組織 | 本部・支部・職員・冒険者・パーティ・依頼者 | 支部は本部に属し、職員と依頼は支部に属し、パーティは冒険者を構成員に持ちます |
| 区分 | ランク・職能 | 冒険者とパーティはランクを、冒険者は職能を持ちます |
| 依頼の流れ | 依頼・受注・精算 | 依頼が受注を持ち、受注を冒険者かパーティが受け、精算が受注の報酬を払います |
| 世界 | 場所・魔物・素材 | 依頼は場所で行って魔物か素材を対象にし、魔物は場所に棲んで素材を落とし、植物と鉱物は産地で採れます |
| 育成（職業訓練） | 訓練の課程・受講・資格 | 課程は職能を身に付けさせ、職員か冒険者が教え、冒険者が受講し、修了すると初級の資格を得ます。依頼は職能を求められ、職能か資格で満たします |
| 評価と規律 | 規約・昇格審査・職能の審査・処分 | 昇格審査は受注の実績を根拠にし、合格すると対象のランクが 1 段上がります。職能の審査（試験）に合格すると、主な職能の段階が上がります。処分は規約の違反に対して冒険者かパーティに下し、受注停止の間は受注できず（パーティと構成員の両方に及びます）、除名なら冒険者は除名になります |
| 会計と在庫 | 預かり・返金・精算・委託契約と委託料・給与の支払い・経費・本部からの補填・素材の買取・売却・廃棄・棚卸・現金の締め | 依頼は預かりと返金を、委託契約は委託料を、職員は給与を、支部は経費と本部からの補填を持ちます。買取・売却・廃棄・棚卸は素材を指します。帳簿は持たず、在庫と現金は動きから導きます |

## 検査

運営の決まりは、指摘を誤りにしています（期限を過ぎてからの報告・履歴の無い依頼・討伐と納品の下限の目安・種別と対象と場所の整合・求める職能と段階・除名の処分の無い除名・安値の売却・棚卸と締めの差は警告）。どの決まりをどの書き方で書いたかは [計画](PLAN.md)「運営の決まり（検査）」にあります。

- 参照の切れと、参照する種類の誤り（受注の受け手は冒険者かパーティ）
- 関係の数: 冒険者とパーティのランクは 1 つ・構成員は 1〜6 人・リーダーと依頼者と受付支部は 1 つ・精算は受注 1 件につき 1 回まで
- パーティのリーダーは構成員の 1 人で、構成員はほかのパーティに入っていないこと
- 受け手のランクが、依頼の受注できるランクの下限以上であること（個人は個人の、パーティはパーティのランク）
- 休業・引退・除名・消息不明の冒険者が、遂行中の依頼を受けていないこと
- 遂行中の依頼の数が、受け手のランクの上限（F 1・E 2・D 3・C 4・B 5、A 以上は制限なし）までであること。個人とパーティで別に数えます
- 依頼の状態と、受注・完了報告・精算の有無が合っていること（掲示し直した依頼は、前の未達の受注を持てます）
- 日付の前後（期限・受注日は受付日以降、報告日は受注日以降、支払日は報告日以降）と、期限を過ぎてからの報告（警告）
- 精算の金額（報酬は依頼と同じ、手数料＝報酬 × 手数料率 ÷ 100、支払額＝報酬 − 手数料）と、報酬は 10 の倍数であること（手数料に端数が出ないように）
- 討伐依頼の受注できるランクの下限が、対象の魔物の討伐の目安のランクを下回らないこと（警告）。下限の無い討伐依頼は F とみなし、目安が F より上の魔物なら警告します。魔物の部位を納める納品依頼も、落とす魔物の目安で同じように確かめます
- 種別と対象の整合（警告）: 討伐には魔物があり、納品物はその魔物が落とす素材であること。採取の対象は魔物でも魔物の部位でもない素材、納品の対象は素材であること
- 討伐の場所が対象の魔物の生息地に、採取の場所が対象の素材の産地にあること（警告。場所のある依頼だけ）
- 求める職能のある依頼の受け手が、その職能かその職能の資格を持つこと（警告。パーティなら構成員の誰か）
- 昇格は 1 段ずつで、決まるまでの間は、審査のいまのランクが対象のいまのランクと同じであること。合格・不合格の審査には決めた日と決めた職員があること
- 受注停止の処分の間は受注していないこと（構成員の誰かが受注停止なら、そのパーティも。パーティが受注停止なら、その構成員も個人で）。除名の処分を受けた冒険者は除名の状態であること
- 職能の審査は対象の主な職能で、いまの段階は対象のいまの段階と同じ、目指す段階はそれより上であること
- 求める段階（中級・上級）のある依頼の受け手が、その職能のその段階以上（主な職能の段階か資格の段階）であること（警告）
- 預かりと返金: 掲示から先の依頼には預かりがあり、預かった報酬は依頼の報酬と同じ・受付料は報酬の受付料率・受け取った額は報酬 ＋ 受付料。返金は却下・取消・期限切れの依頼だけで、預かりのあるそれらには必ずあり、返す額は預かった報酬（受付料は返さない）
- 在庫と現金: 売った・捨てた後の在庫が 0 より少なくならないこと。売る単価は基準の買取価格の 1.5 倍以上（警告）。棚卸と締めの数えた値が導いた値と同じ（警告）。受け取った委託料は月の委託料と同じ
- 受注停止の処分には終わる日があること。受講の結果と終えた日が合っていること。訓練の課程の修了で得る資格は初級であること。買取の代金は単価 × 数であること

## 操作

依頼の状態は操作で進めます。どの操作も履歴に 1 行（日付・操作・前後の状態・理由）を残します。

| 操作 | 状態の移り方 | 止まるとき |
|---|---|---|
| 依頼を受け付ける | （作る）→ 受付 | — |
| 依頼を掲示する | 受付・失敗 → 掲示中 | 期限を過ぎている |
| 依頼を受注する | 掲示中 → 受注済み（受注 A1、A2 … を足す） | 期限を過ぎている・受け手のランクが下限に届かない・同時に受けられる数を超える・受け手が休業などで受注できない |
| 完了を報告する | 受注済み → 報告済み（達成）・失敗（未達） | — |
| 報酬を精算する | 報告済み → 精算済み（精算 PAY- を作る） | — |
| 依頼を却下する | 受付 → 却下 | — |
| 依頼を取り消す | 受付・掲示中・受注済み → 取消 | — |
| 依頼を期限切れにする | 掲示中・受注済み → 期限切れ | 期限がまだ過ぎていない・期限が無い |

冒険者と昇格審査の状態も操作で進め、それぞれの履歴に 1 行ずつ残します。

| 操作 | 状態の移り方 | 止まるとき |
|---|---|---|
| 冒険者を登録する | （作る）→ 現役 | — |
| 休業にする・引退にする・消息不明にする | 現役（引退は休業からも）→ 休業・引退・消息不明 | 個人で遂行中の依頼がある |
| 現役に戻す | 休業・消息不明 → 現役 | — |
| 除名する | 現役・休業・消息不明 → 除名（除名の処分 SNC- を作る） | 個人で遂行中の依頼がある |
| 処分を下す（注意・受注停止） | 変えない（処分 SNC- を作る） | 受注停止に終わる日が無い |
| 昇格審査の対象に決める | （作る）→ 審査の対象 | 1 段ずつでない・いまのランクが対象のランクと違う |
| 職能の審査の対象に決める → 試験を始める → 合格にする・不合格にする | 審査の対象 → 審査中 → 合格（主な職能の段階を上げる）・不合格 | 職能が主な職能でない・いまの段階が違う・目指す段階が上でない |
| 審査を始める | 審査の対象 → 審査中 | — |
| 合格にする | 審査中 → 合格（対象のランクを昇格先へ上げる） | 審査の間に対象のランクが変わった |
| 不合格にする | 審査中 → 不合格 | — |

お金と素材の操作は、状態ではなく在庫と現金の数を動かします。

| 操作 | 作るもの | 止まるとき |
|---|---|---|
| 報酬を預かる（依頼） | 依頼の中の預かり（報酬と受付料） | 受付の依頼でない・もう預かっている。掲示は預かってからです |
| 素材を買い取る・売る・捨てる | 買取 BUY-・売却 SEL-・廃棄 DSP- | 売る・捨てる数が在庫より多い |
| 棚卸する | 棚卸 STK- | 導いた数が、いまの在庫と違う（在庫の一覧から写します） |
| 給与を払う・経費を払う・本部から補填を受ける・現金を締める（支部） | 職員ごとの給与 WAG-・経費 EXP-・補填 SUP-・締め CLS- | 締めの導いた現金が、いまの現金と違う（支部の現金から写します） |
| 委託料を受け取る（委託契約） | 委託料の受け取り RCP- | — |

却下・取消・期限切れの操作は、預かっていれば報酬を返します（受付料は返しません）。ほかに「パーティを組む」があります。

- 依頼・冒険者・昇格審査の操作は、ダッシュボードの業務の流れの工程・業務詳細・エンティティページの ⋮・一覧の行の ⋯ から、ワークスペースの操作（受け付ける・登録する・組む・対象に決める）はダッシュボードの「操作」とコマンドパレット（Ctrl+K）から呼びます。
- 状態が合わないときと期限の条件は、操作の前提が理由を出して止めます。
- ランク・同時に受けられる数・受注できない状態・構成員の重なりは、「確認」で出る適用後の検証の誤りが止めます（適用ボタンが押せません）。
- 精算の手数料率は依頼の受付支部の率を写し、手数料と支払額を計算します。

## ダッシュボード

ワークスペースを開くと、ダッシュボード「ギルドの受付」（`guild-dashboard`）が出ます。ほかに「冒険者の管理」「昇格審査」「職能の審査」「会計と在庫」があり、台帳スペースの「ビュー」タブから開きます。

- **業務の流れ**: 掲示待ち（受付）→ 掲示中 → 遂行中 → 精算待ち → 精算済み の段と、工程（報酬を預かる・掲示する・受注する・報告する・精算する）の流れ図です。段を押すとその段の依頼の一覧、工程を押すとその段の依頼が「いま操作できる／できない（理由）」に分かれて並び、行から操作できます。入口の線は「依頼を受け付ける」です。
- **状況**: 流れの段の区画と、「期限を過ぎた掲示中・遂行中」（基準日で判定。期限切れにする候補）です。
- **流れの外**: 失敗（掲示し直せる）・期限切れ・却下・取消の区画です。流れ図には置きません。
- **会計**: 支部の現金・今月の精算（支払日の年月が基準日の年月）・月ごとの支払額の図・月ごとの手数料の表と、買取の記録・月ごとの買取額です。年・月は支払日・買い取った日から導きます。
- **名簿**: 冒険者の名簿とパーティの編成です。
- **世界**: 魔物・場所・素材の一覧です。
- **運営**: 職員・規約・処分の一覧、決まっていない昇格審査と昇格審査の一覧です。
- **育成**: 訓練の課程と資格の一覧です。
- **操作**: 依頼を受け付ける・冒険者を登録する・パーティを組む。
- 依頼の番号を押すと業務詳細が開き、上部の「流れの中の位置」に、いる段・次にできること・履歴が出ます。

「冒険者の管理」（`adventurer-desk`）は、登録 → 現役 ⇄ 休業・消息不明 → 引退・除名 の流れ図（処分を下すは現役の段に留まる工程）と、いま受注停止の処分・処分の一覧・資格と訓練の課程・パーティの区画です。
「会計と在庫」（`account-desk`）は、在庫なし ⇄ 在庫あり の流れ図（工程は 買い取る・売る・捨てる・棚卸する）と、現金（支部の現金・支部の収支・月ごとの入りと出・累計の図・種類別・手数料と受付料・締め）・委託と給与と経費・在庫の記録・冒険者の稼ぎの区画です。給与・経費・本部からの補填・締めは支部の行から、委託料は委託契約の行から操作します。
「職能の審査」（`job-exam-desk`）は、審査の対象 → 審査中 → 合格・不合格 の流れ図（入口は「職能の審査の対象に決める」）と、審査の材料（名簿・資格・訓練の課程）の区画です。
「昇格審査」（`promotion-desk`）は、審査の対象 → 審査中 → 合格・不合格 の流れ図（入口は「昇格審査の対象に決める」）と、審査の材料（名簿・編成・ランク × 種別）の区画です。

## 開き方と検証

リポジトリのルートで実行します。

```bash
./gradlew run --args="labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="validate labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="schema-graph labs/adventurers-guild"
```

```bash
./gradlew runCli -q --args="action labs/adventurers-guild"
```

- `validate` は全文書の検証です。指摘の件数を [計画](PLAN.md)「いまの姿」に記録します。
- `schema-graph` は型と関係の図の材料（レンズの「型」の段と同じもの）で、オントロジーの全体を文字で確かめられます。画面では、台帳スペースの「レンズ」で型の段に切り替えると図で見られます。
- `action` は操作の一覧です。`action labs/adventurers-guild accept-quest --on QST-0117 --param taker=PTY-001 --param date=2026-11-08` のように名前と値を渡すと、計画と適用後の検証を出します（`--apply` で書きます）。原本を変えずに試すなら、このフォルダを写してから使います。

## 試し方

ワークスペースを写してから開くと、原本を変えずに試せます。どの手順も `Ctrl+Z` 1 回で戻せます。

1. 写したフォルダを YDE で開くと、ダッシュボード「ギルドの受付」が出ます。業務の流れは 掲示待ち 2・掲示中 5・遂行中 2・精算待ち 1・精算済み 103 です（精算済みは過去 1 年分）。
2. 基準日を 2026-11-16 にすると「期限を過ぎた掲示中・遂行中」に `QST-0116`（期限 2026-11-15）が入ります。2026-11-24 なら 4 件です。基準日を今日に戻します。
3. 流れ図の「完了を報告する」の線を押すと、遂行中の 2 件が並びます。`QST-0115` の行から操作を開き、結果「達成」で適用すると、精算待ちが 2 件になります。続けて「報酬を精算する」の線から `QST-0115` を支払日 `2026-11-10` で精算すると、`guild/payments/PAY-0104.yaml`（報酬 150・手数料 15・支払額 135）ができ、精算済みが 104 件になります。
