# 家計簿の試作の引き継ぎ

新しいセッションで続きを頼むときは、次のプロンプトをそのまま貼ってください。

---

`labs/kakeibo` にある家計簿の試作の開発を続けてください。着手前に次を読んでください。

1. `labs/kakeibo/README.md`（構成・決めていること・検査とビュー・わざと入れた食い違い・動かし方）
2. `docs/manual/views.md`「値の式の列」と `docs/manual/checks.md`「パターン制約」の値の式（`all` / `each` / 配列を受け取る集計の書き方）
3. `docs/decisions/0010-expression-values-are-terms.md`（式の値は項・集合から値へは `all` だけ、の決定）

これまでに決まっていること（変えない）:

- 月はエンティティ（`M-YYYY-MM`）で、取引は `month` を参照で書く。年月を日付から切り出す式は足さない。
- 残高は手書きの期首残高と検査で守る。累計の列は作らない。不便なら「前月の期末残高を当月の期首に写す」組込みエージェントを検討する。
- 集計は `all` で集めて `sum` / `count` などの関数で畳む。古い書き方（集計の中の `of`、`count` に `match`）は定義エラーになる。
- 試作は `labs/` で作り、ある程度良いものができたら `samples/` へ置き直す。`samples/` へ移すかどうかはオーナーが決める。
- 新しいテーマや機能の着手はオーナーの判断。提案は出してよいが、指示を待つ。報告には試し方（操作手順と見てほしい観点）を添える。

前回の検討で「足りない」と分かっていて、まだ手を付けていないもの（優先順の目安）:

1. 取り込み skill の採番: 銀行の CSV には ID が無い。配列への取り込みと `IdSuggest` による採番が要る。
2. 桁区切りの表示: 金額の表示に桁区切りが無い。表示のヒントの領分。
3. 明細の並び: ビューの行は ID 順か一覧の順。ID を `TX-YYYYMMDD-NN` にして日付順を代用している。
4. 両方の軸が動く表（年×月など）: クロス集計ビュー `kind: matrix` は BACKLOG の UX-135。
5. 期首残高を写すエージェント: 上の決定のとおり、不便になってから。

最初にやること: `./gradlew runCli -q --args="validate labs/kakeibo"` を実行し、README にある 3 件の指摘が出ることを確かめてから、オーナーに次に何を進めるか聞いてください。
