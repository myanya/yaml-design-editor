# RPG Maker MZ のデータベース（試作）

RPG Maker MZ（以下 MZ）のデータベースを、YDE のワークスペースで再現する試作です。
アクター・職業・スキル・アイテム・武器・防具・敵キャラ・敵グループ・ステートとタイプを YAML の原本で持ち、参照の切れや MZ のエンジンの約束を検査します。
MZ の JSON を取り込み、書き出した JSON を実際の MZ に戻して動かすところまでを目指しています（[計画](PLAN.md)）。

データは、現代の地方都市で怪異の依頼を受ける探偵事務所を題材にした、架空のオリジナルです。

## 配置と原本

| 場所 | 内容 |
|---|---|
| `db/actors/ACT-<番号>.yaml` | アクターです。1 人 1 ファイルです |
| `db/classes/CLS-<番号>.yaml` | 職業です。レベルごとの能力値（レベル 1〜99）を表で持ちます |
| `db/skills/SKL-<番号>.yaml` | スキルです。1 番は通常攻撃、2 番は防御に使われます |
| `db/items/ITM-<番号>.yaml`・`db/weapons/WPN-<番号>.yaml`・`db/armors/ARM-<番号>.yaml` | アイテム・武器・防具です |
| `db/enemies/ENM-<番号>.yaml`・`db/troops/TRP-<番号>.yaml` | 敵キャラと敵グループです |
| `db/states/STA-<番号>.yaml` | ステートです。1 番は戦闘不能に使われます |
| `db/types.yaml` | MZ の「タイプ」（属性・スキルタイプ・武器タイプ・防具タイプ・装備タイプ）です |
| `db/system.yaml` | MZ の System.json のうち YDE が持つ部分（初期パーティと戦闘テスト）と、エンジンの約束です |
| `db/specials.yaml` | MZ が -1 や 0 で表す特別な選択肢（通常攻撃の属性など）の一覧です |
| `db/refs/` | MZ が持つもの（アニメーション・スイッチ）の番号と名前です。中身は MZ で作ります |
| `.yde/schemas/` | 型（`common.yaml`・`parts.yaml`）と、種類ごとのスキーマ、関係の語彙（`relations.yaml`）です |
| `.yde/views/` | ビューとダッシュボードです。ワークスペースを開くと、ダッシュボード `db-dashboard.yaml`（データベースの状況）が出ます（[ビューとダッシュボード](#ビューとダッシュボード)） |
| `.yde/skills/` | MZ の JSON の取り込み（`import-*.yaml`）と書き出し（`export-*.yaml`。一式は `export-all`）です。スキルタイプの「魔法スキル」は、まだ取り込みません（[計画](PLAN.md)） |
| `img/` | 画像です。MZ と同じ並び（`characters/`・`faces/`）で、装備のアイコンは `icons/` に 1 枚ずつ置きます（[データについて](#データについて)） |
| `out/` | 書き出した JSON の既定の置き場です（派生物なので git に載せません） |

番号の数字は、MZ のデータベースの番号そのものです（`SKL-0010` はスキルの 10 番）。

## 書き方の決まり

- 項目名は MZ のデータ（`data/*.json`）のままです。画面では MZ のエディタの日本語の名前で表示します。
- 区分（効果範囲・命中タイプなど）は MZ の数のまま書きます。画面では「敵単体」のような名前で選べます。
- 参照は番号ではなく ID で書きます（`classId: CLS-0001`）。存在しない ID や、種類の違う ID は検査で誤りになります。
- 特徴と使用効果は MZ と同じく `code`（画面では「種類」）で中身が決まり、`dataId` と値の項目が種類で変わります（属性有効度なら属性と倍率、ステート付加ならステートと確率）。
- 倍率と確率は MZ と同じく小数で書き（0.5）、画面では % で見せます（50%）。
- MZ が -1 や 0 で表す特別な選択肢は、`ELM-NORMAL`（通常攻撃の属性）・`ANI-NORMAL`（通常攻撃のアニメーション）・`STA-NORMAL`（通常攻撃のステート）と書きます。MZ がそれを許す項目でだけ選べます。
- 「なし」（MZ の 0）は、項目を書かないことで表します。アクターの初期装備の空の欄は `~` と書きます。
- 能力値の 8 個の並びには名前を付けます（`params: { atk: 10 }`）。書かない能力値は 0 です。
- 敵キャラのドロップアイテムは、使う枠だけを書きます（MZ の枠は 3 つです）。
- 敵グループのバトルイベント（`pages`）は MZ で編集し、YDE は中身を解釈しません。
- アクターの画像（歩行・顔・サイドビューの戦闘キャラ）は、ワークスペースの中の場所で書きます（`faceName: img/faces/ACT0002_Shirasagi_Faces_8.png`）。フォームで画像が見え、書き出しでは MZ の名前（拡張子なし）に戻します。無い画像は警告です（MZ のプロジェクトにだけある画像を指すことがあるため）。
- 武器・防具・アイテムの `iconImage` は、YDE で見るためのアイコンの画像です（書き出しません）。MZ では `img/system/IconSet.png` の空いた枠に足し、その枠の番号を `iconIndex` に書きます。
- ステートの `addedByEvent`（イベントで付ける）も YDE だけの印です（書き出しません）。MZ のイベントのコマンドだけで付けるステートに付けると、「どこからも付加されない」の警告が出なくなります。

## 検査

- 参照の切れと、参照する種類の誤り（特徴・使用効果・ドロップ・行動パターンはコードに合った種類か）
- MZ のエンジンの約束（ステート 1 番・スキル 1 番と 2 番があること。`db/system.yaml` の `engine`）
- ダメージタイプが「なし」以外なら計算式があること
- ドロップアイテムが 3 つまでであること
- 初期レベルが最大レベル以下であること、継続ターン数の最小が最大以下であること
- 職業のレベルごとの能力値が 99 行あること（警告）
- 初期装備の武器と防具が、職業の特徴（武器タイプ装備・防具タイプ装備）で装備できること（警告。MZ はゲームの開始時に、装備できない初期装備を黙って外します。MZ の既定のデータにも 1 件あります）
- ステートが、スキル・アイテムの使用効果か、特徴の「攻撃時ステート」のどれかで付加されること（警告。1 番の戦闘不能と、イベントで付けると印を付けたステートは除きます）
- 敵キャラが、どれかの敵グループに出てくること（警告。出てこない敵キャラは戦闘に出ず、ドロップアイテムも手に入りません。指摘のメニューから敵グループを作れます）
- 敵グループの構成員が 8 体までであること

## ビューとダッシュボード

| ビュー | 内容 |
|---|---|
| データベースの状況（`db-dashboard`） | 開くと最初に出るダッシュボードです。「確認」の群（敵グループに出てこない敵キャラ・どこからも付加されないステート）は 0 件が正常です |
| 敵キャラ一覧 | 能力値・経験値・所持金と、HP 100 あたりの経験値・ドロップアイテム・出現する敵グループを 1 行ずつ並べます |
| ドロップ表 | 落とすものごとに、落とす敵キャラを並べます。MZ のエディタでは敵キャラの側からしか見えない入手先を、アイテムの側から引けます |
| 敵キャラの HP と報酬 | 最大HP を横軸、経験値と所持金を縦軸にした散布図です。ボスは桁が違うので、両方の軸を対数にしています |
| 職業の比較・職業の能力値・職業の HP・MP | レベル 99 の能力値の表と、職業ごとの棒グラフです |
| ステート一覧 | ステートごとに、付加するものと解除するもの（スキル・アイテム・特徴）を逆引きで並べます |
| 職業（成長曲線つき） | 職業を開いたときの「ビュー」タブです。成長を折れ線で見ます |

## 操作

- **敵キャラを作る**（ダッシュボードの「操作」）: 名前と能力値・経験値・所持金を入れて、敵キャラを 1 体作ります。行動は通常攻撃だけで始まります。
- **この敵キャラの敵グループを作る**（敵キャラのエンティティページの ⋮・一覧の行の ⋯・「どの敵グループにも出てきません」の指摘）: その敵キャラ 1 体の敵グループを作ります。
- **敵キャラを加える**（敵グループのエンティティページの ⋮）: 構成員に 1 体加えます（8 体まで）。

## 試し方

1. このフォルダを写して、YDE で開きます。最初に「データベースの状況」のダッシュボードが出ます。「確認」の 2 つが 0 件で、敵・職業・ステートの群に表と図が並びます。
2. ダッシュボードの「操作」から「敵キャラを作る」で 1 体作ると、「敵グループに出てこない敵キャラ」が 1 件になり、検証パネルに警告が出ます。警告のメニューの「この敵キャラの敵グループを作る」で敵グループを作ると、0 件に戻ります。
3. `db/skills/SKL-0020.yaml`（ひっかく）の使用効果（出血の付加）を消すと、「どこからも付加されないステート」に出血が出ます。
4. `db/skills/SKL-0011.yaml`（浄化）の使用効果を開くと、1 件ごとに「種類 ステート解除 ／ ステート STA-0005 — 呪い ／ 確率 100%」と並びます。種類を切り替えると、その下の項目が変わります。
5. `STA-0005`（呪い）のエンティティページを開くと、呪いを付加するスキル（呪詛・呪いの炎）と、呪いを解くアイテム（清めの塩）がつながって見えます。
6. `db/classes/CLS-0001.yaml`（探偵）の「ビュー」タブを開くと、HP・MP と 6 つの能力値の成長が、レベルを横軸にした折れ線で見えます。表の行を書き換えると、図も変わります。
7. 参照を存在しない ID に書き換えると、検証パネルに誤りが出ます。CLI では `./gradlew runCli -q --args="validate labs/rpmz"` で検証できます。
8. 書き出すときは、設計スペースの「連携（skill）」で `export-all` を選び、「出力先を選ぶ…」で MZ のプロジェクトの `data` フォルダを選びます（System.json は既存のファイルに書き込むので、そのフォルダに要ります）。上書きの確認が一括で 1 回出ます。CLI では `export labs/rpmz export-all --out <MZ のプロジェクト>/data`（上書きは `--yes`）です。画像は `img/characters/`・`img/faces/` の PNG を、MZ のプロジェクトの同じフォルダへ写します。
9. MZ のプロジェクトの JSON を取り込むときは、このフォルダの `.yde/` と `db/specials.yaml` だけを空のフォルダへ写し、そこへ取り込みます（架空のデータと混ざらないように）。取り込みの定義は種類ごとに 1 つで、CLI では `import <写した先> import-skills <MZ のプロジェクト>/data/Skills.json --apply` のように実行します（タイプ・初期パーティ・スイッチの名前は System.json から `import-types`・`import-system`・`import-refs` で）。

## データについて

- 人名・地名・団体名・スキル名・説明文はすべて架空のオリジナルです。
- `img/` の画像は、この試作の 4 人（霜月 律・白鷺 灯・大槻 鉄平・御厨 詩織）のためにオーナーが用意した、AI 生成のオリジナルです。顔（144×144 の 8 表情）・歩行（48×48）・装備のアイコン（32×32）を MZ でそのまま使える形で置き、原画と 64×64 の歩行は置いていません。トレンチコートと探偵手帳には人ごとの別のデザイン（`Navy_Trench_Coat_32.png` など）がありますが、MZ の装備 1 つにアイコンは 1 つなので、霜月のものを使っています。
- 音・動画の素材と、MZ の既定の素材は含みません。画像を書いていないもの（敵キャラなど）は空のままです（MZ は名前が空の画像を読まないので、素材がなくても動きます）。
- MZ の新規プロジェクトに入っている既定のデータベースの内容は、ここには含めていません。
- `db/refs/animations.yaml` の番号の中身は MZ のプロジェクトで決まります。名前は使い方の目安です。
