# RPG Maker MZ のデータベース（試作）

RPG Maker MZ（以下 MZ）のデータベースを、YDE のワークスペースで再現する試作です。
アクター・職業・スキル・アイテム・武器・防具・敵キャラ・敵グループ・ステートとタイプを YAML の原本で持ち、参照の切れや MZ のエンジンの約束を検査します。
書き出した JSON を実際の MZ に戻して動かすところまでを目指しています（[計画](PLAN.md)）。

データは、現代の地方都市で怪異の依頼を受ける探偵事務所を題材にした、架空のオリジナルです。

## 配置と原本

| 場所 | 内容 |
|---|---|
| `db/actors/ACT-<番号>.yaml` | アクターです。1 人 1 ファイルです |
| `db/classes/CLS-<番号>.yaml` | 職業です。レベルごとの能力値（レベル 1〜99）を表で持ちます |
| `db/skills/SKL-<番号>.yaml` | スキルです。1 番は通常攻撃、2 番は防御に使われます |
| `db/items/ITM-<番号>.yaml`・`db/weapons/WPN-<番号>.yaml`・`db/armors/ARM-<番号>.yaml` | アイテム・武器・防具です |
| `db/enemies/ENM-<番号>.yaml`・`db/troops/TRP-<番号>.yaml` | 敵キャラと敵グループです |
| `db/states/STA-<番号>.yaml` | ステートです。1 番は戦闘不能に使われます |
| `db/types.yaml` | MZ の「タイプ」（属性・スキルタイプ・武器タイプ・防具タイプ・装備タイプ）です |
| `db/system.yaml` | MZ の System.json のうち YDE が持つ部分（初期パーティと戦闘テスト）と、エンジンの約束です |
| `db/specials.yaml` | MZ が -1 や 0 で表す特別な選択肢（通常攻撃の属性など）の一覧です |
| `db/refs/` | MZ が持つもの（アニメーション・スイッチ）の番号と名前です。中身は MZ で作ります |
| `.yde/schemas/` | 型（`common.yaml`・`parts.yaml`）と、種類ごとのスキーマ、関係の語彙（`relations.yaml`）です |
| `.yde/views/` | ビューです。`class-doc.yaml` は職業を開いたときの「ビュー」タブで、成長曲線を図にします |

番号の数字は、MZ のデータベースの番号そのものです（`SKL-0010` はスキルの 10 番）。

## 書き方の決まり

- 項目名は MZ のデータ（`data/*.json`）のままです。画面では MZ のエディタの日本語の名前で表示します。
- 区分（効果範囲・命中タイプなど）は MZ の数のまま書きます。画面では「敵単体」のような名前で選べます。
- 参照は番号ではなく ID で書きます（`classId: CLS-0001`）。存在しない ID や、種類の違う ID は検査で誤りになります。
- 特徴と使用効果は MZ と同じく `code`（画面では「種類」）で中身が決まり、`dataId` と値の項目が種類で変わります（属性有効度なら属性と倍率、ステート付加ならステートと確率）。
- 倍率と確率は MZ と同じく小数で書き（0.5）、画面では % で見せます（50%）。
- MZ が -1 や 0 で表す特別な選択肢は、`ELM-NORMAL`（通常攻撃の属性）・`ANI-NORMAL`（通常攻撃のアニメーション）・`STA-NORMAL`（通常攻撃のステート）と書きます。MZ がそれを許す項目でだけ選べます。
- 「なし」（MZ の 0）は、項目を書かないことで表します。アクターの初期装備の空の欄は `~` と書きます。
- 能力値の 8 個の並びには名前を付けます（`params: { atk: 10 }`）。書かない能力値は 0 です。
- 敵キャラのドロップアイテムは、使う枠だけを書きます（MZ の枠は 3 つです）。
- 敵グループのバトルイベント（`pages`）は MZ で編集し、YDE は中身を解釈しません。

## 検査

- 参照の切れと、参照する種類の誤り（特徴・使用効果・ドロップ・行動パターンはコードに合った種類か）
- MZ のエンジンの約束（ステート 1 番・スキル 1 番と 2 番があること。`db/system.yaml` の `engine`）
- ダメージタイプが「なし」以外なら計算式があること
- ドロップアイテムが 3 つまでであること
- 初期レベルが最大レベル以下であること、継続ターン数の最小が最大以下であること
- 職業のレベルごとの能力値が 99 行あること（警告）

## 試し方

1. このフォルダを写して、YDE で開きます。
2. `db/skills/SKL-0011.yaml`（浄化）の使用効果を開くと、1 件ごとに「種類 ステート解除 ／ ステート STA-0005 — 呪い ／ 確率 100%」と並びます。種類を切り替えると、その下の項目が変わります。
3. `STA-0005`（呪い）のエンティティページを開くと、呪いを付加するスキル（呪詛・呪いの炎）と、呪いを解くアイテム（清めの塩）がつながって見えます。
4. `db/classes/CLS-0001.yaml`（探偵）の「ビュー」タブを開くと、HP・MP と 6 つの能力値の成長が、レベルを横軸にした折れ線で見えます。表の行を書き換えると、図も変わります。
5. 参照を存在しない ID に書き換えると、検証パネルに誤りが出ます。CLI では `./gradlew runCli -q --args="validate labs/rpmz"` で検証できます。

## データについて

- 人名・地名・団体名・スキル名・説明文はすべて架空のオリジナルです。
- 画像・音・動画などの素材は含みません。画像名の項目は空のままです（MZ は名前が空の画像を読まないので、素材がなくても動きます）。
- MZ の新規プロジェクトに入っている既定のデータベースの内容は、ここには含めていません。
- `db/refs/animations.yaml` の番号の中身は MZ のプロジェクトで決まります。名前は使い方の目安です。
