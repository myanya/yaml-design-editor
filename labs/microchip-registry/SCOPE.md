# 犬猫マイクロチップ登録業務：YDE で実現できた範囲

[README](README.md) の補足です。要件定義書の業務のうち、このワークスペースで何が再現でき、何ができていないかを 1 枚にまとめます。
業務ごとの対応の原本は `spec/businesses.yaml`（ダッシュボード「要件定義書との対応」）で、この文書はその時点の写しです。

- 対象: 環境省 動物愛護管理室「要件定義書」（令和 3 年 4 月。指定登録機関 Web システム）
- 時点: 2026-11-20

## 位置づけ

- 業務の中身（データ・状態・前提・記録・照会）を、1 人が手元で動かせる模型として再現したものです。
- プログラムは書かず、YAML の定義だけで作りました。データはすべて架空です。
- Web システムとしての手段（ログイン・決済・メール・規模・非機能要件）は対象外です。
- 確認は CLI だけで、画面では開いていません。内容のレビューも受けていません。

## 要件定義書のほかの一覧との対応

| 一覧 | 件数 | 対応 |
|---|---|---|

| 業務フロー（別紙 3） | 31 本・工程 243 個 | すべて写した。システムを使う工程 133 個のうち 108 個に操作かビューを対応付け |
| 帳票（表 8） | 16 | 一部 2（登録証明書・ワンストップ情報 CSV）、外のスクリプト 6（一括の CSV）、対象外 8（申請書などの様式） |

## 再現していないこと

| 要件 | 扱い |
|---|---|
| ログイン、利用者区分ごとの閲覧制限 | 無し。ダッシュボードの入力で絞るだけで、権限ではない |
| 決済 | システムの外。確かめた入金を記録する |
| メール | 送らない。文面をレポートで作る |
| 個別 Web と共通 DB の分離、API の呼び出し | 1 つのワークスペースにまとめた |
| PDF・Word の帳票、申請書の様式 | 登録証明書は HTML。様式は作っていない |
| 規模（年 57 万件の登録）、非機能要件 | 対象外 |

## 確かめたこと

- ワークスペースの検証: エラー 0・警告 0
- 業務シナリオ: 15 件すべて合格（宣言した 15 の遷移をすべて通る）
- 断るべき場面で理由つきで止まること（二重登録、違う変更キー、支払額の誤り、死亡後の手続）
- 一括の 3 種: 見本の CSV で 4 行のうち 2 行が成功、2 行が理由つきで失敗
- 業務フロー図: 31 本とも表示モデルが診断なしで解決

## 確かめていないこと

- 画面での操作と見え方
- 業務 Web での利用
- 業務フローの写しと、原本の図との突き合わせ（元は図で、文字に変換したものから読んだため、矢印の向きや分岐は文脈から補っています）
- 要件どおりかどうかの内容のレビュー

## 仮に置いたもの

- 犬猫情報の項目（要件定義書に項目の一覧が無い）
- 料金の額
- 飼養管理基準の判定条件（出産時に母親が 6 歳を超える）
- 変更キーの値（申請番号から決まる値。実システムは推測できない値）
