# ローカル接続

## 概要

ローカル接続は、通信ライブラリを local-server に閉じる組込み構成を取る。
現在は設定型・機能別の状態機械・loopback 待受と、SDK・HTTP・同梱ランタイムの互換性検査がある。
DesktopRuntime が接続管理を所有するが、設定画面と業務経路は未接続で、通常起動では全て OFF のまま待受しない。
全体の設計契約は [ローカル接続の決定](../decisions/0016-local-connections-and-shared-host.md)、実施順序は ROADMAP にある。
外部確定と Undo の扱いは [履歴の決定](../decisions/0017-external-commit-and-desktop-history.md) が補足する。

## 部品

| 部品 | 責務 |
|---|---|
| `server.LocalConnectionSettings` | API・MCP・Web の初期値 OFF と利用者指定ポートの範囲 |
| `server.LocalConnections` / `LocalConnectionStatus` | 希望値と実状態の通知、三機能の受付・停止・要求の収束と一つの待受の寿命 |
| `server.transport.LocalConnectionGate` / `server.LocalRequest` | HTTP 経路の機能判定、停止時の 404、要求と子ストリームの取消、保存完了待ち |
| `service.WorkspaceHost` / `WorkspaceStatus` | 共通セッションの所有、状態の世代・版・未保存・競合・処理中の通知、所有スレッドへの受付 |
| `service.SourceDraftWorker` | 画面と独立した下書きの遅延解析・木との同期、古い入力の採用防止 |
| `desktop.DesktopRuntime` | アプリ全体とワークスペース単位の寿命、監視・自動実行・手動実行・終了の統括 |
| `service.WorkspaceOperations` | 計画の保管・前提と権限の再確認・外部確定・再送と復旧の共通窓口 |
| `service.OperationJournal` / `FileOperationJournal` | 要求 ID と結果の永続化、記録の破損・保管上限での受付停止 |
| `service.WorkspaceWork` / `WorkRecord` | 外部作業の開始・編集・検証・提出・破棄と、デスクトップ専用の確認・承認・却下 |
| `service.WorkJournal` / `WorkChanges` | 提出内容と採否の永続化、コメントと型付きのパスを保持した変更セットの復元 |
| `desktop.ExternalWorkController` / `ui/run/ExternalWorkPane.kt` | 受信箱の外部提出、確認時の差分・検証・保存結果の表示 |
| `server.transport.LoopbackEngine` | CIO の明示起動と終了、`127.0.0.1` の固定、確定したポートの取得 |
| `TransportCompatibilityTest` | Ktor testApplication と公式 MCP クライアントによる JSON・初期化・ツールの往復 |
| `LocalServerDistributionSmoke` | CIO の実待受・停止・占有時の失敗と、同梱 JAR だけでの MCP 往復 |

通信依存の版は `gradle/libs.versions.toml` にまとめ、local-server の解決結果を lockfile に固定する。
JSON の版は既存の agent・app-core・CLI の試験も含めて検査する。

## 流れ

LoopbackEngine の生成では待受しない。`start()` の成功後にだけ確定ポートを返す。
ポートが占有されているときは失敗し、別ポートや全 NIC に切り替えない。
`close()` で待受を止め、終了後のインスタンスは再起動させない。
CIO の内部ジョブは専用の寿命で所有し、起動失敗の内部通知もそこで受ける。終了は内部ジョブの収束まで確認する。
利用者の設定ではポート 0 を許さず、試験では OS が空きポートを選ぶために内部の部品へ 0 を渡す。

## 機能別の切替と停止

LocalConnections の構築時は三機能とも OFF で、待受の構築も行わない。configure だけが希望値を変える。
希望値と実状態は LocalConnectionStatus の StateFlow で配り、停止・起動中・稼働・停止中・エラーを機能別と待受別に持つ。
一つの worker が起動・停止を直列に行い、連続した指定は最新の希望値へ収束する。同じ値の再指定で失敗を明示的に再試行できる。
ポートは、希望値が全 OFF で実際の停止も完了している場合だけ変更できる。

| 機能 | 受付対象 |
|---|---|
| API | `/api/v1` と配下 |
| MCP | `/mcp` と配下 |
| Web | `/app` と `/web-api` および配下 |

受付ゲートはルーティング前に機能の希望値と実状態を確認する。停止・起動途中の機能、上記に属さない経路は 404 とし、health 用の別口も作らない。
Web 専用の通信は API の設定を参照しない。`/api/v10` など、接頭辞だけが同じ別経路を許可しない。
これは機能の受付制御であり、認証・Host/Origin・CSRF 検査の代わりにはならない。製品側の業務経路はまだ登録していない。

OFF の受付時点で新規要求を止め、その機能の世代を変える。要求の子ジョブだけを取り消し、他機能の受付と共有待受を維持する。
要求の本体が返った後も、子のストリームが完了するまで登録を保持する。onDisabled は MCP セッション等の終了口で、失敗時に再試行するため繰り返し呼べる実装を渡す。
機能に結び付く認可やセッションは、受付時に accepts で世代も照合する。OFF → ON でも古い世代には戻さない。
認証と SDK セッション管理への接続は後続工程で行う。

保存の入口は LocalRequest.finishWrite で失効前であることを確認し、開始した保存・結果記録だけを取消から保護する。
停止処理は要求の Job 全体の完了を待つ。これは WorkspaceOperations の確定を包む境界であり、検証・権限を省いた書込や任意要求の取消免除には使わない。
停止中に ON が来ても、古い要求とセッションの終了を取り消さず、収束後に新しい世代で受付を再開する。

最後の機能が収束したら LoopbackEngine を閉じ、keep-alive を含む接続と待受を解放する。
停止失敗ではハンドルとポートを保持し、エラーを表示する。機能を OFF と指定したことだけでは停止完了としない。
起動失敗でも希望値は残し、自動で別ポートへ移ったり再試行を繰り返したりしない。
DesktopRuntime の通常終了は接続の停止を待つ。停止失敗ではアプリ終了を中断し、再試行できる。アプリ寿命の取消でも所有する接続の後始末を行う。
画面やワークスペースを開くだけでは設定を変えず、接続の停止でも作業コピー・提出・Undo を捨てない。

LocalConnectionsTest・LocalConnectionGateTest が全八組合せ・切替競合・世代失効・読取取消・保存待ち・停止失敗を検証する。
LocalListenerLifecycleTest は試験自身の loopback で他機能の継続、keep-alive の切断、ポート再利用、占有時の拒否を確認する。

## 規律

- Ktor と MCP SDK の import と実行時の直接依存は local-server だけに置く。
- local-server は app-core とカーネルまでに依存し、Compose・agent・desktop・cli・形式の拡張に依存しない。
- app-core・agent・カーネル・拡張から local-server へ依存しない。desktop が組み立て、CLI の通信アダプターもこの境界に置く。
- app.service は app-core の最上層として扱い、通信・画面・agent に依存しない。
- モジュールを依存に足すだけでは起動しない。設定の永続化と利用者による有効化は desktop の責務。
- テスト用の経路・ツールを main に置かない。待受の試験は自分が起動した loopback だけを使い、成功・失敗のどちらでも閉じる。
- 通信と接続管理は実行基盤で、Core Calculus の新しい業務評価や書込経路を追加しない。

## 共通状態と寿命

DesktopRuntime は Window の外で生成し、WorkspaceHost と AppState を一つずつ保持する。
AppState は Host の DocumentSession を受け取り、画面の覚えと Compose の写しを持つ。
保存済みを映す Workspace と編集用 WorkspaceSession、カーネルの単一履歴は分けたまま使う。
WorkspaceStatus は可変の本文を含めず、StateFlow で最新値を配る。セッション交換で世代を変え、旧世代の要求を拒否する。
版は文書の変更とソース入力で進め、処理中の開始・終了だけでは進めない。デスクトップでは操作途中の通知を所有スレッドの次の処理へまとめる。
文書とセッションは解除可能な複数購読を持ち、画面と共通状態が互いの購読を上書きしない。
OpenDocument の Compose の写しだけは最後に作った殻へ接続し、破棄した描画の殻を購読一覧へ残さない。

監視・AutomationEngine・RunController・SourceDraftWorker はワークスペース単位の子ジョブである。
AppRoot と SourcePane はこれらを起動・停止しない。画面がなくても監視・解析・質問待ち・実行を保持する。
切替は候補の読込成功後に旧ジョブの終了を待って採用する。読込失敗では旧状態・履歴・ジョブを残す。
監視の登録直後に本文も再確認し、候補の読込から登録までの変更を取り込む。
終了は新規要求を止め、進行中のファイル操作の反映を待ってから監視と子ジョブを終了する。
トレイ・非表示起動の利用者操作と接続の ON/OFF はまだ公開していない。

共有状態の通常操作は DesktopUiDispatcher に集める。ソース解析は文字列を渡して背景で計算し、文書・版・入力世代を確認して採用する。
ファイル配置とその履歴は WorkspaceSession の PendingFileOperation が独立した状態で処理し、所有スレッドの finish で採用する。
処理中の画面は確定済みのセッションを参照できるが、編集・接続からの受付は止め、監視と解析結果の反映を保留する。
書込が始まった作業は呼出し元の取消で途中放棄せず、結果の反映まで完了してから処理中を解除する。

試験は WorkspaceHostTest・DesktopRuntimeTest・BackgroundFileOperationTest と、既存の編集・履歴・外部変更の試験で行う。

## 操作の計画と外部確定

WorkspaceOperations は Host の排他区間で計画・確定を受ける。結果照会は背景で記録を読み、前後に世代と権限を確認して、照会だけでは編集を待たせない。
DesktopRuntime が一つ持ち、権限の供給がない既定状態では全て拒否する。
接続の認証と権限登録は後続の接続口であり、通常起動から外部に公開する経路はまだない。
ワークスペース ID の解決は注入する。既定は実パスのハッシュで、要求から任意の場所を開かせない。

計画は保存済みの独立したセッションで ActionPlanner と ChangeSetApplier.prepare を通す。
入力・計画時刻・世代・編集の版・保存済み文書一覧と本文・権限を計画 ID に結び付け、10 分保持する（最大 256 件）。
返す差分は自動値を含む確定候補で、可変の木を含まない。確定要求は計画 ID と要求 ID だけを渡し、変更内容を差し替えない。

- 計画後のデータ・定義・権限・世代・編集の版の変化と期限切れは再計画を求める。別文書の編集でも当初は失効する。
- 監視の通知と更新時刻だけには依存せず、確定前に文書一覧と本文を照合する。スキーマを読み込めない場合も拒否する。
- 対象に未保存・未反映入力・壊れた下書き・未解決の外部競合があれば拒否する。他文書の未保存内容は保持する。
- 変更対象と影響先に検証エラーが残れば拒否し、警告だけなら許可する。既存のエラーも含み、外部要求で検証を免除できない。
- 影響先の検証はカーネルの ChangeSetValidation を WorkingCopy と共用する。前後の ID・文書への参照元と、横断検査の結果が変わる文書を含める。
- 業務操作の前提は ActionPlanner で再確認する。前提の違反・保留をエラー数だけで判定し直さない。
- 権限は信頼できる入口から供給する。操作名と書込文書を照合し、定義・記録文書は外部確定の対象にしない。
  任意の変更セットの確定権限は外部提案の承認など専用の入口に限る。通常の業務操作の権限では任意パッチを確定できない。

確定は独立したセッションへ ChangeSetApplier.applyPrepared を当て、確認済みの自動値を再計算せず保存する。
文書別に保存済み・変更なし・未保存・結果不明を返す。一部の保存だけ成功しても全体を成功と扱わない。
DocumentSession.acceptExternalCommit が Workspace.noteDiskChanges に取り込みを依頼し、編集用セッションへ実結果を採用する。
外部確定を編集用の Undo に追加しない。変更文書に触れる古い一手を適用不可にし、無関係な Redo と編集を保持する。
カーネルの定義変更に対する全履歴失効も用意するが、外部窓口で定義書換えを許可するものではない。
デスクトップと内蔵レビューは従来の適用窓口を使い、一手の Undo と既存の検証設定を維持する。

## 要求記録と復旧

記録は WorkspaceLayout の runs 領域の `local-operations/*.json` に置く。本文と資格情報を記録せず、変更前後のハッシュと文書別結果を持つ。
ファイル名はワークスペース ID・接続者 ID・要求 ID のハッシュで、任意の要求 ID をファイル名へ直接使わない。
同一要求の再送は前の結果を返し、同じ要求 ID の別内容への再利用は拒否する。照会・再送にも現在の許可と対象文書の範囲を要求する。

受付済み → 実行中を原子的な置換と flush で記録してから書込を始め、最後に成功・拒否・部分保存・結果不明のいずれかを記録する。
接続者が取消・切断しても開始後は反映と記録まで継続する。最後の記録が失敗しても、残った実行中の記録で再実行を止める。
再起動後の受付済みは書込前の拒否、実行中は結果不明として返し、どちらも自動で再実行しない。

結果不明の対象には別の要求 ID でも確定できない。復旧権限を持つ入口から全対象の現在のハッシュを確認して reconcile を呼び、
一致した内容を採用して照合済みにする。照合後も元の要求は再実行せず、新しい変更は新しい計画で行う。復旧の画面はまだ公開していない。
記録は自動削除せず、既定の上限は 10,000 件・1 件 1 MiB。上限や記録の破損では新しい書込を開始しない。
複数文書全体のディスク保存を原子的に戻す仕組みではなく、部分保存を確認可能な結果として扱う。

契約は ExternalCommitTest と WorkspaceOperationsTest で検証する。未保存保護、履歴の停止、権限・版・期限、保存と記録の故障、再送・再起動・照合を含む。

## 外部作業と提出・承認

WorkspaceWork は通信接続と別の作業 ID を発行する。接続の切断で作業を破棄しない。
begin・stage・validate・submit・discard・result は認証済みの OperationCaller を受け取り、接続者とワークスペースを照合する。
WorkGrant は提案を許した文書の集合と権限の版だけを持つ。空集合・供給なしは拒否で、提案権限だけで原本を書き換えるメソッドはない。
review・approve・reject・refresh と inbox の購読はデスクトップ専用で、通信アダプターへ公開しない。

未提出の WorkingCopy はメモリに保持する。開始時の保存内容と権限が変われば新しい作業を求め、サービス内の Mutex と Host でアクセス順を守る。
一回の編集要求は独立コピー上で最後まで成功した場合に採用する。パッチの記録値は適用先の木と共有せず、後続の入れ子編集や再検証で過去の操作を変えない。
検証と提出は ChangeSetApplier.prepare を通し、自動値を含む変更対象と影響先を検証する。エラーがあれば提出を拒否し、警告だけなら承認待ちへ進む。
提出前の状態は作業中・検証済み・破棄済み。未提出の ID は再起動で消え、存在しない ID を成功として返さない。

提出は内容を固定して記録した後に承認待ちへ移る。同じ ID の提出再送は既存の提出を返し、提出後の編集は受け付けない。
人間が「差分と検証を再確認」を行うと、現在の権限・対象の競合・未保存編集を調べ、WorkspaceOperations が自動値込みの確定計画を作る。
「承認して保存」は提出 ID と確認した計画 ID を照合し、承認開始を記録してから同じ共通窓口で確定する。
権限は承認直前にも元の接続者について再確認し、検証の免除は認めない。複数文書の提出は全体を承認し、画面からファイル単位の部分採用はしない。
却下・破棄は原本に書かず、提出済みなら内容と結果を残す。確定失敗後の修正は新しい作業で提出する。

記録は WorkspaceLayout の runs 領域の `local-work/*.json`。RunLog の会話・トークン会計と分け、資格情報を保存しない。
変更セットの値を YAML 文字列、パスを文字列と添字の配列で保存し、新規文書とパッチのコメントを復元する。
提出には差分用の本文を含むため、操作のハッシュ記録と異なり作業対象の内容も保存される。
未提出は最大 64 件・変更セット 2 MiB、提出記録は既定 10,000 件・1 件 4 MiB。上限・破損・保存失敗は無視せず、提出失敗では作業コピーを残す。

復元は承認待ちを自動適用しない。承認を始めた提出は要求記録と照合し、保存済み・失敗・部分保存・結果不明・照合済みを返す。
提出側の最終記録が失敗しても OperationJournal を正として復元する。確定の要求記録が見つからない場合も結果不明として止める。
文書別の保存結果を残し、結果不明や部分保存を成功と表示しない。承認後の保存は取消に左右されず、結果記録まで完了する。
受信箱はこの状態の射影で、画面を離れても採否を保持する。内部エージェントの RunLog・承認方針・Undo は変更せず、提出ゲートだけ SubmissionChecks を共用する。
結果照会と受信箱の再読込は編集を待たせず、背景での読込の前後に世代と権限を確認する。

WorkspaceWorkTest と ExternalWorkPaneTest が、再起動・権限変更・競合・取消・記録故障・画面からの確認と保存・却下を検証する。

## 拡張ポイント

共通状態と接続の状態機械へ認証・能力別の受付を足してから、HTTP API・MCP・Web の経路をサービスへ接続する。
設定画面は希望値の更新を LocalConnections.configure に集め、状態の表示と停止完了の確認に StateFlow を使う。
Web の業務通信と外部向け API の有効化は分け、同じ app-core の操作窓口を使う。
SDK 内蔵の Origin 検査はホスト名の比較なので、機能を公開するときは scheme・port も照合する受付側の検査を追加する。
SDK の既定保護だけでブラウザの認証・CSRF 対策が完成したとは扱わない。
