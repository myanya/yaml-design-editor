# UI 操作規則

入力・フォーカス・補助表示について、画面をまたいで守る操作の意味と適用範囲を定める。
部品と接続方法は [ui.md](ui.md)、利用者向けの説明は [manual/README.md](../manual/README.md)、試し方は [UX-SCENARIOS.md](../UX-SCENARIOS.md) に置く。
規則を追加・拡張する手順は [CONVENTIONS.md「UXフィードバック運用」](../CONVENTIONS.md) に従う。

## フォーム入力からの退出

### 目的と範囲

キーボードだけで入力を終えられ、意図しない内容の消失や保存を起こさない。
対象は文書フォーム・文書情報・汎用フォーム・表内セル・埋め込みフォーム・スキーマ設計のテキスト入力。
文字・複数行・数値・日付・ID・参照・ファイルパスに共通で、チェックボックスやボタンの操作は含めない。

### 値と表示

- 修飾キーなしの Esc で入力フォーカスを外し、入力カーソルとフォーカス枠を消す。
- 値は通常のフォーカス離脱と同じ状態で保持する。空欄・不正値・改行も保持し、エラーを理由に退出を拒まない。
- 表示形式のある値は非フォーカス時の表示へ戻す。表示の切替だけで値を書き直さない。
- 保存・取消・追加・改名の適用を暗黙に行わない。別の確定操作を持つ欄では、入力途中の文字列だけを保持する。
- フォーカスの変化は dirty や文書の Undo 履歴を増やさない。値の反映経路は [editing-history.md「編集の経路」](editing-history.md) に従う。

### Esc の優先関係

入力欄が受ける一押しで扱うのは一層だけとし、候補を閉じた後も押し続けている間はフォーカス解除へ進めない。

| 状態 | 扱い |
|---|---|
| IME の変換中 | IME に渡し、フォーム側では候補の閉鎖もフォーカス解除も行わない |
| 入力欄にフォーカスを残す候補が開いている | 候補だけを閉じて入力欄へフォーカスを戻す |
| 日付・時刻ピッカーなど自身がフォーカスを持つ補助画面 | 補助画面の既存の閉じ方を優先する |
| 上記がなく入力欄にフォーカスがある | フォーカスだけを外す |

変換を終了した同じ Esc を、続けてフォーカス解除へ使わない。
入力欄ではキーを離して改めて押したときに、残っている層の処理へ進む。
ピッカーで既に反映した値は保持し、未適用の選択はピッカー自身の確定・取消規則に従う。

### 例外

ソース本文と検索・置換・行移動、一般の検索欄、確認・追加・改名ダイアログは、それぞれの既存の Esc 操作を持つ。
共通入力部品を使うだけではフォーカス解除を有効にしない。
フォームを再利用する操作パネルの値入力は対象だが、パネル全体の閉鎖・適用とは別の操作として扱う。

### 検証

`TextFieldEscapeTest` で変換終了のタイミング・候補の閉鎖・キーリピート・対象外・フォーカス移動を検査する。
実際の IME・ポップアップ・値の保持・表示形式・保存と Undo の関係は、UX シナリオの「フォーム入力の Esc」で確かめる。
この規則は UI の操作状態だけを扱い、Core Calculus の値・検証・変更演算や YAML 語彙は追加しない。

## 項目説明の予告と全文

### 目的と範囲

項目の意味を確認しながら入力を続けられ、余白を通っただけで大きな説明が出ない。
対象は編集・閲覧フォームの `FieldHelp` による項目説明。ツールバーの操作名の補足とは表示内容を分ける。

### 反応と表示

- ホバー判定は項目名と説明ボタンに限る。項目名の周囲に 2dp の余裕を持たせ、説明文・入力欄までの空白・AI ボタンは含めない。
- 500ms のホバーで短い予告を表示する。入力の焦点を奪わず、重複する見出しや閉じるボタンを置かない。
- 予告は内容に合わせた幅（上限 320dp）・本文高さ上限 84dp・余白 8dp とし、省略時は全文への案内を添える。
- 項目名と説明ボタンの近くに配置し、説明ボタンが折り返しても覆わない。画面端では画面内へ寄せる。
- 説明ボタンのクリック、または Tab で選択して Enter／Space を押すと全文を固定する。固定表示ではスクロールとリンク操作ができる。
- 固定表示は閉じるボタン・外側クリック・Esc で閉じる。説明の開閉は文書を変更せず、画面の長期的な覚えにも含めない。

### 検証

`FieldHelpPositionTest` で画面端の位置調整を検査し、UX シナリオで余白の通過・短文と長文・折り返し・閲覧専用・テーマを確かめる。

## 選択一覧の現在値

### 目的と範囲

一覧を開いたまま、確定済みの値とこれから選ぼうとしている候補を区別できるようにする。
対象はフォームの列挙値・ID・参照・文書参照、スキーマ設定、一覧のフィルター、ビュー・フロー・アクティビティ・操作対象・編集画面・ファイル表示指定の選択。
削除・追加・ジャンプなど、現在値を持たない操作メニューには選択印を付けない。

### 表示と判定

- 現在値の行は末尾のチェックと背景色で示す。ホバーやキーボードの移動先を、確定済みの選択として扱わない。
- 判定には保存値・ID・設定値を使う。表示名が同じ候補でも、別の値なら選択印を付けない。
- 未選択行にもチェックと同じ幅を確保し、文字位置を揃える。支援技術向けにも selected を設定する。
- 「未設定」「すべて」のような状態も、候補として存在する場合は同じ方法で示す。現在値が候補にない場合は、代わりの候補を勝手に選択表示しない。
- ファイル表示指定は実際の表示方式と区別し、そのファイルに設定されている値を示す。

### 部品と検証

行は `ChoiceMenuItem` を共用し、呼び出し元が現在値との一致を渡す。表示だけでは値の書込・保存・履歴追加を行わない。
UX シナリオの「選択一覧の現在値」で、開閉・再選択・未設定・同名異値・テーマ・ホバーとの区別を確認する。
一覧の高さや説明の省略、検索の方式は、各選択部品の現行の動作に従う。

## 規則の拡張

新しい対象へ適用するときは、同じ操作名だけで判断せず、値が反映される時点・IME・補助画面・保存・取消との関係を確認する。
適用範囲・例外・共通部品・確認方法を一緒に更新し、未実装の範囲を共通対応済みと記載しない。
理由のある例外はその場の実装だけに埋めず、この文書の該当する規則から辿れるようにする。
