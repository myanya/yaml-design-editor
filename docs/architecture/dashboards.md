# ダッシュボード

## 概要

業務の状況から対象を選び、詳細と操作へ進む常設画面。`kind: dashboard` をビューの定義フォルダに置く。
原本はYAML文書で、ダッシュボードは既存グリッドの行・原本座標・アクションの参照を合成する。
画面合成をスキーマへ追加せず、操作の計画と適用は既存経路へ委譲する。
独立したDASHBOARDスペースをレール最上部に置き、定義のあるワークスペースの開始画面とする。

## 部品

| 部品 | 責務 |
|---|---|
| `VirtualDashboardDef`・`DashboardSection` | 区画とビュー・操作の参照、タイルの並べ方（`placement`）と群（`group`。`sectionGroups()` が無名の群を先頭に、名前のある群を最初に現れた順に分ける） |
| `DashboardViews` | 既存の行と条件の評価を合成し、選択された行と保留理由を返す。チャートの区画は元の表を解決して `ChartViews.resolve` の数を `DashboardSectionResult.chart` に持つ |
| `ViewDefinitions` | 定義のパース、区画ID・参照先・操作の点検 |
| `core/Dashboards` | 同じ索引・原本の読み手・基準日を渡し、CLIとread_viewへ開示 |
| `DashboardPane` | 件数から区画を選び、一覧から詳細を表示。タイルは群ごとに見出しを付けて横に折り返すか、左の縦一覧に並べる |
| `ResolvedViewGrid`・`EntityPage` | 既存の表・原本編集・対象付きアクションの共有 |

## 流れ

1. 区画の `view` を一意なgrid・matrix・chartへ解決する。chartなら元の表の行を解決して数にし（件数＝横軸の項目の数・filter は不可）、画面は `ChartCard` を描く。
2. 同じビューの行は一度だけ解決する。セル・原本の読み取りは同じオーバーレイ索引とloaderを使う。
3. `filter` があれば、行のエンティティを起点に `SemanticRules.evaluate` で判定する。
4. 充足した行を一覧へ渡す。同じ行から件数を導出し、保留と値不足は理由付きの別の一覧へ渡す。
5. 行キーの選択から独立した対象IDを場所として開き、既存エンティティページを業務用の表示で使う。
   条件から外れても詳細を維持し、対象が削除された場合は不存在を表示する。
6. 操作は `AppState.startAction` から入力・差分確認・適用へ進む。フォームは未保存編集、操作は確認後に適用・保存する。
   ダッシュボードのCtrl+Sは既存のsaveAllへ接続する。

## 規律

- Core Calculus上は既存ビューのQuery／Expression、条件のPredicate、件数のAggregate、画面のTermの射影。
  変更は既存アクションのRewriteからTransactionへ渡す。新しい評価器・Construct・書込経路を持たない。
- 条件は `ActionRequire` のパラメータ付き検査宣言を共有する。`$today` だけを基準日の文字列に差し込む。
  日付の比較は既存の `check` と型の規則に委譲する。評価器内で時計を読まない。
- 基準日は全区画共通。本日表示は画面が定期的に日付変更を検知し、指定日は `ScreenMemory` に覚える。
- 判定の `NOT_IN_SCOPE` は対象外、`NO_VALUE` と保留は判定できない対象として開示する。
  whereは対象範囲の定義なので、値がない場合の扱いをexistsや個票未作成の区画で明示する。
- 件数は原本出現を持つ行の数。クエリ行は束縛行を数え、matrixの合計行は数えない。
  matrixへのfilterは合計との不一致を防ぐため拒否する。埋め込みの循環を許さない。
- 解決失敗とゼロ件を区別する。CLIでは失敗した区画のcountはnull、画面では理由を表示する。
- 場所は `NavLocation` のダッシュボードIDと対象ID。区画・行・基準日・分割・スクロールは `ScreenMemory` が持つ。
- 区画の並べ方（横・縦・auto）と群は定義が決め、群の畳みは `ScreenMemory` が持つ。auto は画面が一覧の幅から折り返しの段数を見積もり、3段以上なら縦にする。分割中は auto を横に決め、vertical は一覧を狭める（表を潰さない）。
  見積もりは画面の都合で、定義・索引・CLIの結果に置かない。
- 全幅の詳細を既定とし、任意の分割は一覧4:詳細6。狭幅では全幅へ切り替える。背後の文書用インスペクタは出さない。
- 対象へのリンクは `openDashboardEntity` へ統一し、参照・被参照も同じスペースでたどる。
  原本への遷移は明示操作に限る。業務用の詳細はタイトル・項目・操作を中心にし、出現座標やスキーマ情報を通常表示しない。
- 開始時は一意なdefault指定を優先し、未指定や重複時は定義ファイル名順の一意なIDを使う。重複指定は診断する。
  再読込では作業中の場所を変えない。入口選択と遷移はUI状態であり、Calculusの演算を追加しない。
- 対象の操作はエンティティページ、主な操作は対象を持たないアクションへ接続する。
  閲覧専用でも操作は利用でき、入力・前提・競合・確認の有効期間は既存規則に従う。
- 区画のviewはメタスキーマのref型で、IDの改名・被参照を既存機構で扱う。
  filter内のパスや固定値、actions内の文字は自動改名せず、リファクタリングの言及として警告する。

## 拡張ポイント

- カテゴリ等の共通入力は、必要な実例に合わせてパラメータの宣言と既存の入力部品を接続する。
- 描画部品を増やす場合も、選択結果と原本への到達可能性を共有する。
- 業務固有の状態遷移や検証規則はワークスペースの定義へ置く。
