# スキーマ設計画面

スキーマ文書を開き、「設計」を選びます。定義の書式は [スキーマ仕様](schema.md) を参照してください。

左の「構成」に基本設定・ルート・名前付き定義・操作や検査などの追加区画をまとめ、右で選択対象を編集します。
上部の方式アイコンで、[通常文書と共通の三つの表示方式](README.md#フォームの表示方式)を選べます。全体表示では各区画を順に並べます。

- **構成**: ルートからの構造を一覧で見渡し、行を選ぶとその項目だけの設定を編集します。ラベル・キー・型・必須を一覧で確認できます。
- **ルート自身の設定**: 一覧の「ルート」を選んで編集します。object の項目だけでなく、array の要素、map の値、enum の条件付き項目も同じ一覧で辿れます。
- **追加・移動・削除**: 親を選んで「追加」。項目を選んで上下矢印で移動、ゴミ箱で定義を削除します。削除と子定義を失う型変更は確認後に適用します。
- **名前付き定義**: 構成から定義を選び、右の詳細入力で編集します。見出しの「＋ 追加」で新しい定義を作れます。参照先の内容は一覧へ展開せず、宣言した構造だけを表示します。
- **基本設定**: ID・名前・説明・適用パターンを編集し、フェーズ・カバレッジ・エンティティの設定は必要な区画だけを開きます。
- **操作・検査・文書作成など**: 構成一覧で「操作（横断）」「検査」「新しい文書の置き場所」などを選びます。メタスキーマの項目を共通フォームで表示し、既存の未知キーも隠しません。
- **操作の入力**: 「操作（横断）」で操作を追加し、ID・表示名・対象・入力項目を設定します。入力項目には通常のフィールドと同じ型・必須・選択肢・初期値を使えます。
- **追加区画の子項目**: 操作の表示名（未設定ならID）を展開すると、入力項目・前提条件・処理手順の子まで辿れます。「選択項目」方式では選んだ箇所を編集し、「全体とツリー連動」では畳みを開いて該当箇所へ移動します。
- **項目の追加設定**: 「追加設定・操作・検査」で、型の操作・配列の採番・ファイルの拡張子制約・保有関係・値の式などを編集します。属性付き参照の子項目は構成一覧から追加します。
- **採番**: 配列の「追加設定・操作・検査 → 配列の操作 → 追加の決まり → ID採番」で、ID項目のパス・接頭辞・桁数を設定します。

項目の「説明・表示・必須条件」は通常フォームと同じ見出し・縦線の折りたたみ式です。入力欄の開始位置を揃え、狭い領域ではラベルの下へ配置します。
区画・選択・開閉は文書ごとに保持します。
追加区画の配列を並べ替えると、選択は同じ要素へ追随します。Undo時は一意な操作ID・入力キーで追随し、選択対象を削除した場合は残る親へ戻ります。
編集領域が狭い場合は「構成を開く」で一覧へ切り替え、項目を選ぶと詳細へ戻ります。閲覧専用では選択・開閉は使え、入力・追加・削除などの編集は無効です。
「設計／ソース／差分」は上部の一段で切り替えます。右端に「プレビュー」と表示メニュー（⋯）があり、「適用対象」「汎用フォーム」もそこから開けます。
項目のタイトルと追加・移動・削除は詳細の先頭一行にまとめています。YAML パスはタイトルにカーソルを合わせて確認できます。
「文書を定義順へ整列」は構成内の「スキーマ操作」にあります。「全体のみ」ではフォーム先頭にスキーマ操作と確認メッセージを表示します。


## 条件と処理手順の入力

自由な値の欄には、種類の選択と「値・構造を選ぶ」があります。
「手順」では設定・追加・削除・文書作成・型の操作の呼出し・繰り返し、「条件」「判定」では比較と否定・いずれかを選べます。
「ひな型」は値のコピー・入力値・文字列の組立てなど、「値の式」は項目の読み出しや集計の入力を助けます。

- 選択すると編集用の例が入り、項目名・対象のパス・値を自分のモデルに合わせて編集します。例に入っている `todo`・`status` などは自動解決された値ではありません。
- 「設定項目を追加」で対象の文書や束縛名・実行条件などを足します。任意の項目名も追加でき、既存の別記法や未知のキーを保持できます。
- 配列は要素を追加・上下移動・削除できます。マップは項目を追加・削除でき、各値の形も選択できます。
- 内容のある値を別の形に置き換えるときと、削除するときは確認が出ます。変更は通常の Undo/Redo と保存・差分に反映されます。
- 任意設定を外す場合は、その設定の「削除」を使います。対象設定を削除した操作はワークスペースの操作になります。
- 選べる入力例は記述の補助です。束縛名・前提の成立・型の操作の範囲などは既存の定義検査が確認します。「確認 n 件」で問題を確認してから保存します。

複雑な組合せも項目・配列として編集できますが、利用する語彙の意味は [操作の定義](actions.md) と [スキーマ仕様](schema.md) を参照してください。

## 検証とプレビュー

構成の「確認 n 件」から検証メッセージを開けます。スキーマ設計画面には次の確認機能があります。

- **メタスキーマ検証**: 必須情報、フィールドキー重複、arrayの要素定義、enumの選択肢、`cases` の整合（enum型のみ・値の存在・キー衝突）、未解決の `$ref` を保存前に検出
- **プレビュー**: スキーマからサンプルYAMLを生成し、実際のフォームまたはYAMLとして確認（フォームの方式アイコンは設計と同じファイル指定を使用）
- **サンプル生成**: 生成したYAMLをクリップボードへコピー
- **適用対象**: `match` に一致するワークスペース内のファイルを一覧表示し、他スキーマとの競合も表示
- **フェーズ・カバレッジ**: スキーマ全体設定の `phases`（申告キー・フェーズ順序）と `coverage`（参照ベース／出現ベースの切替・重大度・判定開始フェーズ）も構造化UIで編集できます（後述のリファレンス参照）

スキーマファイルを保存すると、メタスキーマ検証結果は通常の右側「検証」パネルにも表示されます。
