# スキーマ設計画面

スキーマ文書を開き、「スキーマ設計 → 設計」を選びます。定義の書式は [スキーマ仕様](schema.md) を参照してください。

設計は「項目構成」「名前付き定義」「基本設定」に分かれています。

- **項目構成**: ルートからの構造を一覧で見渡し、行を選ぶとその項目だけの設定を編集します。ラベル・キー・型・必須を一覧で確認できます。
- **ルート自身の設定**: 一覧の「ルート」を選んで編集します。object の項目だけでなく、array の要素、map の値、enum の条件付き項目も同じ一覧で辿れます。
- **追加・移動・削除**: 親を選んで「項目を追加」。項目を選んで上下矢印で移動、ゴミ箱で定義を削除します。削除と子定義を失う型変更は確認後に適用します。
- **名前付き定義**: 定義を切り替え、同じ構成一覧と詳細入力で編集します。参照先の内容は一覧へ展開せず、宣言した構造だけを表示します。
- **基本設定**: ID・名前・説明・適用パターンを編集し、フェーズ・カバレッジ・エンティティの設定は必要な区画だけを開きます。

項目の「説明・表示・必須条件」は折りたたみ式です。区画・選択・開閉は文書ごとに保持します。
編集領域が狭い場合は、構成一覧を上、詳細を下に並べます。閲覧専用では選択・開閉は使え、入力・追加・削除などの編集は無効です。
「フォーム」タブでは、引き続きメタスキーマによる汎用フォームを利用できます。


## 検証とプレビュー

スキーマ設計画面には次の確認機能があります。

- **メタスキーマ検証**: 必須情報、フィールドキー重複、arrayの要素定義、enumの選択肢、`cases` の整合（enum型のみ・値の存在・キー衝突）、未解決の `$ref` を保存前に検出
- **プレビュー**: スキーマからサンプルYAMLを生成し、実際のフォームまたはYAMLとして確認
- **サンプル生成**: 生成したYAMLをクリップボードへコピー
- **適用対象**: `match` に一致するワークスペース内のファイルを一覧表示し、他スキーマとの競合も表示
- **フェーズ・カバレッジ**: スキーマ全体設定の `phases`（申告キー・フェーズ順序）と `coverage`（参照ベース／出現ベースの切替・重大度・判定開始フェーズ）も構造化UIで編集できます（後述のリファレンス参照）

スキーマファイルを保存すると、メタスキーマ検証結果は通常の右側「検証」パネルにも表示されます。
