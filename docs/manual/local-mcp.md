# 外部 AI からの MCP 接続

同じ PC の外部 AI エージェントから、保存済みの参照、作業コピーの編集・検証・提案・直接確定、定義済み操作を利用できます。
YDE 内蔵の AI 設定や LLM の契約は使いません。外部 AI 側がツールを選び、YDE が権限・検証・保存を管理します。

## 接続の準備

1. デスクトップで対象のワークスペースを開き、「設定 → 接続と常駐」で **MCP を ON** にします。API は OFF のままで利用できます。
2. 「接続者を追加」で **MCP** を選び、権限を設定します。参照だけなら全体閲覧、変更するなら変更提案・直接確定・業務操作を必要に応じて選びます。業務操作は操作名も選びます。
3. その接続者の行からトークンを発行し、外部 AI アプリの MCP 接続設定へ入力します。

| 設定 | 値 |
|---|---|
| 接続方式 | Streamable HTTP |
| URL | `http://127.0.0.1:18765/mcp`（ポートを変更した場合は設定画面の表示に合わせる） |
| 認証ヘッダー | `Authorization: Bearer 発行したMCP用トークン` |

Streamable HTTP と認証ヘッダーの指定に対応したクライアントを使ってください。
API 用のトークンは使えません。トークンを URL のクエリへ入れないでください。
stdio 接続や、YDE の自動起動は提供しません。アプリが画面非表示で常駐中でも、MCP が稼働中なら利用できます。

接続後は、外部 AI に「このワークスペースの保存済み文書を一覧にしてください。変更は行わないでください」と依頼して参照を確認できます。
登録した権限で使えるツールだけが一覧に現れます。権限を変更した場合はトークンを再発行し、MCP 接続を再初期化してください。

## 参照ツール

| ツール | 主な引数・結果 |
|---|---|
| `get_workspace` | 接続したワークスペースの状態 |
| `list_documents` | 文書一覧とハッシュ |
| `read_document` | `document`: 相対パス。保存済みの `text` と `hash` |
| `search` | `q`: 検索語 |
| `read_entity` | `id`: エンティティ ID |
| `list_views` | ビュー一覧 |
| `read_view` | `id`: ビュー ID、`date`: 任意の基準日 |
| `validate_workspace` | `document`: 任意の対象文書。検証の指摘・保留 |
| `list_actions` | この接続者に許可された操作名・入力・対象 |

すべての参照は保存済みが対象です。デスクトップの未保存編集や、外部作業内の編集は含みません。
参照結果には `workspaceId`・`epoch`・`revision`・`data` が含まれます。
一覧系は `offset` と `limit` に対応し、`nextOffset` がある場合は返された `revision` とともに次のページへ渡します。
検証の指摘や保留がないページだけを見て、ワークスペース全体が正しいと判断しないでください。
詳細な返却内容は [読取 API](local-connections.md#api-の読み取り) と共通です。

## 提案と直接確定

作業開始時の `mode` で選びます。両方の権限を付与していても、開始後に方式を変更することはできません。

| 方式 | 外部 AI が呼ぶ順番 | 保存のタイミング |
|---|---|---|
| `proposal` | begin_work → edit_work → validate_work → submit_work | デスクトップの受信箱で確認・承認したとき |
| `direct` | begin_work → edit_work → validate_work → plan_work → commit_work | 計画 ID を指定して確定したとき |

外部 AI への依頼例は「a.yaml の title を変更し、proposal の作業として検証して提出してください」または
「a.yaml の title を変更し、direct の作業として差分と検証結果を確認してから確定してください」です。
文書・項目・値は実際のワークスペースに合わせて指定してください。
外部 AI アプリ側のツール実行確認は、そのアプリの設定に従います。YDE のデスクトップ承認とは別です。

開始の引数は次の形です。

```json
{"title":"タイトル変更","mode":"direct"}
```

返った `data.id` を `workId` として、`edit_work` へ変更セットを送ります。

```json
{
  "workId": "開始時の作業ID",
  "changes": [
    {
      "file": "a.yaml",
      "ops": [{"op":"set","path":"title","value":"更新後のタイトル"}]
    }
  ]
}
```

パッチの形式は [API による変更](local-api-changes.md) と共通です。必要に応じて `read_document` の `hash` を文書の `base` に指定できます。
`validate_work` は `{"workId":"作業ID"}` で呼び、作業コピーの差分と指摘を確認します。
`plan_work` は計画 ID・期限・差分・`canCommit` を返します。再編集・再検証をすると、古い計画は無効になります。

直接確定の `commit_work` は `{"workId":"作業ID","planId":"計画ID"}`、提案の `submit_work` は `{"workId":"作業ID"}` で呼びます。
`work_result` で状態・結果を照会し、不要な未確定作業は `discard_work` で破棄できます。
提案の承認・却下、記録の復旧、権限変更、Undo/Redo のツールは公開しません。

変更対象と影響先の検証エラー、対象の未保存編集、古い計画、権限の変更は確定を拒否します。
外部の確定はデスクトップの Undo に追加せず、関係する文書の古い履歴を適用不可にします。無関係な履歴を飛び越えることはできません。
詳しい状態と履歴の扱いは [API による変更](local-api-changes.md) と同じです。

## 定義済み操作

`list_actions` で操作を確認し、`plan_action` に `name`、必要な `target` と `params` を渡します。
計画の差分・検証結果を確認して、`commit_action` に `planId` と一意な `requestId` を指定します。
`action_result` へ同じ `requestId` を渡すと結果を照会できます。
操作名の追加許可はデスクトップで行い、AI が自分の権限を拡張することはできません。

## 結果・停止・再接続

ツールの結果は構造化された JSON と、同じ内容のテキストで返ります。
検証不合格・確定不可・保存失敗・結果不明などは `isError: true` と結果を返します。
`validate_workspace` は読取結果として指摘・保留を返すため、`isError` だけでは文書が正しいかを判定できません。
提案提出の `awaiting_approval` は受付済みで、保存済みではありません。

MCP の OFF・トークン失効はセッションと実行中の処理を終了させます。開始した保存は結果の記録まで終えます。
通信が切れた場合、保存されていない保証にはなりません。同じ `workId` / `requestId` で結果を照会し、再送には同じ計画 ID も使ってください。
作業 ID と MCP の通信セッション ID は別です。通信をつなぎ直すだけでは作業を作り直す必要はありません。
初期化の応答を受け取った後に HTTP 接続が閉じても、それだけで MCP セッションは終了しません。同じ資格情報とセッション ID で続けられます。
未提出の作業コピーと計画はメモリ内にあり、アプリの再起動・ワークスペース切替で失われます。提出済みと確定済みの結果は記録に残ります。

ツール実行は原則 30 秒、引数は 2 MiB、結果全体は 4 MiB までです。保存開始後は結果確定を待ちます。
MCP セッションは操作のない状態で約 15 分が経過すると終了し、再初期化が必要になります。
同時セッションは待受全体で 64、同じ資格情報で 8 までです。クライアント終了時は可能ならセッションの終了要求も送ってください。
HTTP の受付・MCP のセッションとツール実行は、共通の同時要求上限にも含まれます。

接続し直すときは、エラーの種類に合わせて次の操作を行います。

| 状態 | 対処 |
|---|---|
| MCP は稼働中だがセッションが 404 | 古いセッション ID を外し、同じトークンで初期化からやり直す |
| 401（期限切れ・失効） | 同じ接続者のトークンを再発行し、新しい接続を作る |
| MCP を OFF にした後の 404 | 設定で MCP を ON に戻し、トークンを再発行して接続する |
| 429（接続数・同時要求の上限） | 不要なセッションを終了するか期限切れを待つ。トークン再発行でも、その接続者の旧セッションは終了する |

クライアントによっては接続を閉じてもセッション終了の DELETE を送らず、約 15 分間枠を使い続けます。
短い接続を繰り返す自作クライアントでは、接続を再利用するか DELETE も送ってください。
再接続後は、以前の `workId` / `requestId` で結果を確認してから続きを行います。資格情報を再発行しても同じ接続者の作業を照会できます。
ブラウザから YDE と異なる Origin で直接接続する方式には対応しません。認証ヘッダーを指定できるデスクトップクライアントや Inspector の CLI を使用してください。
