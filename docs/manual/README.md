# 利用者マニュアル

Kotlin + Compose for Desktop + Material 3 製の**スキーマ駆動・汎用 YAML エディタ**。
YAML で設計項目（要求・設計・課題など）を管理するためのツールです。

- 外部のスキーマ定義（`_schemas/*.yaml`）に沿って、YAML ファイルごとに適切なフォームビューを自動生成
- スキーマがないファイルも**汎用ビュー**（再帰的なツリーエディタ）で編集可能
- ワークスペース内の **ID を横断的に索引化**し、参照（ref）のリンクジャンプ・補完・未解決検出・バックリンク表示に対応
- フォーム／ソース／差分の3モード編集、スキーマ検証、ID検索
- 外部変更の自動検出、ファイル／ディレクトリ操作、リサイズ可能な左右ペイン
- `_schemas` 専用のスキーマ設計画面と、`definitions` / `$ref` による再帰定義
- **スキーマ工学**: 既存文書からの**スキーマ推測**、スキーマ文書自体を検証・フォーム編集する**メタスキーマ**、テーブル定義書などから検証スキーマを導出する**派生スキーマ**（`derive`）
- Undo/Redo、保存ショートカット、未保存終了確認、復元されるペインレイアウト
- ライト／ダークを切り替えられるMaterial 3テーマ（選択状態は次回起動時に復元）
- ワークスペース一覧・絞り込み・一括編集、**エンティティページ**（全出現のアスペクト合成・関係パネル・改名／統合／削除）、**グラフレンズ**（起点近傍・型／関係の絞り込み）、差分表示、コマンドパレット、最近開いたファイル
- **4スペースUI**: 左端のレールで「編集・台帳・実行・設計」を切替。人間の判断待ち（承認・質問・競合）は実行スペースの**受信箱**に集約され、右ペインは検証・関係・出現をまとめた**IDインスペクタ**
- 参照への**関係種別**（`relation`）付与と、「全要求は設計から参照される」等の**カバレッジルール**によるトレーサビリティ検証
- **AIによる作成支援**（OpenAI / Anthropic 連携）: フィールド単位・配列への候補追加・文書全体のたたき台生成。スキーマ準拠の構造化出力＋適用前プレビューと検証
- **エージェントによるアクティビティ実行**: `_agents`／`_activities` に定義した仕事（レビュー・改名・起票など）を、エージェントが探索→複数文書編集→自己検証のループで実行。提案は変更セットとして人間が部分採用
- **自動実行**: トリガ（ファイル更新・スケジュール・検証エラー）による自動起動、連鎖・リトライ、条件付き自動承認（適用前バックアップと巻き戻し付き）
- **自己改善**: 実行記録のメトリクス集計、評価セット（`_evals`）によるアクティビティの回帰評価とA/B比較、メタアクティビティによる定義改善の提案
- **skill（フォーマット適合）**: Excel / CSV / JSON / Markdown の宣言型インポート・エクスポート（YAMLが常に原本）、ユースケース別テンプレートパック（`init`）
- **ヘッドレスCLI**: GUIなしでカタログ・骨子・検索・部分パッチ（変更セット）・検証・エージェント実行・評価・入出力変換（エージェント連携の基盤）

主題ごとに 1 ファイルに分かれています。開発者向けの文書は [docs/README.md](../README.md) を参照してください。

|---|---|
| [README.md](README.md)（本書） | ビルドと起動・画面構成・ワークスペースの構成・外部変更と競合・テーマ |

## ビルドと起動

要件: **JDK 17以上**。Gradle Wrapper（Gradle 9.3.0）を同梱しています。

```bash
cd yaml-design-editor
./gradlew run                                  # スタート画面から履歴・選択でワークスペースを開く
./gradlew run --args="/path/to/your/workspace" # 任意のワークスペースを指定して起動
```

配布物の作成:

```bash
./gradlew packageDistributionForCurrentOS # dmg / msi / deb
```

起動引数を省略すると**スタート画面**が表示され、最近開いたワークスペースの履歴（最大10件。アプリグローバルに保存）から選ぶか、「ワークスペースを開く…」でディレクトリを選択します（`samples/sample-workspace/` があれば、それを開くボタンも表示されます）。開いた後もツールバーの「開く」やコマンドパレット（`Ctrl+K`）の「ワークスペースを切替」からいつでも切り替えられます（未保存の変更があれば確認ダイアログを挟みます）。

## 画面構成

画面は左端の**アクティビティレール**で切り替える4つの**スペース**からなります。

```
┌──┬─────────────────────────────────────────────────────────────────────┐
│  │ 開く 再読込 ← → 履歴 │            検索・コマンド (Ctrl+K) 閲覧 Theme ◀▶ │
│編├─────────────┬──────────────────────────────────┬──────────────────────┤
│集│ ファイルツリー │ ファイル名 / スキーマ  Undo Redo 保存 すべて保存 │ 検証│関係│出現 │
│  │ 新規・改名    ├──────────────────────────────────┤ （IDインスペクタ）    │
│台│ 削除・展開    │ フォーム │ ソース │ 差分             │                      │
│帳│ ● 未保存      │ 構造化フォーム / YAML / 比較表示     │                      │
│  │             │                                  │                      │
│実│                                                                       │
│行│  台帳スペース: 一覧 │ ビュー │ レンズ │ エンティティ （ワークスペースの俯瞰） │
│  │  実行スペース: 受信箱 │ 手動実行 │ 自動化 │ 計測・評価 （エージェント運用）    │
│設│  設計スペース: スキーマ・ビュー・エージェント・アクティビティ・評価・連携の定義 │
│計├───────────────────────────────────────────────────────────────────────┤
│  │ ステータスバー: 状態 ／ 検証サマリ ／ 実行状態 ／ 判断待ちバッジ            │
└──┴─────────────────────────────────────────────────────────────────────┘
```

| スペース | 役割 |
|---|---|
| **編集** | ファイルツリー＋フォーム／ソース／差分で文書を1件ずつ編集する（従来のエディタ画面） |
| **台帳** | ワークスペース全体を俯瞰する。「一覧」「ビュー（ビューグリッド）」「レンズ（グラフレンズ）」「エンティティ（エンティティページ）」のタブ（[views.md](views.md)） |
| **実行** | エージェント運用。**受信箱**（承認待ち・質問・競合）・手動実行・自動化・計測/評価のタブ（[ai.md](ai.md)）で、定義が空でも常時表示され、`_agents`／`_activities` が無い間は空状態の案内が出る |
| **設計** | スキーマ・ビュー・エージェント・アクティビティ・評価・連携（skill）の定義を種類別に見渡し、新規作成・スキーマ推測の入口を提供する（[schema.md](schema.md)・[ai.md](ai.md)） |

- ファイル名横の `●` は未保存の編集を表します。ファイルを切り替えても編集内容はメモリ上に保持されます（「保存」「すべて保存」で書き出し）。
- 「フォーム」タブが構造化編集、「ソース」タブがテキスト編集です。ソースの編集は**入力のたびに解析され、成功時だけ内部のYAMLツリーへ自動反映**されます（フォームと相互に反映されます）。文書ヘッダーの「保存」はそのツリーをファイルへ書き出します。解析できない状態の間はツリー＝最後に解析できた状態が正で、保存もそれを書きます（エラーが画面に表示され、ソースタブの `Ctrl+S` は保存を拒否します）。
- `Ctrl+S` で現在のファイルを保存、`Ctrl+Shift+S` ですべて保存、`Ctrl+Z` / `Ctrl+Y` で編集を元に戻す／やり直すことができます。
- 右ペインは**IDインスペクタ**です。「検証」（エラー・警告・フェーズ進捗）、「関係」（この文書からの参照と被参照）、「出現」（文書ルートIDと同じ論理IDの全出現・カバレッジ充足。エンティティページへ展開）をタブで切り替えます。object、array、mapはフォーム内で折りたためます（既定ではルートから2階層までを展開し、より深い階層だけを折りたたみます。
編集モード・閲覧専用モードで共通で、モード切替後も展開状態は保たれます）。畳んだ状態のヘッダには要素の要約（object は「ID タイトル（n項目）」、array は「n件: 先頭要素の要約, …」。[ids.md](ids.md) の表示解決）が表示され、開かなくても中身を判断できます。
- **配列・map のテーブル表示**: スカラー項目中心の object 配列（例: テーブル定義書のカラム一覧）や、値が object の map（例: 環境定義の `dev` / `staging` / `production`）は、フォーム内で自動的に**表形式**（列ヘッダ＋1要素1行。
map は先頭にキー列）になります。適否は「列が2〜8個 かつ 要素の項目の過半がスカラー系」で自動判定され、スキーマの `display: table` / `display: list` で固定できます（[schema.md](schema.md)）。セルはその場で編集でき、長文・ネスト・enum 連動項目など列にならない項目は行頭の ▶ で開く展開フォームで編集します。
map のキー列は表では表示のみです（キーの追加は表の下の入力行、削除は行操作で行えます）。表が広いときは表の下の横スクロールバーで移動します。不適格な配列・map は従来どおり縦のリスト（各要素は畳み込み可）です。
- 参照ジャンプなどの移動は、実行・設計スペースにいても常に編集／台帳スペースへ着地します。スペースの切替自体も「戻る・進む」（`Alt+←` / `Alt+→`）の対象なので、ジャンプ後に戻れば元のスペースへ帰れます。
- **閲覧専用モード**: ツールバーの目のアイコンで切り替えます。入力欄がテキスト表示になり、追加・削除・AIボタンが消えて表示密度が上がります。参照ジャンプ・バックリンクは閲覧行為としてそのまま使えます。エンティティページの埋め込みフォームやビューグリッドにも同時に効き（操作メニューも非表示になります）、状態は次回起動時に復元されます。
- 左右ペインはドラッグでリサイズでき、開閉状態・幅・テーマ・閲覧専用モードは次回起動時に復元されます。
- ファイルペイン上部からYAML／ディレクトリの作成、名前変更、削除を実行できます。新規YAMLは配置先に適用されるスキーマから初期値を生成します。作成先は**ツリーで選択中の場所の配下**で、ダイアログに作成先パスが表示されます（「ワークスペース直下に作成する」への切替も可能。ツリーの空白をクリックすると選択が外れ、未選択時はルート直下が作成先になります）。名前の入力は Enter でも確定でき、同名ファイルが既にある等で作成できない場合は理由がダイアログ内に表示されます。
- ステータスバーの右側に、開いている文書の検証サマリ、実行中のアクティビティ、自動化の稼働状態、**判断待ちの件数**（クリックで受信箱へ）を常時表示します。
- ウィンドウ終了時とワークスペース切替時には未保存確認を表示します。

### 操作の役割

- **ライブ同期**（ソースタブ）: 入力のたびに解析し、成功時だけ内部YAMLツリーへ自動反映します。解析エラーの間は行・列つきのエラーが表示され、「編集を破棄」でツリーの状態に戻せます（エラーがなければ同じボタンが「整形」＝正規化テキストへの揃えになります）。
- **保存**（文書ヘッダー）: 内部YAMLツリーを現在のファイルへ書き込みます。コメント・キー順・引用符やフロー表記のスタイルは保持されます（詳細は「既知の制約」）。
- **ソース編集中の `Ctrl+S`**: 反映と保存を続けて実行します。
- **検索・置換**（ソースタブ）: 大文字小文字を無視した検索（件数表示）と「置換」「すべて置換」ができます。置換結果も自動で反映されます。
- **Tab キー**（ソースタブ）: フォーカス移動ではなくスペース2個を挿入します（YAMLはタブ文字を使えないため）。
- **構文ハイライト**（ソースタブ）: キー・文字列・数値・真偽値・コメント・`---` を色分け表示します。
- **Undo/Redo**: 履歴は**ワークスペース全体で1本**です（直前の変更が別のファイルのものなら、そのファイルが戻ります）。同じフィールドへの連続入力（1秒以内のタイプ）は1回の Undo でまとめて戻ります（フィールドを移る・時間を空ける・構造を変える操作が区切りになります）。
実行するとステータスバーに「元に戻しました: <変更の内容>」と**戻ったファイルへのリンク**が表示され、戻した結果が未保存（●）になった場合は「保存で確定します」と案内します（この通知は次の編集・保存・✕で消えます）。
ツールバーの Undo/Redo ボタンにマウスを載せると「次に何が戻るか」の予告が表示されます。**文書の新規作成**（新規 YAML・ビューからの詳細文書／新規行ファイル・検証指摘からの「詳細文書を作成」・スキーマ推測）も履歴に入り、`Ctrl+Z` で取り消せます——作成の取り消し／やり直しは**ファイルの有無までその場で反映**されます（内容の編集の Undo が未保存●に留まるのと違い、保存の操作は要りません）。
作成しても、それまでの Undo 履歴は失われません。
- **キー名の変更**（汎用ビュー）: キー名横の鉛筆アイコンから、順序と値を保ったまま改名できます。
- **複数ドキュメント（`---` 区切り）**: フォームでは先頭ドキュメントを編集し、後続ドキュメントは保持されて保存時にそのまま再出力されます。全ドキュメントを編集したい場合はソースタブを使います。

### ショートカット

| キー | 操作 |
|---|---|
| `Ctrl+S` | 現在の文書を保存。ソース編集中は反映後に保存 |
| `Ctrl+Shift+S` | ソースを反映後、未保存文書をすべて保存 |
| `Ctrl+Z` | 元に戻す |
| `Ctrl+Y` / `Ctrl+Shift+Z` | やり直す |
| `Ctrl+K` | 検索・コマンド（ID・ファイル・本文・コマンドの統合パレット） |
| `Alt+←` | 戻る（ジャンプ・ファイル切替の履歴） |
| `Alt+→` | 進む |

## ワークスペースの構成

任意のディレクトリを「ワークスペース」として開きます。

```
my-workspace/
├── _schemas/            # スキーマ定義（このディレクトリ名は固定）
│   ├── requirement.yaml
│   └── design-item.yaml
├── requirements/        # 以下は自由な構成。*.yaml / *.yml が対象
│   ├── req-001.yaml
│   └── req-002.yaml
├── designs/
│   └── dsn-001.yaml
└── notes/
    └── memo.yaml        # スキーマにマッチしない → 汎用ビュー
```

各 YAML ファイルには、`_schemas/` 内のスキーマのうち `match`（glob）がワークスペース相対パスに最初にマッチしたものが適用されます（ファイル名の昇順で評価）。どれにもマッチしなければ汎用ビューになります。

### `.yde` 構成（既存リポジトリとの共存・台帳範囲の宣言）

上記のレガシー構成（ルート直下の `_schemas` 等）に加えて、ツールの構成を隠しディレクトリ `.yde/` にまとめる**オプトイン構成**が使えます。既存のプロジェクトリポジトリ（他ツールのYAMLが混在する環境）へ後入れする場合はこちらを推奨します。

```
my-project/
├── .yde/                     # ツール構成（.git / .obsidian と同じ流儀）
│   ├── workspace.yaml        # ledger: 台帳ディレクトリの宣言
│   ├── schemas/              # 旧 _schemas（以下、アンダースコア無しの名前）
│   ├── views/  agents/  activities/  evals/  skills/  runs/
├── doc/                      # 台帳（ledger に宣言した範囲）
│   └── req-001.yaml
├── .github/workflows/        # 台帳外 → 索引・検証集計・エージェントの対象外
└── build/                    # 台帳外（エクスポート先などに自由に使える）
```

```yaml
# .yde/workspace.yaml
ledger: doc          # 文字列またはリスト（例: [doc, spec]）。未宣言なら全体が台帳
```

機能は2層に分かれます。**エディタ層**（ソース／スキーマフォーム編集・単文書検証など、1ファイルで完結する機能）は台帳外のYAMLにも効きます——スキーマの `match` は常にワークスペース相対で、台帳外にもマッチします。**台帳層**（ID索引・参照解決・カバレッジ・ビュー・エージェント・自動化・skill）は `ledger` 配下だけが対象です。台帳外の文書では未解決参照が情報レベルに降格され、ファイルツリーでは薄色・折りたたみで区別されます。

- `.yde/` が無いワークスペースは従来どおり動きます（設定不要）。
- レガシー構成からの移行は `./gradlew runCli -q --args="migrate <workspace> [--ledger doc]"`（予約ディレクトリの移動と構成ファイル作成のみ。スキーマ等の中身は書き換え不要）。
- `.git` などの隠しディレクトリは走査されません（`.yde` のみ例外）。


## 外部変更・競合・安全性

- ワークスペース内のYAMLをOSのファイル監視（WatchService）で監視します。監視を開始できない環境では約1秒間隔のポーリングに自動フォールバックします。
- 未編集のファイルが外部変更された場合は自動的に再読込します。
- 未保存文書が外部変更された場合は自動上書きせず、競合バナーを表示します。
- 競合時は「ディスク版を読み込む」または「編集内容を維持」を選択できます。
- 未保存文書を含む名前変更・削除・一括編集は拒否されます。
- ファイル削除は確認ダイアログを経由します。

## テーマ

Material 3ベースのライト／ダークテーマを搭載しています。深いティール、シアン、バイオレットをアクセントとし、ツールバー、ペイン、エディタ、入力欄、選択状態、警告色を共通トークンで管理しています。ツールバーのテーマアイコンから切り替えられ、選択は保存されます。
