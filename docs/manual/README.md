# 利用者マニュアル

Kotlin + Compose for Desktop + Material 3 製の**スキーマ駆動・汎用 YAML エディタ**。
YAML で設計項目（要求・設計・課題など）を管理するためのツールです。

- 外部のスキーマ定義（`_schemas/*.yaml`）に沿って、YAML ファイルごとに適切なフォームビューを自動生成
- スキーマがないファイルも**汎用ビュー**（再帰的なツリーエディタ）で編集可能
- ワークスペース内の **ID を横断的に索引化**し、参照（ref）のリンクジャンプ・補完・未解決検出・バックリンク表示に対応
- フォーム／ソース／差分の3モード編集、スキーマ検証、ID検索
- 外部変更の自動検出、ファイル／ディレクトリ操作、リサイズ可能な左右ペイン
- `_schemas` 専用のスキーマ設計画面と、`definitions` / `$ref` による再帰定義
- **スキーマ工学**: 既存文書からの**スキーマ推測**、スキーマ文書自体を検証・フォーム編集する**メタスキーマ**、テーブル定義書などから検証スキーマを導出する**派生スキーマ**（`derive`）
- Undo/Redo、保存ショートカット、未保存終了確認、復元されるペインレイアウト
- ライト／ダークを切り替えられるMaterial 3テーマ（選択状態は次回起動時に復元）
- ワークスペース一覧・絞り込み・一括編集、**エンティティページ**（全出現のアスペクト合成・関係パネル・改名／統合／削除）、**グラフレンズ**（起点近傍・型／関係の絞り込み）、差分表示、コマンドパレット、最近開いたファイル
- **4スペースUI**: 左端のレールで「編集・台帳・実行・設計」を切替。人間の判断待ち（承認・質問・競合）は実行スペースの**受信箱**に集約され、右ペインは検証・関係・出現・操作をまとめた**IDインスペクタ**
- 参照への**関係種別**（`relation`）付与と、「全要求は設計から参照される」等の**カバレッジルール**によるトレーサビリティ検証
- **AIによる作成支援**（OpenAI / Anthropic 連携）: フィールド単位・配列への候補追加・文書全体のたたき台生成。スキーマ準拠の構造化出力＋適用前プレビューと検証
- **エージェントによるアクティビティ実行**: `_agents`／`_activities` に定義した仕事（レビュー・改名・起票など）を、エージェントが探索→複数文書編集→自己検証のループで実行。提案は変更セットとして人間が部分採用
- **自動実行**: トリガ（ファイル更新・スケジュール・検証エラー）による自動起動、連鎖・リトライ、条件付き自動承認（適用前バックアップと巻き戻し付き）
- **自己改善**: 実行記録のメトリクス集計、評価セット（`_evals`）によるアクティビティの回帰評価とA/B比較、メタアクティビティによる定義改善の提案
- **skill（フォーマット適合）**: Excel / CSV / JSON / Markdown の宣言型インポート・エクスポート（YAMLが常に原本）、ユースケース別テンプレートパック（`init`）
- **操作**: スキーマに定義した「型の操作」（要素 1 つの中を変える）と「アクション」（複数の要素・文書にまたがる。受け取る値・前提・手）を名前で呼ぶ。結果は変更セットで、検証・競合・Undo はこれまでどおり（いまの入口は CLI）
- **ヘッドレスCLI**: GUIなしでカタログ・骨子・検索・部分パッチ（変更セット）・検証・エージェント実行・評価・入出力変換（エージェント連携の基盤）

主題ごとに 1 ファイルに分かれています。開発者向けの文書は [docs/README.md](../README.md) を参照してください。

## ビルドと起動

Windows ZIP 版は Java の追加インストール不要です。すべて展開して `yaml-design-editor.exe` を起動し、「ワークスペースを開く…」でフォルダを選びます。
同梱の `examples/todos` をアプリの外へコピーして試せます。更新時は終了して新版を別フォルダへ展開し、同じワークスペースを開いてください。
起動案内は ZIP 内の `README.txt`、配布物を作る手順は [Windows ZIP の配布](../releasing.md) にあります。以下はソースからビルドする場合の手順です。

要件: **JDK 21**（ビルドと実行に使います。無ければ Gradle が自動で取得します。`./gradlew` を動かす JDK は 17 以上で構いません）。Gradle Wrapper（Gradle 9.3.0）を同梱しています。初回のビルドは、ソース・差分などに使う等幅フォント Cica（約 23 MB）を GitHub から取得するためネットワーク接続が要ります（2 回目からは不要）。

```bash
cd yaml-design-editor
./gradlew run                                  # スタート画面から履歴・選択でワークスペースを開く
./gradlew run --args="/path/to/your/workspace" # 任意のワークスペースを指定して起動
./gradlew hotRun                               # 開発者向け: Compose Hot Reload 付きで起動（JetBrains Runtime 21 を自動取得）
```

配布物の作成:

```bash
./gradlew packageDistributionForCurrentOS # dmg / msi / deb
```

起動引数を省略すると**スタート画面**が表示され、最近開いたワークスペースの履歴（最大10件。アプリグローバルに保存）から選ぶか、「ワークスペースを開く…」でディレクトリを選択します（`samples/sample-workspace/` があれば、それを開くボタンも表示されます）。開いた後も「ファイル → ワークスペースを開く…」やコマンドパレット（`Ctrl+K`）の「ワークスペースを切替」からいつでも切り替えられます（未保存の変更があれば確認ダイアログを挟みます）。

## 画面構成

画面は左端の**アクティビティレール**で切り替える4つの**スペース**からなります。

```text
タイトル: ワークスペースのフルパス — YAML Design Editor
メニュー: ファイル / 編集 / 表示 / ヘルプ
操作列:   ファイルペイン / 戻る・進む・履歴 / 検索・コマンド / 右ペイン
左レール: 編集 / 台帳 / 実行 / 設計
編集画面: ファイルツリー | 文書名・保存、フォーム / ソース / 差分 | 検証・関係・出現・操作
下部:     ステータスバー（検証サマリ・実行状態・判断待ち）
```

| スペース | 役割 |
|---|---|
| **編集** | ファイルツリー＋フォーム／ソース／差分で文書を1件ずつ編集する（従来のエディタ画面） |
| **台帳** | ワークスペース全体を俯瞰する。「一覧」「ビュー（ビューグリッド）」「レンズ（グラフレンズ）」「エンティティ（エンティティページ）」のタブ（[views.md](views.md)） |
| **実行** | エージェント運用。**受信箱**（承認待ち・質問・競合）・手動実行・自動化・計測/評価のタブ（[ai.md](ai.md)）で、定義が空でも常時表示され、`_agents`／`_activities` が無い間は空状態の案内が出る |
| **設計** | スキーマ・ビュー・エージェント・アクティビティ・評価・連携（skill）の定義を種類別に見渡し、新規作成・スキーマ推測の入口を提供する（[schema.md](schema.md)・[ai.md](ai.md)） |

- ファイル名横の `●` は未保存の編集を表します。ファイルを切り替えても編集内容はメモリ上に保持されます（「保存」「すべて保存」で書き出し）。
- 「フォーム」タブが構造化編集、「ソース」タブがテキスト編集です。ソースの編集は**入力が止まると解析され、成功したときだけ内部のYAMLツリーへ自動反映**されます（フォームと相互に反映されます）。文書ヘッダーの「保存」はそのツリーをファイルへ書き出します。ソースの書きかけは文書が覚えているので、フォームや別の文書を見に行って戻っても、カーソルごとそのまま残ります。
- **解析できない書きかけがある間**: ツリー＝最後に解析できた状態が正で、フォームにはその旨のバナーが出て閲覧専用になります（フォームで触って書きかけを失うことがありません）。バナーの「ソースで直す」「書きかけを捨てる」で進めます。その間に `Ctrl+Z` などで木を戻そうとすると「書きかけを捨てて戻しますか」の確認が出ます。
- **ソースの構文状態**: 本文の上の固定高の枠で、緑の構文正常・グレーの確認中・赤の解析エラーを表示します。エラーの長さや発生・解消で本文は上下に動きません。緑はYAMLの構文が正常という意味で、スキーマ定義や値の検証結果とは別です。
- 赤い枠の「詳細」で、説明とエラー全文をスクロールして読めます。「全文をコピー」、位置が分かる場合の「該当行へ移動」が使えます。閉じる・Esc・外側クリックで本文に戻り、行移動を選ばなければカーソルとスクロール位置を保ちます。未保存・保存済みは枠の右側に表示します。
- **壊れたまま保存**: 解析できない状態で `Ctrl+S` を押しても保存は止まりません。テキストがそのまま書かれ、その文書は直して保存するまで**索引・検証・ビュー・エージェントの対象外**になります（文書ヘッダーのバナー、ファイルツリーの「解析不可」、検証一覧のパースエラーで分かります）。`_schemas/` の文書だけは、そのスキーマを使う全文書に波及するため確認が出ます。直して保存すれば自動で元に戻ります。バナーの「解析できた内容に戻す」で、壊す前の木に戻すこともできます（未保存になります）。
- フォームなど他所で変えた内容は、ソースの書きかけに**変わった行だけ**差し込まれます（丸ごと整形されず、カーソルも動きません）。書きかけと食い違う変更があったときは書きかけを優先し、ステータスバーで知らせます（「整形」で木の内容に揃えられます）。
- Undo/Redo では履歴の値がソースにも反映されます。関係しない書式はできる限り保ちますが、インデントなどを保つと値が変わる場合は、内容を揃えるため書式を整えて通知します。変更した行の空白まで元どおりになるとは限りません。
- `Ctrl+S` で現在のファイルを保存、`Ctrl+Shift+S` ですべて保存、`Ctrl+Z` / `Ctrl+Y` で編集を元に戻す／やり直すことができます。
- 右ペインは**IDインスペクタ**です。「検証」（エラー・警告・フェーズ進捗）、「関係」（この文書からの参照と被参照）、「出現」（文書ルートIDと同じ論理IDの全出現・カバレッジ充足。エンティティページへ展開）、「操作」（スキーマに定義した操作の一覧と、作業中の操作の開き直し。操作そのものは浮いたパネルで進めます。[actions.md](actions.md)）をタブで切り替えます。object、array、mapはフォーム内で折りたためます（既定ではルートから2階層までを展開し、より深い階層だけを折りたたみます。
編集モード・閲覧専用モードで共通で、モード切替後も、別の画面や文書へ移って戻っても展開状態は保たれます）。畳んだ状態のヘッダには要素の要約（object は「ID タイトル（n項目）」、array は「n件: 先頭要素の要約, …」で、参照の配列なら「ID 参照先の名前」。[ids.md](ids.md) の表示解決）が表示され、開かなくても中身を判断できます。
- **配列・map のテーブル表示**: スカラー項目中心の object 配列（例: テーブル定義書のカラム一覧）や、値が object の map（例: 環境定義の `dev` / `staging` / `production`）は、フォーム内で自動的に**表形式**（列ヘッダ＋1要素1行。
map は先頭にキー列）になります。適否は「列が2〜8個 かつ 要素の項目の過半がスカラー系」で自動判定され、スキーマの `display: table` / `display: list` で固定できます（[schema.md](schema.md)）。セルはその場で編集でき、長文・ネスト・enum 連動項目など列にならない項目は行頭の ▶ で開く展開フォームで編集します。
参照のセルは ID の下に参照先の名前を添え、右端の Hub ボタン（⌾ のような印）で横ぐし（エンティティページ）へ 1 クリックで移動できます（閲覧専用モードでも同じ。→ ボタンの「定義へ／エンティティページで開く」も残ります）。
map のキー列は表では表示のみです（キーの追加は表の下の入力行、削除は行操作で行えます）。表が広いときは表の下の横スクロールバーで移動します。不適格な配列・map は従来どおり縦のリスト（各要素は畳み込み可）です。
配列の削除ボタンは、リスト・表・汎用表示とも対象を確認してから削除します。キャンセルでは変更せず、確定すると入れ子の項目も削除します。文書の変更は未保存となり、Undoで戻せます。
確認中に内容が変わった場合は閉じて選び直してください。他の箇所にある同じIDや参照は削除しません。操作の入力欄では入力値だけが変わり、文書のUndo対象にはなりません。
行頭の ▶ で開いた編集フォームは、表示領域の幅に収まります。表を横スクロールしてもフォームの位置は動かず、フォーム内にある別の表はそれぞれ横スクロールできます。
- 参照ジャンプなどの移動は、実行・設計スペースにいても常に編集／台帳スペースへ着地します。スペースの切替自体も「戻る・進む」（`Alt+←` / `Alt+→`）の対象なので、ジャンプ後に戻れば元のスペースへ帰れます。
- **閲覧専用モード**: 「表示 → 閲覧専用モード」で切り替えます。入力欄がテキスト表示になり、追加・削除・AIボタンが消えて表示密度が上がります。参照ジャンプ・バックリンクは閲覧行為としてそのまま使えます。エンティティページの埋め込みフォームやビューグリッドにも同時に効き（改名・統合・削除のメニューも非表示になります）、状態は次回起動時に復元されます。封じるのは編集（未保存の木の変更）で、スキーマに定義した操作（[actions.md](actions.md)）は確認してから書いて保存するため、閲覧専用でも使えます。
- 左右ペインは上部の「ファイル」「検証・関係」（レンズ表示では「レンズ」）で開閉し、各ペイン見出しの × でも閉じられます。
  ボタンの色は表示中かどうかを示し、ホバーで操作名を確認できます。対象ペインのないスペースではボタンは無効になります。
- 左右ペインは境界のドラッグでリサイズでき、開閉状態・幅・テーマ・閲覧専用モードは次回起動時に復元されます。
- 「ファイル」に開く・保存・すべて保存・再読込、「編集」にUndo/Redo・検索、「表示」にペイン・閲覧専用・テーマをまとめています。
- **フォームのまとまり**: 複合項目の前に広い余白を取り、子要素を縦線と字下げで示します。字下げには上限があり、深い構造でも入力幅を確保します。
- **文書情報**: 編集時はフォーム先頭の「文書情報 · 名前と概要」を開いて編集します。他文書の同一IDの定義も件数付きの見出しから開けます。
  開閉は文書ごとに覚えます。閲覧専用時は記載済みの名前・概要を表示します。
- **フォームの配置**: object・map・array は項目名の下に内容を全幅で表示します。単一値は左右に並び、幅が狭いと項目名が上に移ります。スキーマ外の項目や属性付き参照も、値が複合構造なら縦配置になります。
- **入力を終える**: フォームの入力欄で Esc を押すと、入力内容を保ったままカーソルとフォーカス枠が消えます。空欄や不正な値も保持し、エラー表示は残します。表内の入力やスキーマ設計でも同じです。
- 日本語の変換中は IME の Esc 操作を優先します。候補や日付ピッカーが開いている場合は先にそれを閉じ、入力欄に戻ってからの Esc でフォーカスを外します。
- Esc は保存や取消を行いません。保存は Ctrl+S、変更の取り消しは Ctrl+Z です。「追加」など別の確定操作を持つ欄も、Esc では入力途中の文字を保ち、適用しません。
- **選択一覧の現在値**: 選択肢を開くと、現在値の行にチェックと背景色が付きます。マウスを別の候補へ移しても、選ぶまでは現在値のチェックが残ります。未設定や「すべて」も候補にある場合は同じ表示になります。
- **長い選択一覧**: 現在値が見える位置で開き、候補部分をスクロールできます。長い名前や説明は省略表示し、ⓘで全文を読めます。戻るボタンや Esc で一覧へ戻っても、選択は変わりません。
- **候補の検索**: 候補が多い一覧には検索欄が出ます。名前・値・IDなどで絞り込み、クリックまたは上下キーと Enter で選びます。検索だけでは入力値は変わらず、Esc で閉じると検索語は消えます。IME 変換中の Enter・Esc は変換操作が優先されます。
- 入れ子の項目はそれぞれの幅に合わせて配置され、幅の広い表は表内で横スクロールできます。文書ヘッダーは一行で、AI や文書の操作は右端の「文書操作」（⋯）にあります。
- **項目の説明**: 編集時は項目名の下に短く表示します。項目名または ⓘ にマウスを置くと、小さな予告を表示します。説明文・入力欄までの空白・AIボタンでは表示しません。閲覧専用でも同じ操作ができます。
- ホバーの予告は本文約5行分までで、長い説明には「… ⓘで全文表示」を添えます。
- 項目名の ⓘ をクリックするか、Tab で選んで Enter／Space を押すと説明を開いたままにできます。長文はスクロールでき、リンクも操作できます。閉じるには説明の ×、外側のクリック、または Esc を使います。
- **画面の見え方は画面が覚えています**: フォームの畳み、ファイルツリーの展開と選択、右ペインのタブと検証の範囲、台帳の絞り込みとレンズのチェック、実行と設計のタブは、別の画面へ移って戻っても同じままです。「戻る・進む」で戻った文書も見ていたタブ（フォーム・ソース・差分）で開きます。文書を開くときのタブも文書ごとに覚えていて、初めて開く文書は直前の文書と同じタブで開きます（ソースで書いている最中に別の文書を開いてもソースのままです）。ワークスペースを切り替えると既定に戻ります（ファイルツリーの展開・表示設定は起動を跨いで保持します）。
- **ワークスペースやファイルの選択**は OS 標準のダイアログで開き、最後に選んだ場所から始まります（ワークスペースの選択と取り込みファイルで別々に記憶）。
- **Markdown 文書**: ワークスペース内の `.md`（README や設計メモ）もツリーに薄色で表示され、クリックすると描画した「表示」と「ソース」の 2 タブで読めます（表示のみ。編集は「外部のエディタで開く」）。本文の相対リンクは、アプリ内の YAML・Markdown ならそのまま開きます。
- **画像の表示**: `file` 型の項目が画像を指していると、欄の下にそのまま表示され、「拡大表示」で編集スペースの全面に出ます（[files.md](files.md)）。
- **内蔵ヘルプ**: 「ヘルプ → 利用者マニュアル」、またはコマンドパレットの「ヘルプ: …」で、この利用者マニュアルをアプリの中で読めます。題目間のリンクで移動でき、「戻る・進む」の対象です。
- **日付・時刻の項目**: 入力欄の右のカレンダー（時計）ボタンからポップアップで選べます。日付はクリックで即反映、時刻を含むときは「決定」で反映します。手入力もそのまま使えます。
- **配列の並べ替え**: 要素の左の取っ手（⋮⋮）を押したまま動かすと並べ替えられます（縦リスト・テーブルの行とも）。上へ・下へのボタンも残っています。
- ファイルペイン上部からYAML／ディレクトリの作成、名前変更、削除を実行できます。新規YAMLは配置先に適用されるスキーマから初期値を生成します。作成先は**ツリーで選択中の場所の配下**で、ダイアログに作成先パスが表示されます（「ワークスペース直下に作成する」への切替も可能。ツリーの空白をクリックすると選択が外れ、未選択時はルート直下が作成先になります）。名前の入力は Enter でも確定でき、同名ファイルが既にある等で作成できない場合は理由がダイアログ内に表示されます。
- ステータスバーの右側に、開いている文書の検証サマリ、実行中のアクティビティ、自動化の稼働状態、**判断待ちの件数**（クリックで受信箱へ）を常時表示します。
- ウィンドウ終了時とワークスペース切替時には未保存確認を表示します。

### フォームの表示方式

フォームとスキーマの「設計」では、上部の三つのアイコンで編集範囲を切り替えます。ホバーすると名称と説明が出ます。初期状態は可変・全ファイル未指定で、最初の表示は「選択項目」です。

| 表示 | 操作 |
|---|---|
| 選択項目 | 左の構成ツリーで選んだ項目だけを右で編集 |
| 全体・ツリー連動 | 全体フォームを表示し、ツリー選択でその位置へ移動、手動スクロールでツリーの選択が追従 |
| 全体のみ | ツリーを隠し、全幅で全体フォームを編集 |

- ピンを留めると現在の方式で**固定**し、ファイルを切り替えても同じ方式を使います。外すと**可変**になり、ファイルの指定があればそれを使い、未指定なら直前に表示した方式を引き継ぎます。
- 方式アイコンを押すと、そのファイルの**明示指定**になります。同じ方式の選び直しも指定です。固定中は固定する方式も変わります。ファイルを開くだけでは指定を作りません。
- ピン横の設定アイコンで「現在の表示」と「このファイルの指定」を確認・変更できます。指定があるとアイコンに点が付きます。固定中はここで指定を変更しても表示は変わらず、固定解除後に反映します。
- 指定を「未指定」に戻しても現在の表示は維持します。次回はその時点の直前表示を引き継ぎます。固定／可変の切り替え自体は指定を作りません。
- 構成ペインの **×** は「全体のみ」への明示変更です。再表示はツリー付きの方式アイコンから行います。狭幅の「編集に戻る」は方式を変えずフォームへ戻る操作です。
- 固定／可変はワークスペース全体、方式の指定はファイル単位で、このワークスペースを開いている間保持します。スキーマの設計と汎用フォームも指定を共有します。選択位置・ツリーの開閉は画面ごとに保持します。
- 「全体・ツリー連動」では、ツリーをクリックした後も、フォームをスクロールすると上端付近の項目へ選択が切り替わります。折り畳みで項目の位置が変わった場合も追従します。
- 表示を切り替えても選択対象を引き継ぎます。全体表示への移動では必要な祖先や表の行詳細を開きます。ツリーの開閉とフォームの折り畳みは独立しています。
- 通常文書のツリーは項目名と要約を表示し、配列の要素にはタイトルを添えます。「文書全体」を選ぶと全体を編集できます。文書ビューの項目選別も反映します。
- 幅が狭いときは「構成を開く」でツリーへ切り替え、項目を選ぶとフォームへ戻ります。閲覧専用でも表示の切り替えと移動は使えます。

### 操作の役割

- **ライブ同期**（ソースタブ）: 入力が止まると（0.3 秒）解析し、成功したときだけ内部YAMLツリーへ自動反映します。解析エラーの間は行・列つきのエラーが表示され、「編集を破棄」でツリーの状態に戻せます（エラーがなければ同じボタンが「整形」＝正規化テキストへの揃えになります）。
- **行番号と折り返し**（ソースタブ）: 行番号は折り返した行でもずれません。右上の「折り返し: あり／なし」で、長い行を折り返すか横スクロールにするかを切り替えられます（画面を離れても覚えています）。
- **閲覧専用モード**はソースタブにも効きます（欄は読み取り専用になり、置換と整形のボタンが消えます）。
- **文書情報**: 文書名を押すと、相対パス・スキーマ名の確認とフルパスのコピーができます。未保存・閲覧専用の状態はヘッダーに常時表示します。
- **保存**（文書ヘッダー）: 内部YAMLツリーを現在のファイルへ書き込みます。コメント・キー順・引用符やフロー表記のスタイルは保持されます（詳細は「既知の制約」）。スキーマに保存時に自動で入る値（更新日・作成日・版。[schema.md](schema.md)「保存時に自動で入る値」）があれば、保存の直前に入って状態表示に出ます（`Ctrl+Z` で戻せます）。
- **ソース編集中の `Ctrl+S`**: 反映と保存を続けて実行します。解析できない状態なら「壊れたまま保存」になります（上記）。
- **ソース編集中の `Ctrl+Z` / `Ctrl+Y`**: 欄の中だけの取り消しではなく、フォームと同じワークスペース全体の履歴を戻します（入力待ちの分は先に反映されます）。カーソルは戻した行の近くに留まります。
入力直後から Undo ボタンが使えます。Redo は入力の反映待ちの間は無効になり、新しい編集が反映されると以前のやり直しはできなくなります。
壊れた下書きを捨てる確認中に履歴や下書きが変わった場合は、取り消しを中止して再操作を案内します。
- **フォーム編集中の Undo/Redo**: 文書の値を直接編集する欄でも、Ctrl+Z／Ctrl+Y／Ctrl+Shift+Z はツールバーと同じ履歴を使います。別の文書の変更が直前なら、その変更から戻します。
  検索欄・追加や改名の確定前・操作パネルの入力では欄の文字列を戻します。フォームで日本語変換中に押したキーは文書の Undo を実行しません。
- **検索・置換**（ソースタブ）: `Ctrl+F` で検索欄へ。一致はすべて色が付き、現在の一致は濃く出ます。Enter / `F3` で次へ、Shift+Enter / Shift+F3 で前へ、Esc で欄へ戻ります。「Aa」で大文字小文字を区別、「.*」で正規表現になります（置換では `$1` のような群の参照が使えます）。`Ctrl+H` で置換欄へ。「置換」は現在の一致だけ、「すべて置換」は全部です。置換結果も自動で反映されます。
- **行へ移動**（ソースタブ）: `Ctrl+G` で行番号の欄へ。Enter でその行へ移ります。
- **Tab キー**（ソースタブ）: フォーカス移動ではなくスペース2個を挿入します（YAMLはタブ文字を使えないため）。複数行を選んでいれば選んだ行をまとめて 1 段深くし、`Shift+Tab` で 1 段戻します。
- **Enter キー**（ソースタブ）: 前の行と同じ深さで改行します。前の行が `:` で終わるか `-` だけなら 1 段深くなります。
- **行の操作**（ソースタブ）: `Ctrl+/` でコメントの付け外し、`Ctrl+D` で行の複製、`Alt+↑` / `Alt+↓` で行の移動（複数行の選択もまとめて）。カーソルの行は背景が付き、行番号も濃く出ます。
- **検証の指摘**（ソースタブ）: 指摘のある行は左端に赤（エラー）か橙（警告）の印が付き、値にも薄く色が付きます。印にマウスを載せると内容が出ます。右パネルの「検証」で指摘を押すと、ソースを見ている間はその行へ移ります（フォームを見ていればフォームの項目へ）。
- **補完**（ソースタブ）: `Ctrl+Space` で候補が出ます。キー名はスキーマから（既に書いたキーは除く）、`ref` の項目の値は ID の索引から（未保存の ID も）、`enum` は選択肢、`file` はワークスペースのファイル。打ち続けると絞られ、↑↓ で選んで Enter か Tab で入ります。Esc で閉じます。入力中に勝手には出ません。
- **項目の説明**（ソースタブ）: キーや値にマウスを載せて少し待つと、項目のラベル・型・説明（スキーマの `description`）が出ます。
- **参照先へ**（ソースタブ）: `ref` の項目の値を `Ctrl` を押しながらクリックすると、その ID の定義へ移ります。
- **折り畳み**（ソースタブ）: 行番号にマウスを載せると、入れ子のある行に ▾ が出ます。押すとその下の行が畳まれ、見出しに「⋯ n 行」が付きます（`Ctrl+Shift+[` でカーソルの行も同じ）。もう一度押すか「すべて広げる」で戻ります。畳んだ状態は文書ごとに覚えていて、検索やジャンプで畳んだ中の行へ行くときは自動で広がります。畳んでも文字列は変わりません（保存される内容は同じ）。
- **保存済みとの差分**（ソースタブ）: 行番号の左に、追加した行は緑、変えた行は青の縦線、行を消した場所は赤の短い横線が付きます。保存すると消えます。
- **フォームとの行き来**（ソースタブ）: フォームで項目を編集してからソースへ移ると、その項目の行にカーソルが来ます。ソースからフォームへ移ると、カーソルのあった項目がフォームで強調されます。
- **選択範囲を整形**（ソースタブ）: 複数行を選ぶと「選択範囲を整形」が出ます。その範囲だけを正規化し、深さはそのまま保ちます（範囲が YAML の塊になっていないときは案内が出て何もしません）。
- **構文ハイライト**（ソースタブ）: キー・文字列・数値・真偽値・コメント・`---` を色分け表示します。
- **Undo/Redo**: 履歴は**ワークスペース全体で1本**です（直前の変更が別のファイルのものなら、そのファイルが戻ります）。同じフィールドへの連続入力（1秒以内のタイプ）は1回の Undo でまとめて戻ります。

別の項目への編集・時間を空ける・構造を変える操作に加えて、**保存・タブ切替・別画面への移動**が入力の区切りになります。画面を離れてすぐ戻った場合も、復帰後の入力だけを戻せます。
ソースの解析待ち入力は移動前のまとまりへ含めます。保存後の入力を戻すと保存した値へ戻り、さらに Undo すれば保存前の編集も戻せます（保存時の自動値は別の1回です）。
一覧からの一括変更は、更新日や版番号の自動更新も含めて **Undo 1回で全対象が戻ります**。Redo も同じ値を復元します。内容の Undo は未保存の変更になり、ファイルに反映するには保存します。
表示中とは別の文書を含む操作では、ツールバー直下に変更内容・対象件数・現在の未保存件数を表示します。「対象の文書を開く」または「対象 N 件を確認」から戻った文書を確認できます。
Undo/Redo が成功すると、**編集した画面へ戻ります**。ファイルでの編集はその文書とタブ、ビューのセル編集や一括変更は元のビューを表示します。同じ画面にいるときはそのまま操作できます。
移動前の画面へは Alt+←で戻れます。元のビューがなくなった場合は対象が一文書ならその文書を開き、複数なら通知から対象を確認できます。
通知は編集・保存後も残り、「閉じる」、次の Undo/Redo、ワークスペース切替で消えるか更新されます。
同じ文書だけの操作はステータスバーに通知し、次の編集・保存・✕で消えます。
ツールバーの Undo/Redo ボタンにマウスを載せると「次に何が戻るか」の予告が表示されます。**文書の新規作成**（新規 YAML・ビューからの詳細文書／新規行ファイル・検証指摘からの「詳細文書を作成」・スキーマ推測）も履歴に入り、`Ctrl+Z` で取り消せます——作成の取り消し／やり直しは**ファイルの有無までその場で反映**されます（内容の編集の Undo が未保存●に留まるのと違い、保存の操作は要りません）。
作成しても、それまでの Undo 履歴は失われません。
開いていない文書が戻った場合も、一覧・検索と、後で開くフォーム・ソースには戻した内容が表示されます。
その文書も未保存件数・終了時の確認・「すべて保存」の対象になります。内容の Undo だけでは保存済み内容は変わらず、ソースの差分印も残ります。
- **キー名の変更**（汎用ビュー）: キー名横の鉛筆アイコンから、順序と値を保ったまま改名できます。
- **複数ドキュメント（`---` 区切り）**: フォームでは先頭ドキュメントを編集し、後続ドキュメントは保持されて保存時にそのまま再出力されます。全ドキュメントを編集したい場合はソースタブを使います。

| キー | 操作 |

| `Ctrl+Z` | 元に戻す |
| `Ctrl+F` / `Ctrl+H` / `Ctrl+G` | ソースタブ: 検索欄・置換欄・行へ移動の欄へ |

| `Tab` / `Shift+Tab` | ソースタブ: スペース 2 個（複数行の選択ならまとめて 1 段深く）・1 段戻す |
| `Ctrl+/` / `Ctrl+D` / `Alt+↑↓` | ソースタブ: コメント切替・行の複製・行の移動 |
| `Ctrl+Space` | ソースタブ: 補完（キー名・ID・enum の値・ファイルの場所） |
| `Ctrl+Shift+[` | ソースタブ: カーソルの行の区画を畳む／広げる |

| `Alt+→` | 進む |

## ワークスペースの構成

任意のディレクトリを「ワークスペース」として開きます。

```
my-workspace/
├── _schemas/            # スキーマ定義（このディレクトリ名は固定）
│   ├── requirement.yaml
│   └── design-item.yaml
├── requirements/        # 以下は自由な構成。*.yaml / *.yml が対象
│   ├── req-001.yaml
│   └── req-002.yaml
├── designs/
│   └── dsn-001.yaml
└── notes/
    └── memo.yaml        # スキーマにマッチしない → 汎用ビュー
```

各 YAML ファイルには、`_schemas/` 内のスキーマのうち `match`（glob）がワークスペース相対パスに最初にマッチしたものが適用されます（ファイル名の昇順で評価）。どれにもマッチしなければ汎用ビューになります。

### `.yde` 構成（既存リポジトリとの共存・台帳範囲の宣言）

上記のレガシー構成（ルート直下の `_schemas` 等）に加えて、ツールの構成を隠しディレクトリ `.yde/` にまとめる**オプトイン構成**が使えます。既存のプロジェクトリポジトリ（他ツールのYAMLが混在する環境）へ後入れする場合はこちらを推奨します。

```
my-project/
├── .yde/                     # ツール構成（.git / .obsidian と同じ流儀）
│   ├── workspace.yaml        # ledger: 台帳ディレクトリの宣言
│   ├── schemas/              # 旧 _schemas（以下、アンダースコア無しの名前）
│   ├── views/  agents/  activities/  evals/  skills/  runs/
├── doc/                      # 台帳（ledger に宣言した範囲）
│   └── req-001.yaml
├── .github/workflows/        # 台帳外 → 索引・検証集計・エージェントの対象外
└── build/                    # 台帳外（エクスポート先などに自由に使える）
```

```yaml
# .yde/workspace.yaml
ledger: doc          # 文字列またはリスト（例: [doc, spec]）。未宣言なら全体が台帳
files:               # file 型の値（ファイルの場所）の扱い（省略可）
  outside: warning   # ワークスペースの外（絶対パス・.. で外へ出る）: allow / warning / error。既定 warning
  allowedRoots:      # 外でも許す場所（絶対パスの接頭辞）。ここに入る場所は外として扱わない
    - C:/shared/diagrams
  missing: error     # 無いファイル（場所は読めるが存在しない）: allow / warning / error。既定 error
```

機能は2層に分かれます。**エディタ層**（ソース／スキーマフォーム編集・単文書検証など、1ファイルで完結する機能）は台帳外のYAMLにも効きます——スキーマの `match` は常にワークスペース相対で、台帳外にもマッチします。**台帳層**（ID索引・参照解決・カバレッジ・ビュー・エージェント・自動化・skill）は `ledger` 配下だけが対象です。台帳外の文書では未解決参照が情報レベルに降格され、ファイルツリーでは薄色・折りたたみで区別されます。

- `.yde/` が無いワークスペースは従来どおり動きます（設定不要）。
- レガシー構成からの移行は `./gradlew runCli -q --args="migrate <workspace> [--ledger doc]"`（予約ディレクトリの移動と構成ファイル作成のみ。スキーマ等の中身は書き換え不要）。
- `.git` などの隠しディレクトリは走査されません（`.yde` のみ例外）。


## 外部変更・競合・安全性

- ワークスペース内のYAMLをOSのファイル監視（WatchService）で監視します。監視を開始できない環境では約1秒間隔のポーリングに自動フォールバックします。
- 未保存編集のないファイルの外部変更は、自動的に取り込みます。
- 未保存文書が外部変更された場合は自動上書きせず、競合バナーを表示します。
- 保存直前にもファイルの内容を比較し、外部変更があればその文書の保存を停止して、編集内容と履歴を残します。「すべて保存」では保存できなかった文書を通知し、ほかの文書は保存します。
- 競合時は「ディスク版を読み込む」か「次回保存で上書きを許可」を選びます。上書き許可だけでは保存せず、次の保存時に編集内容を書き込みます。許可後に再度外部変更があれば停止します。
- 未保存文書を含む名前変更・削除・一括編集は拒否されます。
- ファイル削除は確認ダイアログを経由します。

「ファイル → 再読込」は、未保存編集・ソースの下書き・Undo/Redo を保って外部変更を取り込みます。再読込後の Undo も、編集した文書やビューへ戻ります。
未保存の文書が外部で変わっていた場合は、その編集を残して競合を通知し、ほかの変更は取り込みます。競合する文書の保存と Undo/Redo は解決まで停止します。
「次回保存で上書きを許可」を選ぶと、手元の編集を保って既存の履歴を使えます。「ディスク版を読み込む」を選ぶと、採用した外部版と衝突する古い履歴は使えなくなります。

保存済みの文書への外部変更も取り込みますが、それを上書きする古い Undo/Redo は、対象を示して停止します。一括変更は一文書でも競合すると全体が停止し、途中の履歴を飛ばして戻すことはできません。
外部版を取り込んだ後の新しい編集は、通常どおり Undo/Redo できます。

スキーマや構成の変更も、編集と履歴を保ちながら取り込みます。定義の読込エラーや、変更後の配置では履歴の対象を扱えない場合は、理由を表示して取り込み全体を中止します。

編集を捨てて現在のディスク内容から再開する場合は、「ファイル → 編集と履歴を破棄して開き直す…」を使います。確認画面に未保存の対象と Undo/Redo の件数を表示します。
確定すると下書き・未保存編集・全履歴が失われますが、保存済みのファイル内容や移動済みの配置は変わりません。キャンセル・読込失敗・確認中に編集が変わった場合は、編集と履歴を残します。

## ファイル一覧の表示と検索

ファイルペインの「表示」で「すべての形式」「隠し項目も表示」、除外 glob（`;` 区切り）を設定できます。隠し項目と除外は独立した設定です。
フォルダーは矢印で展開し、名前で操作対象を選択します。Ctrl＋クリックで追加・解除、Shift＋クリックで表示中の範囲を選べます。選択は背景、開いている文書は枠と太字で示します。「現在地」は編集中のファイルの祖先を開いてスクロールします。
名前・相対パスの絞り込みは空白区切りの全語一致です。未展開のフォルダーも調べ、結果には相対パスを表示します。上限に達した場合は条件を絞ってください。検索を消すと元の展開へ戻ります。
展開と表示設定はワークスペースごとに再起動後も復元します。「畳む」で全体を折り畳みます。右クリックから改名・削除・相対パスのコピー・外部フォルダー表示を使えます。
一般のテキストファイルは読み取り専用です。UTF-8・2 MiB までを表示し、それ以外は外部アプリで開けます。参考資料を表示しても台帳の索引・検証対象は増えません。
ツリーに焦点があるとき、上下で選択、左右で展開・折り畳み、Enterで開く、F2で改名、Deleteで削除、Ctrl+Cで選択先の相対パスをコピーできます。

## ファイルとフォルダーの整理

複数選択にも対応しています。フォルダーへドラッグするか、一覧の空白へドラッグして直下を指定すると、移動の確認画面が開きます。
件数・選択数・ドラッグ中の案内は同じ高さの状態欄に表示します。ドラッグ中は移動先のフォルダーを背景と枠で強調し、直下なら一覧の枠を強調します。
自分自身・自分の配下・現在と同じフォルダーなどでは「ここには移動できません」と表示し、ドロップしても移動の確認を開きません。
「移動」または右クリックの「移動…」でワークスペース内の移動先を選び、「影響を確認」で定義修正と警告を確認して適用します。改名も同じ確認画面です。フォルダー内の非表示ファイルも一緒に移動します。
スキーマ・ビューなどのパス指定の追随は既定で有効です。台帳範囲・書込許可は別のチェックで採用します。部分移動のパターンは元の範囲も残します。将来作るファイルへの適用範囲も差分で確認してください。
型付き file 値と通常の Markdown インラインリンクも追随します。Markdown の参照形式・HTML・コード、定義内の未対応の言及は自動修正せず確認対象とします。ソースコードの import 等は書き換えません。
移動・改名・フォルダー作成・削除は Ctrl+Z / Ctrl+Y で戻せます。削除は `.yde-trash` への退避で、再起動後も退避内容は残りますが、Undo 履歴は再起動を跨ぎません。退避領域の手動整理は復元が不要になってから行ってください。
開いている文書は移動・改名先へ追随します。Undo/Redo でもファイルの場所と表示を更新し、処理が終わるまで次の書込操作を待ちます。
未保存の編集・壊れたソース下書き・外部変更・同名の移動先がある場合は適用を止めます。電源断・強制終了を跨ぐ一括操作の原子性は保証しません。

## 参考資料の本文検索と構造

ファイルペインの「表示 → 本文を検索」を有効にし、検索欄へ空白区切りで語を入れます。同じ行に全語を含む箇所を、大文字小文字を区別せず検索します。
「選択先の配下」で範囲を狭め、「上限」で合計読込量を16・64・256 MiBから選べます。既定は64 MiB、1ファイル2 MiB、結果2,000箇所までです。
時間上限は既定30秒で、120秒・時間制限なしへ切り替えられます。検索中も見つかった結果を順次表示します。中止と時間上限はファイル読込の合間で確認します。
表示対象の設定・除外 glob も検索へ適用します。ソースコードを探す場合は「すべての形式」を有効にしてください。「検索を中止」で止められ、上限・中止時は一部の結果と表示します。
結果の行番号と抜粋を見てクリックすると、読み取り専用表示で該当行へ移動します。ディスク上の内容を検索するため、未保存の YAML 編集は含みません。

Kotlin・Java・Python・JavaScript／TypeScript の閲覧では「構造」からクラス・メソッド・関数等の宣言候補へ移動できます。
「構造を保存…」はソースのパス・言語・宣言の種類・名前・行番号・所有者を、新規 YAML に保存します。元のソースを書き換えず、既存の保存先も上書きしません。
保存先に適用するスキーマで索引・検証の扱いを定義してください。ソースの移動に追随させる場合は保存された `source` を `type: file` として定義します。
この情報は保存時のスナップショットです。構文木や型解決に基づく完全な一覧ではなく、複数行の宣言や言語固有構文では欠落・誤検出があります。
