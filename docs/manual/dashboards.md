# ダッシュボード

ダッシュボードは、業務の状況を確認し、対象の詳細と操作へ進む画面です。
左端レールの最上部「ダッシュボード」で開きます。定義があればワークスペースを開いたときに表示します。
Ctrl+Kの「ダッシュボードを表示」からも移動できます。定義がなければ従来の編集画面から始まります。

## 操作

1. 上部の名前からダッシュボードを選びます。
2. 状況の件数を押すと、その区画の一覧に切り替わります。区画は群ごとに見出し付きで並び、見出し（▾）を押すと群を畳めます。畳みはワークスペースを切り替えるまで覚えます。
3. 一覧のID・「詳細を開く」・通常の表示セルから、全幅の業務詳細へ進みます。参照項目からは参照先の対象へ進みます。
4. 詳細の「この対象の操作」または一覧の「⋯」から、対象の操作を始めます。
5. 上部の「操作」から登録等の対象を持たない操作を始められます。
6. 定義に共有の入力（`inputs`）があれば、基準日の横に欄が並びます。日付と文字は「反映」で、選択はすぐに効き、全区画の件数・一覧・図が揃って絞られます。空は「絞らない」で、「入力を戻す」で初期値に戻ります。

操作は既存の入力・確認・差分・適用の流れを使い、閲覧専用でも実行できます。
未保存編集が操作の対象にあると適用できません。先に「すべて保存」で保存してください。
操作後に対象が区画の条件から外れても、開いている詳細は維持します。対象自体が削除された場合はその旨を表示し、別の対象へ切り替えません。
「一覧へ」で更新された一覧へ戻り、区画・基準日・スクロール位置を引き継ぎます。「戻る」「進む」は関連対象や原本への移動もたどれます。

「一覧と並べる」は一覧と詳細を4:6で表示します。幅が足りない場合は全幅表示になり、広げると分割へ戻ります。
区画のタイルの並べ方は定義の `placement` で選びます。auto（既定）は、横に折り返して並べると3段以上になる幅のときだけ左の縦一覧にし、広げると横へ戻ります。「一覧と並べる」の分割中は、auto は横にし、vertical の縦一覧は狭くします。
ファイル・スキーマの情報は通常の業務詳細には出しません。「原本を開く」で編集スペースへ移動できます。
文書参照は業務対象への参照と区別し、「原本を開く」から参照文書を開きます。
詳細のフォームも既存の編集経路を使います。ダッシュボード上のCtrl+Sは「すべて保存」と同じです。

基準日は全区画で共通です。YYYY-MM-DDを入力して「反映」で指定し、「本日」で当日の表示へ戻せます。
基準日は表示の条件だけに使います。操作の完了日等を過去日にする設定ではありません。
本日表示では日付が変わると自動で再評価します。指定日はワークスペースを切り替えるまで覚えます。

件数と一覧は同じ結果です。未保存編集も表示に反映します。
データ不足等で判定できない行は件数に含めず、理由付きで表示し、IDから確認できます。
定義エラーはゼロ件として扱いません。通常のビューは台帳スペースから開けます。

## 定義

`.yde/views/`（従来配置は `_views/`）に定義します。既存のgrid・matrix・chart（[views.md](views.md)「チャート」）を参照します。

```yaml
id: task-home
name: 作業の状況
kind: dashboard
default: true
actions: [register-task]
placement: auto
inputs:
  - { key: from, label: 期限（から）, type: date, default: $monthStart }
  - { key: assignee, label: 担当, type: enum, values: [{ value: taro, label: 太郎 }, hanako] }
sections:
  - id: overdue
    label: 期限超過
    group: 状況
    view: task-list
    filter:
      match: [{node: {entity: task, bind: t}}]
      where:
        - {of: t, path: status, equals: OPEN}
        - {of: t, path: due, exists: true}
      check:
        - lt: [{of: t, path: due}, $today]
          type: date
  - {id: all, label: すべて, group: 状況, view: task-list}
```

この例は、task型・task-listビュー・register-taskアクションがあるワークスペース用です。
実際に使える一式は [TODOサンプル](../../samples/todos/README.md#ダッシュボードを試す)を参照してください。

| 項目 | 意味 |
|---|---|
| id / name / description | ビューID・表示名・説明 |
| default | trueなら開始時の入口、指定はワークスペース内で1件 |
| actions | 対象を持たないアクションIDの並び |
| placement | 区画のタイルの並べ方。auto（既定。幅に応じて判断）・horizontal（横に折り返す）・vertical（左の縦一覧） |
| inputs | 全区画に共有する入力の配列。`key`（名前）、`label`、`type`（`date` / `enum` / `string`。既定は string）、`values`（enum の候補。値か `{value, label}`）、`default`（初期値。`$today` / `$monthStart` / `$monthEnd` は基準日から） |
| sections | 表示順に並べる区画の配列 |
| sections[].id / label | 画面内で一意な区画IDと見出し |
| sections[].group | 群の名前。同じ名前の区画を見出し付きでまとめ、見出しで畳めます。書かない区画は無名の群として先頭に並びます |
| sections[].view | 一意なgrid・matrix・chartのID |
| sections[].filter | 行のエンティティを起点に判定する条件、省略すると全行（chartの区画には書けません） |

defaultを省略すると、一意なIDを持つダッシュボードを定義ファイル名順で選びます。
複数のdefault指定はエラーを表示し、同じ規則で先頭を開きます。切替は上部の名前から行います。

filterは既存の検査と同じ `match` ＋ `expect / count / check / forAll` のいずれかです。
`where` で対象範囲を限定できます。条件を満たした行だけを表示します。
`$today` は基準日です。共有の入力は `$名前` で使えます（例 `{of: t, path: assignee, equals: $assignee}`）。それ以外のパラメータ、指摘の重大度や修正応答は指定できません。

共有の入力の値は、区画の `filter` と、区画が参照する表（グリッド・クロス集計・チャートの元の表）の `params`（[views.md](views.md)）に `$名前` で渡ります。
空の値は「絞らない」で、その値を使う条件（`where` / `check` の項目）が外れます。`match` の中で使うと空にできません（誤りになります）。
値の式の列（`all` の集計）には渡りません。集計を絞るなら、クロス集計の `cells.where` に書きます。
個票がないことを状態の既定値で補完しません。`occurrenceCount` で別の区画として扱えます。

件数は行数です。クエリ行は同じIDでも束縛が違えば別の行になり、matrixの合計行は件数に含めません（行の軸が値のクロス集計では、値の行を数えます）。
matrixの区画にはfilterを付けられません。ビューの入れ子や自由なレイアウト、カテゴリの共通選択欄は未対応です。
chartの区画は、件数の代わりに横軸の項目の数を出し、一覧の代わりに図を描きます。棒を押しても対象の詳細は開かず、「元の表を開く」で台帳のビュータブへ移ります。絞り込みは元の表で行います。
表示や操作の状態はローカルで、権限管理の仕組みではありません。

## CLIとエージェント

```text
view <workspace> <dashboard-id> --date YYYY-MM-DD --param 名前=値
```

基準日を省略すると本日です。共有の入力は `--param` で渡し、渡さなければ定義の `default`、空文字なら絞りません。出力の `inputs` に効かせた値が出ます。区画・件数・行・セルの原本座標・判定できない対象と理由を返します。
`read_view` もダッシュボードIDと任意の `date` を指定でき、ステージングを重ねた同じ解決結果を返します。
ダッシュボードでは `file / rows / columns` は指定しません。
