# 既知の制約


- **コメント・キー順・表記スタイルは「開く→編集→保存」の往復で保持されます**（引用符・リテラルブロック `|`・フロー表記 `[a, b]` を含む）。残る正規化は次のとおりです:
  - アンカー／エイリアス（`&x` / `*x`）は読み込み時に展開され、保存すると実体化します。
  - ブロックスタイルのインデントは 2 に正規化され、リストの `-` は親プロパティより一段深く配置されます。
  - リスト要素の**前の行**に書かれたコメントは、SnakeYAML エミッタの制約により初回保存時に `- # コメント` の形（`-` の後ろ）へ移動します。内容は失われず、以降の保存では安定します。
  - 編集で値を**置き換えた**箇所（AI適用・パッチなど）のコメントは可能な範囲で引き継がれますが、削除した項目のコメントは項目とともに消えます。
- 外部変更は OS のファイル監視（WatchService）で検出します。監視を開始できない環境（ネットワークドライブ等）では約1秒間隔のポーリングへ自動フォールバックします。未編集ファイルは自動反映され、未保存の編集がある場合は競合バナーからディスク版または編集中の内容を選択できます。
- 複数ドキュメント（`---` 区切り）の YAML は、フォーム編集・索引・検索が**先頭ドキュメント**を対象とします。後続ドキュメントは失われずに保持され、ソースタブで編集できます。
- 差分ビューは行単位の整列＋行内の文字単位強調です。Gitの履歴表示ではありません。
- 一覧ビューの一括編集はルート直下のスカラー項目のみが対象です（配列・オブジェクトの項目は選択しても上書きされません）。
- ビューグリッドの**行の増減**（新しいIDの出現）は索引基準のため保存まで反映されません（セルの値・編集は未保存でも即時反映されます）。セルの直接編集はスカラー値のみで、配列・オブジェクトはジャンプして個別フォームで編集します。

改善予定を含む実装状況の全体は [docs/FEATURES.md](../FEATURES.md) で管理しています。拡張方法（型の追加・横断ビュー・AIプロバイダの追加など）は [docs/architecture/](../architecture/README.md) の「拡張ポイント」を参照してください。
