# 接続と常駐の設定

同じ PC 内の API・MCP・Web を、機能ごとに有効・無効にできます。
API は保存版の閲覧と、業務操作・変更提案・直接確定に対応します。MCP の業務経路、Web 画面・ブラウザのログインは未公開です。

## 有効・無効と状態

スタート画面、またはワークスペースを開いた後の「設定 → 接続と常駐」から開きます。
新規導入と設定のない旧版からの更新では、三つとも OFF です。ワークスペースを開くだけでは有効になりません。

- **API**: 自作ツール向けの接続です。
- **MCP**: 外部 AI エージェント向けの接続です。
- **Web**: ブラウザの業務画面と、その画面用の通信です。API が OFF でも独立して有効にできます。

「指定: ON / OFF」と「停止・起動中・稼働中・停止中・エラー」を別々に表示します。
一つでも有効なら `127.0.0.1` の一つのポートで待ち受け、すべて OFF で停止が完了すると「待受なし」になります。
ON にした機能の接続先はコピーできます。停止しても登録した権限・提出済みの作業・未保存編集は残ります。

初期ポートは `18765` です。変更は全機能を OFF にして停止完了を待ち、ポートを入力して「ポートを保存」で行います。
他のアプリがポートを使用しているとエラーを表示し、別ポートへ自動では切り替えません。原因を解消して「設定保存と接続を再試行」を押してください。
保存済みの ON/OFF とポートは次回起動時に復元します。アプリを終了する操作は保存した ON/OFF を変えません。

## トレイ常駐と画面非表示での起動

同じ設定ページの「トレイに常駐する（×で画面を隠す）」を ON にすると、タスクトレイにアイコンを表示します。
常駐中はウィンドウの × または「画面を隠す」で画面だけを隠し、未保存編集・監視・実行・承認待ちを保持します。常駐が OFF のときの × は従来どおり終了です。
常駐の設定だけでは API・MCP・Web は有効になりません。三つとも OFF ならポートを開きません。

アイコンをダブルクリックするか、右クリックメニューの「画面を表示」で戻せます。
「受信箱を開く」には承認待ち・外部変更の競合・質問待ちの合計件数を表示し、選ぶと実行スペースの受信箱を開きます。
「接続・常駐の設定」はワークスペース未選択でも開けます。Windows の設定によってはアイコンがタスクトレイの隠れた一覧に入ります。

アプリを止めるときはトレイの「完全終了」を選びます。未保存編集がある場合は画面に戻り、保存せず終了するかキャンセルするか確認します。
保存して終了したい場合はキャンセルして通常の保存を行ってください。終了時には進行中の保存や接続停止の完了を待ちます。

常駐を ON にすると「次回から画面を表示せずに起動する」も選べます。両設定は保存され、常駐を OFF にすると非表示起動も解除して画面を戻します。
非表示起動では表示を求めるまで窓を作りません。起動時にワークスペースを開く場合はパスを引数で指定してください。パスがない場合は未選択で常駐します。
トレイを利用できない環境や起動エラーでは画面を表示し、理由を通知します。設定を保存できなければ切り替えず、エラーを表示します。

起動引数で今回の表示だけを指定することもできます。保存済みの設定は変更しません。

| 引数 | 動作 |
|---|---|
| `--hidden` | 今回だけトレイを有効にして画面非表示で起動 |
| `--show` | 非表示起動の設定にかかわらず画面を表示 |
| 指定なし | 保存済みの常駐・非表示起動の設定を利用 |

例: `yaml-design-editor.exe --hidden "C:\work\my-workspace"`。ソースからは `./gradlew run --args="--show"` で表示できます。
両オプションの同時指定はできません。オプションに似たパスは `--` の後に置きます。
`--show` は新しく起動するアプリへの指定です。すでに常駐しているアプリの画面はトレイから戻してください。

## ワークスペースの二重利用

同じワークスペースを二つのデスクトップで同時に開くことはできません。別のワークスペースは開けます。
画面を隠して常駐している間も使用中です。履歴などから開けなかった場合は、「ワークスペースを開けませんでした」という通知に対象・理由・対処方法を表示します。
既に開いている画面を使う場合は、常駐側のトレイから「画面を表示」で戻れます。この画面で開く場合は、使用中のアプリを完全終了してから通知の「再試行」を押してください。
通知は「閉じる」で消せます。切替に失敗した場合は元のワークスペースを保ち、再試行時も未保存の変更があれば確認します。
異常終了後も再起動して取得できます。
終了直後にまだ使用中と表示される場合は、少し待ってから再試行してください。

デスクトップが使用中の間は、独立 CLI の書込も拒否します。閲覧・検証・プレビューは使えますが、対象は保存済みの内容です。
対象コマンドは [CLI のワークスペース所有](cli.md#ワークスペースの所有と書込) を参照してください。API を自動で ON にすることはありません。
この判定だけでポートは開きません。利用者ホームの `.yaml-design-editor-locks` に空のロックファイルを置き、ワークスペースの構成は変えません。
終了後も空のファイルは残ります。手動削除による解除は行わないでください。
保護対象は同じ OS 利用者・同じルートの本ツール同士です。他のエディタや別 PC の書込を防ぐものではありません。

## 接続者と権限

ワークスペースを開いて「接続者を追加」を押し、接続名・機能・許可範囲を入力して「登録権限を保存」を押します。
権限は、そのワークスペースだけに結び付きます。
API を呼び出す場合は「利用する機能」で API を選んでください。有効にしている機能が一つだけなら、新規登録ではその機能を最初に選択します。
登録後は「接続名 / API」のように機能を表示します。既存の接続者の機能は変えられないため、別の機能を使う場合はその機能の接続者を追加します。

### 簡単設定

新しい接続者では「簡単設定」で全体の閲覧だけを許可する初期値にします。接続名と利用する機能を選べば、文書パスの入力なしで登録できます。
対象は、そのワークスペースの保存済み YAML 文書全体です。スキーマ・ビューなどの定義と構成情報、今後追加する文書も含みます。実行記録や一般の添付ファイルは対象外です。
文書の追加だけでは登録権限を変更しないため、有効な同じトークンを使い続けられます。未保存の編集は公開しません。
変更権限は初期値で全て OFF です。必要に応じて「変更提案を許可（デスクトップで承認）」「直接確定を許可（外部ツールで保存）」「選択した業務操作を許可」を独立して追加できます。
変更範囲は今後追加する文書を含む業務データ全体で、定義・構成は対象外です。業務操作は「業務操作を選択」で名前を明示選択し、後から追加する操作名は自動許可しません。
直接確定と業務操作はデスクトップの承認を待たずに保存できます。提案の承認はデスクトップで行います。[API による変更](local-api-changes.md) に両方式の利用例があります。

既存の文書指定の登録は、自動で簡単設定へ切り替わりません。「権限を編集」から切り替えると、全体閲覧への変更と変更権限の解除を確認します。
切替後も「登録権限を保存」を押すまでは登録へ反映しません。保存する対象ワークスペースと権限の要約を確認してください。

### 詳細設定

「詳細設定」では閲覧範囲を「指定した文書のみ」または「ワークスペース全体（今後の追加を含む）」から選べます。
指定文書の欄では「文書を選択」を押し、文書ツリーのチェック、相対パスでの検索、検索結果の一括選択を使えます。「選択を反映」で入力欄へ戻り、登録権限を保存すると確定します。
フォルダーのチェックも、その時点の具体的な文書一覧として保存します。後から追加する文書は自動許可しません。
「一覧を再読込」は候補だけを更新し、選択済みの範囲を広げません。候補には入力済みの指定も残すため、未作成・削除済みの文書の指定も確認・解除できます。

| 入力欄 | 意味 |
|---|---|
| 閲覧する文書 | 読み取りを許可する文書 |
| 変更提案する文書 | 作業コピーで変更し、承認待ちとして提出できる文書 |
| 直接確定する文書 | 作業コピーから外部ツールが保存できる文書 |
| 業務操作の対象文書 | 定義済みの業務操作を適用できる文書 |
| 許可する業務操作名 | 適用を許可する操作の名前 |

文書は `orders/order-001.yaml` のようなワークスペース相対のパスを、1 行に 1 件直接入力することもできます。操作名も 1 行に 1 件です。
指定文書の空欄は許可なしです。選択画面で指定した変更対象は閲覧にも追加します。変更の計算には定義と影響先を含む全入力文書の閲覧が必要です。
変更範囲ごとに「業務データ全体」を選ぶこともできます。この指定は今後の追加を含むため、全体閲覧を選んでください。
業務操作には対象範囲と操作名の両方が必要です。全体閲覧だけでは変更権限を付けません。詳細設定でも操作一覧から選択できます。
提案の許可と直接確定の許可は独立しています。旧設定からの更新では直接確定を許可しません。他のワークスペースへ移動する権限は付与されません。

「権限を編集」で登録を変更すると、旧資格情報は失効します。「登録を削除」では確認後に登録と権限を削除します。
提出済みの作業自体は残りますが、登録を削除した接続者の提案は承認できなくなります。

## トークンの発行と失効

API・MCP を有効にし、登録したワークスペースを開いた状態で「トークンを発行」を押します。
発行には、接続者に登録した機能が「稼働中」であることが必要です。API が ON でも、MCP 用の登録のトークンは MCP が停止中なら発行できません。
ボタンが無効な場合は、その登録の近くに理由と対処方法を表示します。設定の読込失敗・処理中・別のワークスペース・機能 OFF・起動中・停止中・エラーを確認してください。
API 用に登録したつもりで「接続名 / MCP」と表示されている場合は、「接続者を追加」で API を選んで登録し、その行から発行してください。
「トークンをコピー」で接続先ツールへ渡す値をコピーできます。期限は発行から 8 時間です。
表示を閉じると同じ値は再表示できません。「トークンを再発行」は確認後に旧トークンを失効させます。

「失効」は、登録した権限を残して通信の認証を無効にします。実行中の要求を停止し、開始した保存は結果確定まで待ちます。
再起動・機能 OFF・ワークスペース切替や再読込・権限変更でも資格情報は失効するため、再発行してください。
API のトークンを MCP で使うことはできません。Web のログインとセッション発行は Web 画面の公開後に利用できます。

## API の読み取り

ワークスペースを開き、API を ON にして、API 用の接続者を登録します。全体を閲覧する場合は「簡単設定」のままで使えます。発行したトークンを `Authorization: Bearer …` ヘッダーに付けて接続してください。
アドレスは設定画面に表示される `http://127.0.0.1:ポート/api/v1` です。ブラウザのアドレス欄や URL のパラメーターにトークンを入れないでください。

PowerShell では次のように一覧を取得できます。ポートを変更した場合は表示に合わせます。

```powershell
$base = 'http://127.0.0.1:18765/api/v1'
$token = Read-Host '発行した API トークンを貼り付けてください'
$headers = @{ Authorization = "Bearer $token" }
Invoke-RestMethod "$base/documents" -Headers $headers
```

| GET の経路 | 主なパラメーター | 返す内容 |
|---|---|---|
| `/workspace` | なし | 閲覧できる保存済み文書の件数 |
| `/documents` | `offset`・`limit` | 文書 ID と本文ハッシュの一覧 |
| `/document` | `document` 必須 | 文書 ID・本文ハッシュ・原本の YAML テキスト |
| `/search` | `q` 必須、`offset`・`limit` | キーと値の部分一致による検索結果と原本座標 |
| `/entity` | `id` 必須 | エンティティの側面・項目・値と原本座標 |
| `/views` | `offset`・`limit` | ビューの一覧と API での対応可否 |
| `/actions` | `offset`・`limit` | 保存済みの定義済み操作（実行には操作名の許可が必要） |
| `/view` | `id` 必須、`date`・`offset`・`limit` | 表・クロス集計・ダッシュボード・チャートの結果 |
| `/validation` | `document`、`offset`・`limit` | 文書ごとの指摘と判定保留 |
| `/openapi.json` | なし | 応答の型と要求条件を記述した OpenAPI 契約 |

`document` はワークスペース相対の文書 ID です。文書の存在を含め、閲覧を許可していない文書は開示しません。
検索・一覧は許可文書だけを対象にします。検索は大文字・小文字を区別しない部分一致で、任意のクエリ式や参照検索は受け付けません。
エンティティ・ビュー・検証・操作カタログは、定義や構成も含むすべての入力 YAML への閲覧権限が必要です。現在は部分権限での派生結果を提供しません。
実行記録の領域は対象外です。文書を個別指定して定義ファイルを外した場合や、新しい文書を追加して未許可の入力が増えた場合も派生結果は拒否します。全体閲覧では追加した入力も閲覧範囲に含みます。

成功応答は `workspaceId`・`epoch`・`revision`・`data` を持ちます。`revision` は閲覧可能な保存済み本文から求める版で、未保存編集や作業コピーの変更では変わりません。
本文・索引・参照・検証・ビューは同じ保存済みスナップショットを使います。読み取り中に保存・切替・権限変更があれば成功として返さず、再取得を求めます。
複数ページや複数の経路を同じ版として読む場合は、最初の応答の `epoch` も照合し、後続の要求へ `revision` を渡してください。版が変わったら最初から取得します。
`origin` は文書 ID と文書内のパスです。集計セルは導出情報、ダッシュボードは行とセルの原本座標、チャートは元の表の ID を返します。

一覧の `limit` は既定 50・最大 200、`offset` は 0〜10000 です。`nextOffset` があれば続きがあります。取得位置の上限で続きが返せない場合は `truncated: true` です。
表の `definitionLimit` は定義側の打ち切りで、API のページサイズとは別です。ダッシュボードとチャートはページ分割せず、`offset=0`・`limit=50` の既定値だけを受け付けます。
ダッシュボードの基準日は `date=2026-11-01` のように指定し、省略時はアプリの当日です。
未対応のビューは一覧に理由を示し、取得は拒否します。定義エラーはデスクトップで確認・修正してください。

原本テキストは YAML ストリーム全体を返し、索引・検索・ビューは先頭ドキュメントを対象にします。
検証は指摘と判定保留を別々に返します。指摘が空でも、すべての検査が充足した意味にはしません。
実ファイルの存在は YAML の版に含まれないため検査せず、`fileExistence: not_checked` を明示します。通常のデスクトップ検証で確認してください。
JSON で表せない非有限数は文字列です。値がない場合や解決不能の説明は、原本座標・導出情報・保留理由と併せて読んでください。

読取は同時 2 件、取得対象の YAML は 10000 文書・合計 32 MiB、応答は 4 MiB が上限です。計算は 15 秒を目安に取消を確認しますが、実行中の同期処理の終了までは待つことがあります。
上限を超えた応答は途中までの成功にはせず拒否します。ページを小さくするか、対象ワークスペースを分けてください。

| HTTP 状態 | 対処 |
|---|---|
| 400 | パラメーターの誤り・重複・未対応の指定を修正 |
| 401 | API 用のトークンを発行し直す |
| 403 | 登録した閲覧権限を確認 |
| 404 | API の稼働状態、文書・ID を確認 |
| 409 | 保存版や世代が変わったため最初から再取得 |
| 413 | 文書量・応答量を減らす |
| 422 | 定義の誤りや未対応のビューをデスクトップで確認 |
| 503 | 処理中・同時実行上限・時間超過のため対象を絞って再試行 |

上記の読取経路の失敗は `error.code` と日本語の `error.message` を返します。存在しない経路や API OFF では本文なしの 404 となり、全機能 OFF なら待受自体がなくなります。

## 保存とエラー

接続・常駐の設定と登録権限は、利用者ホームの `.yaml-design-editor-connections/settings.json` に、現在の利用者だけがアクセスできる権限で保存します。
ワークスペースには保存しません。トークンの値・Web セッション・CSRF トークンはメモリだけで保持します。
Windows では保存先と設定ファイルの権限の継承を停止します。フォルダの一覧参照は許容しますが、他の利用者が設定ファイルを読める場合や、フォルダを書き換え・削除できる場合は読み書きを停止します。

設定が破損している場合や保存先を保護できない場合は、全機能を OFF にして設定画面に理由を表示します。
保存先の内容や権限を修復して「設定を再読込」を押すと、ファイルを上書きせず、保存済みの設定を再び反映します。
設定内容を捨てる場合だけ「接続設定を初期化」を確認して実行してください。初期化は保存した接続・常駐設定と登録権限を削除し、提出済みの作業は残します。権限のエラーは初期化では解消しません。
有効化の設定を保存できなければ、待受を開始しません。OFF は保存に失敗しても通信を止めますが、次回起動で以前の保存値に戻るため、原因を解消して「設定保存と接続を再試行」を押してください。
