### 3.3 第2回の重点観点（セッション基盤切替後。2026-08-28 準備）

第2回は通常の台本に加え、**RA-02〜06（アプリ土台のセッション切替）と RB-01（リファクタリングのセッション一本化）による挙動変化**の体感確認を主目的とする。実装側の一致テスト・統合テストは緑（`SessionReadParityTest` / `SessionWriteParityTest` / `AppStateRefactorTest` ほか）＝データが壊れる類の退行は固定済みで、ここで見るのは**操作感と説明性**。台本の付録データ（A-1〜A-8）と幕8のCLIコマンドは 2026-08-28 に現行ビルドでヘッドレス検証済み（validate エラー0・ビュー5行解決＋詳細リンク・検索ヒット・定義ロードエラー0・スキーマ推測動作）。指摘の登録番号は **UX-86 から**。

**意図して変えた挙動（変化に気づいたら「意図どおりか・体感として許容か」を見る）**:

1. **Undo がワークスペース横断の1本**（D-07）: 文書Aを編集→文書Bを編集→Ctrl+Z は**Bが戻る**（従来は開いている文書だけが戻った）。戻った文書が開いていなくても内容は戻っている。連続タイプの合体（1秒窓で1記録）は従来どおり
2. **reload を伴う操作の後は Undo 履歴が空**になる: ファイル作成・改名・削除・エージェント変更セットの適用（幕2・幕4・幕5・幕7 で発生）。従来は文書ごとの履歴が生き残っていた
3. **リファクタリング・一括変更が Undo 1回で戻る**（D-12）: エンティティ改名等の適用・台帳の一括変更は、適用直後の Ctrl+Z で**全ファイルまとめて**戻る（戻した状態は未保存＝●付き。確定するなら保存）。従来は Undo 不可だった
4. **ファイル改名は参照書き換えと1トランザクション**: 旧実装の「移動は成功したが参照書き換えに失敗」の中間状態が構造的に無くなった（D-09）
5. dirty（●）・保存ボタン活性・「見たまま判定」の**供給元がセッションに変わった**（挙動は同一のはず——違和感・追随漏れがあればそれ自体が指摘）

**追加プローブ（台本の該当幕に差し込む小手順。計10分程度）**:

- **P1（幕3の後）横断 Undo**: `issues/00-issues.yaml` の概要を1箇所直す →続けて `members/00-members.yaml` の氏名を直す → Ctrl+Z を2回 → 氏名→概要の順に戻ること。連続タイプ→Ctrl+Z 1回でひとまとまり戻ることも見る
- **P2（幕4の後）エンティティ改名の Undo**: エンティティページの操作メニューで ISS-001 を `ISS-101` へ改名（プレビュー→適用）→ 一覧と詳細文書の id が書き換わったことを確認（ファイル名 `ISS-001.yaml` は変わらない＝従来どおり）→ **Ctrl+Z 1回**で全ファイル戻る（●付き）→ すべて保存で確定復元。プレビューの件数・対象ファイル表示に不足がないかも見る
- **P3（幕5の後）一括変更の Undo**: ～~~課題の priority を一括変更~~（**訂正 2026-09-02**: 一括変更はファイル単位の**ルート直下スカラーキー**が対象（R8-05 L-07）で、S1 の課題台帳＝1ファイル内の配列要素には適用できない。本プローブは台本不備＝UX-94 登録。Undo 1回の挙動自体は P2 で確認できる）
- **P4（幕5の後）改名の影響プレビュー**: ツリーで `issues/00-issues.yaml` を `01-issues.yaml` へ改名しようとし、ダイアログに**ビュー「issue-catalog」の fileGlob・newRow.file が対象外になる警告**が出ることを確認してキャンセル（このワークスペースにはパスIDの文書参照が無いため書き換え予告は出ない＝それで正しい）
- **P5（幕7の後）適用と履歴**: エージェント変更セットの適用後に Ctrl+Z を押し、**何も戻らない**（適用は Undo 不可・履歴もリセット＝上記2）ことの体感を記録する（「戻せると思ったのに」感が強ければ登録）

### 3.5 第3回の重点観点（場所の表し方の統一後。2026-09-22 準備）

P27 段D の D-d・D-e（R27-21。ARCHITECTURE §4.48・意図的差分 D-38）で、画面が索引・検証・ビューから受け取る「場所」が、ファイルの絶対パスから、ワークスペース相対の文書ID に変わった。**利用者から見える挙動は変えていない**——ので、見るのは「今までどおり動くか」。ヘッドレスの出力（root の CLI の 190 の出力）は変更前と完全に一致し、全テストは緑だが、画面（Compose）は自動テストがほとんど無い。特に、場所どうしの比較（「この文書か・他の文書か」）は、型を取り違えてもコンパイルが通ってしまうので、手で確かめる価値が高い。

確認は、通常の台本（S1）でも、`labs/sysdev-template` を開いての抜き取りでもよい（以下は `labs/sysdev-template` での例。15分程度）。

- **Q1 ジャンプ（他の文書へ）**: `10_requirements/usecases/UC-001.yaml` を開き、参照の項目（ビジネスルール・画面など）の ↗ から参照先へ飛ぶ → 参照先の文書が開き、対象の要素が強調される。Alt+← で戻れる
- **Q2 被参照（右パネル「関係」）**: `00_input/business-rules.yaml` で BR-001 を選ぶ → 被参照の一覧に、参照元の要素（ID・タイトル）と、相対パスが出る。行を押すと、参照元の文書の、その参照の場所へ飛ぶ。**同じ文書の中からの参照と、他の文書からの参照の区別**（「この文書」の印・他の文書だけを数える件数）が今までどおりか
- **Q3 検証パネルの対応**: `30_basic-design/screens/SCR-RESERVE-DETAIL.yaml` の警告（関係「field-basic」の被参照が不足）の対応メニューから「参照の追加先を開く: …」を押す → 案内された文書が開く。`10_requirements/usecases/UC-003.yaml` の案内（報告先: 定義出現 `10_requirements/usecase-list.yaml`）の文面も見る。表示される場所が、相対パス（`10_requirements/usecase-list.yaml` のような形）であること（絶対パスが出ていたら指摘）
- **Q4 未保存の編集の「見たまま判定」**: `30_basic-design/screen-list.yaml` で画面の ID を1つ書き換える（保存しない）→ その ID を参照している文書を開くと、参照が未解決の警告になる／元に戻す（Ctrl+Z）と消える。書き換えた文書に ● が付き、Ctrl+Z で ● が消える
- **Q5 ビューのグリッド**: 台帳スペースでビュー（`br-trace`・`test-matrix` など）を開く → 行が出る・セルを押すと原本の文書のその場所へ飛ぶ・セルを編集すると、原本の文書に ● が付く（保存で確定）。場所（相対パス ／ パス）が文字で出るのは、計算列のセルのメニュー（「導出規則へ」「入力値へ」の副題）だけ（第3回の訂正。普通のセルには場所の表示が無い＝UX-122）。詳細文書のある行の「詳細を開く」
- **Q6 ID 横ぐし／エンティティページ**: BR-001 や SCR-ROOM-LIST のエンティティページを開く → 出現の一覧（定義・詳細化）・参照・被参照・検査の状況が出る。各行から、その文書へ飛べる。重複所有の案内が出る場合は、相手の文書が相対パスで示される
- **Q7 AI 生成ダイアログ（API キーがあれば）**: フォームの ✨ から生成 → 参考にする文書の候補に、関連する文書（参照先・参照元）が「関連」として上がっている・プレビューの検証（指摘の件数）が出る・適用できる。キーが無ければ、ダイアログを開いて候補の一覧だけ見る
- **Q8 開く・再読込の体感**: ワークスペースを開く／ツールバーの再読込。読み込みが1回になったので、わずかに速くなっているはず（遅くなった・固まる、があれば指摘）。未保存の編集がある状態で再読込しても、編集（●）が残る
- **Q9 新しい文書の作成と Undo**: 詳細文書の作成（検証パネルの「詳細文書を作成」。`labs/sysdev-template` では出ない＝S1 の課題台帳で）や、ビューの「行を追加」（ビュー定義に `newRow:` があるビューだけに出る。`labs/sysdev-template` の3つのビューには無い＝UX-124。S1 の `_views/issue-catalog.yaml` にはある）→ 文書ができて開く／行が足されて ● が付く → Ctrl+Z で戻る（R29-09 の挙動のまま）

気になった点は、今までどおり [BACKLOG.md](../BACKLOG.md) へ（第3回で UX-120〜124 を登録。次の番号は UX-125）。
