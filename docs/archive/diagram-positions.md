# flow・lens の手動位置の実装記録

2026-11-03。利用者との議論で、手動位置を先に与えて未固定だけを自動配置すること、
ワークスペース内に保存して `_views` へ動的情報を混ぜないこと、形式の版番号と過去形式の読込を持たないことを確認した。
現在の仕様は [図の手動位置](../architecture/diagram-positions.md)、決定は [ADR-0021](../decisions/0021-workspace-diagram-positions.md)。

## 配置エンジンの確認

使用中の ELK 0.12.0 で小さなグラフを実行し、固定前後の座標と辺の出力を比較した。
検証プログラムの 18 アサーションが通った。

- stress の固定は interactive を有効にし、連結成分の別配置を止めると保たれるが、全体の平行移動の補正が必要。
- 既定の初期位置・成分の詰め直し・spore の重なり除去は固定位置を変える。
- layered の interactive 指定だけでは任意の x/y を保持しない。
- noLayout は接続辺で例外になるか、辺も除外すると経路を返さない。
- fixed は全ノードを据え置き、未固定だけの配置にならない。radial も同じ固定指定では座標を保たない。

固定位置を先に障害物として置く配置と直交経路探索を別の小さな試作で確認し、
負の座標・自由ノード・レーン内・戻り線・自己ループの 11 アサーションが通った。
これを共通の固定優先配置として Kotlin に実装した。固定が無い場合の既存の配置は維持した。

## 実行結果

- `gradlew test --no-daemon --console=plain`: 成功。JVM 側 1,893 件、失敗・エラー・スキップ 0。Web 側 4 件も成功。
- 新規の Canvas 操作テストは flow・lens のドラッグ保存・Esc・画面復帰後の解除を確認した。
- `scripts/docs-lint.sh`: エラーなし。既存の行長・セル等の目安の指摘は 98 件。
- `git diff --check`: エラーなし。
- 調査のための `scratchpad/graph-layout-investigation` は削除した。labs・test-fixtures の原本とオーナーの起動中アプリには手を加えていない。

## 現在位置の保持と明示的な再配置

2026-11-03、利用者の「一つを動かすと他のノードが自動配置される」という指摘を受け、
[ADR-0022](../decisions/0022-stable-diagram-positions.md) で操作を変更した。
ドラッグの確定はプレビューを採用し、周囲のノードと無関係な辺の計算を起動しない。
固定解除はフラグだけを変え、「再配置」で初めて未固定を並べ直す。

記録は `positions` に全ノードの現在位置と `pinned` を持つ形へ変更した。
flow のレーン原点も記録し、初回の自動配置とノード追加の結果も保存する。
保存先・ワークスペースの境界・版番号と旧形式の読込を持たない方針は維持した。
この追加分も Core Calculus の意味評価の外側にある幾何と表示状態で、対象選択と射影の計算は変更していない。

- `FlowPositionsTest` に全表示・両方向での復元とノード追加後の位置保持を追加した。
- `LensPositionsTest` で全配置方式の親子・周囲の位置・追加・開閉・固定フラグを確認した。
- `DiagramPositionUiTest` を複数ノードの flow に広げ、固定解除の直後は動かず、再配置で動くことを検査した。
- Canvas テストが検出した、保存直後に古い配置を書き戻す競合を修正した。再実行で flow・lens の操作テストは通過した。
- オーナーが作成した `samples/diagrams/.yde/state/` は変更していない。
- 最終の `gradlew test --no-daemon --console=plain` は成功。JVM 側 1,895 件、失敗・エラー・スキップ 0、Web 側 4 件も成功した。
- 固定フラグだけの変更でもドラッグの確定処理を通し、配置計算中の再読込では処理中の状態を解除する。flow の固定件数は常設行にして、最初の固定で図の領域がずれないようにした。
- 文書同期後の docs-lint は失敗なし（既存の目安 98 件）、`git diff --check` もエラーなし。

## 移動後の配線

2026-11-03、現在位置の保持までを `37108c4` にコミットした後、人物カードの初期・移動後・再配置後の画像に基づいて配線を改善した。
移動時には方向を問わず上下に折る簡略処理、再配置時には戻り線も進行方向の出口へ強制する処理があり、見え方が揃っていなかった。

- `OrthogonalRouting` に接続面・短い直交線・障害物探索・ラベル追従を集約した。移動前の接続面を優先し、相手を通り越した場合は向かい合う面へ切り替える。
- 探索は進入軸を状態に含めて長さと折れ数を評価する。狭い隙間で逆走せず、小さな寸法差による短い段差は揃える。
- flow のドラッグは新たに遮られた辺も引き直し、それ以外の辺と周囲のノードは保持する。レンズの既存直交線も移動時に直交を維持する。
- ラベルは線分の近くの空きを選び、短い線では折れ点付近も候補にする。遠くへ置かれる退行を距離の検査で防ぐ。
- `FlowRoutingTest` の計算結果から比較用の簡易図を生成し、折れ方とラベル位置を確認した。OS の画面取得・ポインタ操作は行っていない。
- `OrthogonalRoutingTest` は横向き・戻り線・障害物・自己ループ・狭い隙間・段差・レンズの移動を検査する。
- 意味の対象選択・射影と保存形式は変更していない。Core Calculus の意味評価の外側である幾何の調整に閉じた。
- 最終の `gradlew test --no-daemon --console=plain` は成功。JVM 側 1,901 件、失敗・エラー・スキップ 0、Web 側 4 件も成功した。
- docs-lint は失敗なし（既存の目安 98 件）、`git diff --check` もエラーなし。比較用の `scratchpad/diagram-routing` は確認後に削除した。
