# ADR-0037: 定義に書ける語の仕様を devtrack に持ち、今の実装の記述としてテストで実装に結ぶ

- 日付: 2026-11-16
- 状態: 承認済み

## 文脈

定義（スキーマ・ビュー・検査・操作など）に書ける語は、4 か所に分かれていた。読み取りの実装（Kotlin）、メタスキーマ、利用者向けの manual、設計の architecture である。
実際に読む語を決めるのは実装で、メタスキーマは検証とフォームのためにそれを写し、manual は使い方を説明する。どれも「書ける語の一覧」ではなく、次のことが起きていた。

- 実装が読むのにメタスキーマに無い語がある。メタスキーマが形を決めていない場所（型が any で、形は説明文だけ）が多い。
- 種類ごとに書ける語の決まりや、値の式・クエリ・変換のひな型の語は、実装にしか無い。
- manual の表に載っていない語がある。
- ずれを機械で見つける仕組みは、項目定義と操作の一部にしか無かった。

オーナーの方針は、仕様を本ツール自身で管理し、開発管理（devtrack）と一括で扱うことである。

## 決定

- **原本は devtrack の `spec/`**: 定義に書ける語の仕様を、devtrack のワークスペースの文書として持つ。位置（語を書ける場所）・語（1 つの位置に書けるキー 1 つ）・スキーマの種類・基底の種類を、1 件 1 ファイルの YAML で書く。独立のワークスペースにはしない（機能・指摘・ロードマップと参照で結ぶため）。
- **今の実装の記述**: 仕様は「今の実装が読むもの」を書く。実装より先に仕様を決める文書にはしない。語彙を変えるコミットでは、実装・メタスキーマと同じコミットで仕様の語も直す。
- **テストで実装に結ぶ**: 位置ごとに、突き合わせる相手を宣言する。メタスキーマが形を決めている位置は、メタスキーマの中の場所（語と必須が同じこと）。決めていない位置は、読み取りの実装が持つキーの集まりと列挙（語が同じこと）。実装は読むがメタスキーマに無い語は、分かっているずれとして位置に並べ、指摘を登録する。
- **ID は名前で付ける**: 位置は `CTX-` と名前、語は `KW-` と位置の名前とキー。番号を振らない（並行する作業で重ならないように）。
- **読む文書は生成物**: `docs/spec/` の参照文書は、devtrack のレポートで生成する。直接直さない。生成と、最新かどうかの確認は、台帳（BACKLOG・FEATURES・ROADMAP）と同じ仕組みに乗せる。
- **役割の分担**: 仕様は「何が書けるか」（語・書ける場所・値の形・必須・省いたとき・決まり）を短く持つ。使い方と例の説明は manual、実装の構造は architecture が持つ。メタスキーマは検証とフォームのための定義のままで、仕様から生成しない。

## 既存の決定との関係

既存の決定は変えない。
開発管理を devtrack のワークスペースで行い、台帳を生成物にする運用に、仕様を足す。
Core Calculus（ADR-0009）の「プリミティブ・組込みの定義・利用者の定義」の層のうち、利用者が定義に書く表面の語を、仕様が一覧にする。

## 影響

- 語彙を足す・変えるときの確認先が 1 つ増える（CONVENTIONS「スキーマ語彙と編集UIの同期」）。食い違いは repo-tests の `SpecTest` が止める。
- テストが見るのは、語の有無と必須までである。語の意味の文面、種類ごとの使い分け、値の形は、人が実装とメタスキーマを読んで書いたもので、機械では確かめていない。
- 定義の言語に版の印を持つかどうかは、この決定に含めない（指摘として判断を待つ）。
