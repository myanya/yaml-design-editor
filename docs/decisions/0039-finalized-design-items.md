# ADR-0039: 導出・補正と指定・追加を合成して確定項目一覧を作り、ビューと後段の生成で共有する

- 日付: 2026-11-16
- 状態: 方針合意。確定項目一覧への移行は未実装。エンティティ定義書の属性と画面構成はレビュー中

## 文脈

エンティティの項目に共通型への参照を持たせた結果、項目自身を読むフォームと、共通型をたどるビューで値が異なった。
基底の種類と項目固有の制限を保持する修正後も、最大文字数などの継承値はフォームに無く、ビューが個別に解決している。
補正後の値を後段へ渡す処理も、ビューから設計情報を組み立て直している。

オーナーの意図は、業務モデルから設計情報を導出し、補正・指定とアーキテクチャによる追加を反映した同じ設計情報を、複数の観点でレビューすることである。
表示箇所ごとの修正ではなく、設計情報を確定する処理を共通化する。

## 決定

### 管理する入力と出力

| 分類 | 内容 |
|---|---|
| 導出項目一覧 | 業務モデルから機械的に作る設計項目。型への参照、個別に明記された指定、導出元を保持する |
| 補正・指定項目一覧 | 既存項目の値の修正と、方式・対象・既存項目の利用などの設計上の指定 |
| 追加項目一覧 | 新しい設計項目。人が書く追加と規則が生成する追加を区別し、生成で手書き部分を上書きしない |
| 確定項目一覧 | 上記を合成し、型・参照・成立条件を検証した生成物。レビュー用ビューと後段の生成の共通入力 |

分類と作成元は別である。アーキテクチャ規則も、既存項目の変更と新しい項目の追加の両方を出せる。
値は YDE の標準の書き方を保ち、説明の文へ置き換えない。

### 変換の順序

1. **準備**: 導出項目と手書きの追加をそろえ、規則の適用方式・対象・利用する既存項目を決める。
2. **展開**: 規則が追加・変更の候補と成立条件を生成する。規則が読む指定は、その規則の実行前に確定させる。
3. **確定**: 個別補正を合わせ、競合を解決し、型と参照を解決して成立条件を検査する。

規則間の依存関係を明示し、依存先の結果を読んで有限の段階で実行する。
依存しない規則は同じ段階の入力から候補を作り、その後に合成する。ファイル名の順番を優先順位にしない。
処理の依存が循環したら定義の誤りとし、結果が変わらなくなるまでの反復は導入しない。
業務エンティティの相互参照は処理の循環とは別に扱う。
再生成は入力から計算し直し、前回の生成結果に変更を継ぎ足さない。

### 明記と継承

共通型と値が等しくても、項目に明記された制約は保持する。現在の値の差だけで明記の有無を判断しない。
例えば、共通型が最大 100 文字で項目にも最大 100 と明記されていれば、共通型を 200 に補正しても項目は 100 のままである。
個別の指定が無い項目は、補正後の共通型の 200 を継承する。

補正を適用する処理と、型の意味に従って制約を合成する処理は分ける。
型の制約は既存の YDE の狭める規則に従い、名称や初期値の置き換えと同じ優先順位だけでは決めない。

### 既存項目の利用

アーキテクチャ規則が既存項目を使うときは、使う項目を明示的に指定する。
同じ名前や型であることだけを理由に兼用しない。
指定がなければ専用項目を追加し、ID やキーが衝突すれば指摘する。
指定があれば追加を省き、その項目が方式の成立条件を満たすか検査する。

### 競合と成立条件

| 状況 | 扱い |
|---|---|
| 規則の既定値と個別指定 | 個別指定を採用する |
| 異なる個別指定が同じ属性を変更する | 競合として指摘する |
| 複数規則が同じ属性に異なる既定値を出す | 競合として指摘し、個別指定で採用値を明示すれば解決できる |
| 複数規則が同じ属性に同じ値を出す | 値は一つにまとめ、すべての出どころを残す |
| 新しい項目の ID やキーが重複する | 値の一致だけでは統合せず、重複として指摘する |
| 補正対象が無くなる | 対象のない補正として指摘する |

規則が出す既定値と、その方式の成立条件を分ける。
個別指定は既定値の競合を解決できるが、成立条件を免除するものではない。
例えば版番号方式の楽観ロックでは、項目の表示名を変えることと、版の照合・更新が成立しなくなる変更は区別する。
補正後にすべての成立条件を検査する。

### 確定項目とビュー

確定項目一覧は YAML の生成物として保存する。人は入力を変更し、確定項目を再生成する。
論理型への参照を残すとともに、各項目に適用する基底・制約などを解決した値として保持する。
値ごとに導出元・継承元・補正・規則を追えるようにする。

個別ビュー、横断ビュー、後段の生成は同じ確定値を読む。
ビューは対象選択・並べ方・集計・表示形式を担い、型の継承や補正の優先順位を独自に決めない。
「制限なし」「対象外」「解決できていない」を区別し、数値などの値そのものへ表示用の文字を混ぜない。
確定は変換と検証の状態であり、オーナーのレビュー完了とは別である。

## 既存の決定との関係

- ADR-0034 の段階的な詳細化と出どころの保持を継続する。規則をファイル名順で適用する方式は、この設計項目の合成では依存関係と競合検査に置き換える。
- ADR-0035 の設計項目・人が書く補正・ビューという分担を継続する。ビューごとに補正を重ねる方式は、確定項目を生成して共有する方式に置き換える。
- ADR-0036 の論理型と型対応表を継続する。型の性質をビューが解決する方式は、確定項目の生成時に解決する方式に置き換える。
- ADR-0038 の項目固有の制限と後段への反映を継続する。共通型との差だけを保持する方式と、ビューから後段用のモデルを再構築する方式を見直す。

この決定は移行先の方針であり、現在のサンプルが確定項目一覧へ移行済みであることを意味しない。
対象属性・保存構造・ビューの構成・確認例は、[エンティティ定義書の見直し案](../../samples/todos-sysdev/docs/entity-definition-plan.md)でレビューする。
条件付き必須・項目間の業務規則、CRUD の R/D への拡張は引き続き保留する。
