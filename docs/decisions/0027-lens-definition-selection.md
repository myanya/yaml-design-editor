# ADR-0027: レンズの定義に箱の絞り込みを持たせる

- 日付: 2026-11-07
- 状態: 承認済み

## 文脈

レンズの定義（`kind: lens`）は、記法と矢印の向きだけを持っていた。
型・関係の絞り込みと起点・畳みは画面の操作で、定義には持たせない決まりだった（architecture/views.md の規律）。
開発管理（devtrack）でレンズを見ると、終わった指摘と残っている指摘が同じ型に混ざって区別しにくかった。
型の絞り込みでは、同じ型の中の状態で分けられない。
「状態が終わったものを隠す」「残っているものだけ見せる」は、その型の値を知るワークスペースで決まる。
毎回の画面操作でなく、記法と一緒に共有したい。

## 決定

- レンズの定義は、記法と矢印に加えて箱の絞り込み（`filters`）を持てる。絞り込みは定義の中で名前（`id`・`label`）を持つ。
- 絞り込みには 2 つの向きがある。`hide` は条件に合う箱を隠し、`show` は条件に合う箱だけを見せる。
  対象（段 `level`・エンティティ型 `entityType`）の外の箱には効かない。
- 条件は変換の `$when` と同じ書き方で、同じ評価器（`SemanticTransform.holds`）で評価する。
  入力は記法と同じ箱の材料（`id`・`title`・`entityType`・`data`）。値が無くて決められない条件は成り立たない。
- 入れるか外すかは画面の操作で、画面の覚えに持つ。覚えが無ければ定義の `default` に従う。
  入っている絞り込みのどれかが隠す箱は隠す。起点は隠さない。隠した箱につながる線は描かない。
- 絞り込みを持つ定義は、記法を持つ定義と同じく画面の「見え方」で一つ選ぶ。
  記法も絞り込みも持たない定義（矢印だけ）は、従来どおり全部を合わせて読む。
- 定義が決めるのは見え方と選択の既定までにする。画面の操作（型・関係のチェック・起点・深さ・畳み）は残し、定義より優先する。

## 計算体系の確認

対象は既存のグラフが選ぶ箱で、新しいクエリは作らない。判定は Predicate で、変換の条件と同じ評価器を使う。
入力は記法と同じ Construct の材料で、原本の値をそのまま読む。結果は表示の選択だけで、書込経路を作らない。
同じ定義・入力・入れた絞り込みから、同じ箱が残る。

## 既存の決定との関係

architecture/views.md の規律「節点の選択は画面の操作のままで、定義に持たせない」を上書きする。
定義は選択の既定を持てる。ただし選択の操作は画面に残し、定義が操作を封じることはしない。
ADR-0020 の「見え方を持つレンズ定義は名前で一つ選ぶ」は維持し、絞り込みを持つ定義も同じ選び方に入れる。
矢印だけの定義の扱いは変えない。

## 影響

絞り込みの型は semantic-core（`LensViews.kt`）、読み取りは workspace-core の `ViewDefinitions`、画面の切り替えは desktop のレンズに置く。
スキーマ・関係レジストリには見え方を足さない。今後、既定の配置や既定で隠す関係を定義に足すときも、この決定の範囲で `kind: lens` の語彙として足す。
