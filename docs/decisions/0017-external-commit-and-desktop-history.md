# ADR-0017: 外部の確定とデスクトップの取り消しを分ける

- 日付: 2026-10-31
- 状態: 承認済み
- 上書き対象: ADR-0016 の「外部からの適用も既存の編集用セッションと単一履歴へ載せる」のうち Undo 対象とする部分

## 決定

Web・API・MCP には Undo/Redo を公開しない。単発の業務操作は確認して確定し、複数の変更は作業コピーを保存（確定）または破棄する。
承認が必要な提案は提出後、人の承認を経て確定する。確定の指示で権限・承認を迂回しない。
外部確定はデスクトップの Undo 対象に追加しない。確定後の訂正は新しい業務操作として扱う。
変更の検証・適用は既存のカーネルの経路を使い、履歴の扱いのために入口ごとの書込経路を増やさない。

- 通常の文書更新では、変更文書に触れる以前の Undo/Redo を適用不可にする。履歴全体は削除しない。
- 判定は文書単位。同じ文書の別項目も競合とし、項目単位の再配置や差分併合は行わない。
- 複数文書を変更する一手は、対象の一文書でも競合すれば一手全体を拒否する。
- 履歴の順序を維持し、競合する一手で止まる。古い無関係な一手へ飛び越える選択的 Undo は初期版に含めない。
- 外部確定後の新しいデスクトップ編集は通常どおり Undo/Redo できる。外部確定だけを理由に無関係な Redo を消さない。
- スキーマ・配置ルールなど履歴の前提を広く変える更新を外部から許可する場合、初期版はそれ以前の全履歴を適用不可にする。
- 対象に未保存編集・未反映入力・壊れた下書きがあれば、外部からの確定を拒否する。
- 保存失敗や結果不明を確定成功と扱わない。作業単位の確定と、複数ファイルのディスク書込全体の原子性は区別する。

例えば A、B、C の順で編集・保存後に外部から B が更新された場合、C は Undo でき、B で停止する。A の記録は残るが B を飛ばして戻さない。
画面には止まった理由と対象文書を示す。履歴があることと、次の一手を実行できることを区別する。

## 影響

共通状態の所有を移す作業では既存のデスクトップ編集と外部ファイル変更の挙動を維持する。
この外部確定の契約は ROADMAP の操作計画・適用の共通化で実装し、接続の業務更新を公開する前に検証する。
内蔵エージェントの既存レビュー適用を、この決定だけで外部接続の確定へ変更しない。
