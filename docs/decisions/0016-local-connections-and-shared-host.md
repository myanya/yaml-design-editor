# ADR-0016: ローカル接続を組込みサーバへ集約し、編集状態を入口間で共有する

- 日付: 2026-10-31
- 状態: 承認済み
- 上書き対象: ADR-0013 の入口構成（単独 mcp モジュール）と提出・承認の所有範囲。カーネルの依存方向・変更セット・単一履歴、ADR-0015 の拡張方針は維持する

## 文脈

同じ PC 内の外部 AI エージェント、自作ツール、業務用ブラウザから YDE を使う。
通常の編集はデスクトップに残し、画面を隠しても処理を維持する。
使わない接続機能が待受ポートを開かないこと、および API・MCP・Web を個別に停止できることを必須とする。
既存の DocumentSession は単一スレッドからの呼出しを前提とし、画面は直接編集と非同期 IO を持つため、HTTP 側だけを排他しても状態を共有できない。

## 決定

### モジュールと寿命

- `local-server`（パッケージ `server`）を追加し、Ktor/CIO と公式 MCP Kotlin SDK をここに閉じる。API・MCP・Web 配信はパッケージで分ける。
- 依存先は app-core とカーネルまで。agent・desktop・cli・形式の拡張を使わない。desktop は local-server を組み立て、cli は必要なクライアントアダプターだけを使う。
- app-core の `app.service` は通信非依存の窓口を持つ。共通の WorkspaceHost が Workspace と DocumentSession を保持し、AppState は同じ状態を受け取る。
- ディスクを映すセッションと編集用セッションは分けたままにする。画面・HTTP・MCP の呼出し順を統一し、最初は既存の DesktopUiDispatcher と IO 中の操作制限に合わせる。
- セッション・監視・実行・接続の寿命をウィンドウの表示と分離する。トレイから表示・承認待ちの確認・完全終了を行えるようにする。
- Web は `web-ui` の React/TypeScript プロジェクトで作り、静的資源を同梱する。利用者に Node を要求しない。評価・検証・変更計画はブラウザへ移さない。
- 別プロセスの daemon、OS サービス、LAN 公開、複数ワークスペースの同時公開はこの決定に含めない。

### 接続の契約

- アプリ設定に API・MCP・Web の独立したスイッチを置く。新規・未設定の旧版からの更新ではすべて OFF。ワークスペースの定義から接続を有効化しない。
- 一つでも ON の場合だけ `127.0.0.1` に一つの待受を作る。既定ポートは 18765、変更は停止中だけ。占有時の自動変更や全 NIC へのバインドをしない。
- API は `/api/v1`、MCP は `/mcp`、Web は `/app` と `/web-api`。Web 用の通信は公開 API のスイッチに依存しないが、認証と業務操作の制限を受ける。
- 希望する設定値と実際の稼働状態を分ける。無効な機能は要求受付時に拒否し、画面だけを隠す実装にしない。
- OFF では新規受付を止め、その機能の接続・ストリーム・認可を失効させる。他の機能は継続する。保存中は結果の確定を待ち、停止完了まで「停止中」とする。
- 最後の OFF で全接続と待受ソケットを解放する。すべて OFF なら検出・health 用の別ポートも開かない。トレイ常駐は接続を暗黙に ON にしない。
- 接続者・機能・ワークスペースに許可を結び、閲覧・提案・許可済み業務操作の適用を分ける。未設定は拒否する。既存 ToolPolicy の空一覧の意味を外部権限へ流用しない。
- ローカルでも資格情報、Host/Origin の検査、CSRF 対策、入力・処理量の制限を設ける。Origin は scheme・port まで照合する。資格情報を URL・ワークスペース・通常ログへ書かない。
- ワークスペース切替で旧作業の対象を付け替えず、新しい対象を既存の接続者へ自動公開しない。
- MCP は Streamable HTTP を使う。stdio 中継は必須外で、追加しても MCP の停止設定を迂回しない。

### 操作と状態の契約

- 外部の通常読取は保存済み、画面は未保存編集込み、外部作業は作業コピー込み。索引と本文を同じ版から取り、ワークスペース ID・起動世代・版を応答する。
- 業務操作は ActionPlanner → ChangeSet → ChangeSetApplier。任意編集は WorkingCopy → 検証 → 提出 → 人の承認を既定とする。定義文書の自由な書換えや任意コード実行を公開しない。
- 画面・外部の適用を既存の単一履歴へ載せる。未保存編集や解析不能の下書きを上書きしない。外部へ任意の全体 Undo を公開しない。
- 計画を入力・対象・時刻・版・権限と結ぶ。前提が変わったら失効させる。要求 ID と内容を照合して二重適用を防ぎ、結果不明・部分保存を成功扱いしない。
- 作業 ID は通信接続の寿命と独立させる。提出済みの差分と結果は復元可能にし、復元時に競合・権限を再検査する。未提出の作業コピーと Undo 履歴の永続化は必須外。
- 提出・承認の共通部分を agent から app-core へ移す。LLM とアクティビティ固有の読込ゲートは agent 側に残し、注入で接続する。
- YDE 間のワークスペース所有は OS ファイルロックで守る。独立 CLI の書込を拒否し、明示した接続では API が ON の場合だけ共通サービスを使う。他のエディタとの排他は保証しない。
- Web はダッシュボード・表・集計・チャート・詳細・参照・検証・レポートと定義済み業務操作を扱う。任意のフォーム・ソース・スキーマ編集はデスクトップで行う。

### 検証と依存

- 通信依存の版は Gradle の version catalog、解決した推移依存は lockfile で管理する。Serialization の変更は既存の AI 応答解析・ツール・CLI の回帰試験も通す。
- 規則テストが local-server の走査、依存方向、Ktor/MCP の隔離、app.service の層を検査する。
- 単体・契約試験はインメモリ通信を優先する。待受の検査だけは試験プロセス自身の loopback と OS が選んだポートを使い、必ず終了する。外部 AI の実 API は呼ばない。
- ON/OFF の全八組合せ、切替競合、既存接続の終了、ポート解放、同梱ランタイムの起動を受入条件とする。

### Core Calculus

通信と接続管理は実行基盤で、業務の評価器を追加しない。
読取は Term/Query、表示値は Expression/Aggregate、前提と検証は Predicate、入力準備は Construct、変更は Rewrite と既存の変更セットへ落とす。
Unknown/Conflict・出どころ・時刻の意味を DTO で失わず、既存の書込経路を共用する。

## 影響

共通状態の移行・権限・所有権がそろうまで、外部の業務操作を有効化しない。
小さな段階で既存編集の回帰を検査できる一方、接続用の認証・状態管理と Web 資源の配布が新しい責務になる。
実装状況と工程は ROADMAP、現在の部品と制約は architecture、利用者の有効化手順は実装後の manual に置く。

## 却下した案

- API・MCP・Web を別プロセス・別ポートにする: 状態と履歴の同期が増え、ローカル利用の初期範囲に不要。
- Web を公開 API の ON に従属させる: 三つの機能を独立に切り替える要件を満たさない。
- 全機能 OFF でも検出用サーバを常駐させる: 未使用時に待受しない要件を満たさない。
- 既存 AppState の状態と独立した HTTP 用編集セッションを作る: 未保存編集・Undo・確認済み計画の整合を保てない。
