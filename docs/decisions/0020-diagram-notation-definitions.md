# ADR-0020: 図の記法を共有するYAML定義にする

- 日付: 2026-11-03
- 状態: 承認済み

## 文脈

人物の画像と名前、クラスの属性と操作などを、レンズとフローで描き分けたい。
対象ごとに描画コードを追加すると、意味の読み取りと配置・描画が重複する。

## 決定

- ビュー領域の `kind: diagram-notation` は、入力契約と変換のひな型から表示モデルを作る定義とする。
- 組込みも利用者も同じ形式と評価器を使う。表示の組み立ては Construct、条件は Predicate、値は Expression に委譲する。
- 表示モデルは文字・画像・枠・並び・線種・端点の記号に閉じ、任意コードを実行しない。
- レンズとフローの意味モデルを統合しない。表示に必要な入力と原本座標を共通モデルへ渡す。
- 記法は意味・参照方向・検査を変更しない。型の参照をUMLの継承と推定しない。
- 入力と出力は構造スキーマで検査し、曖昧な適用や不足を診断する。来歴は変換をまたいで保持する。
- 見え方を持つレンズ定義は名前で一つ選ぶ。従来の矢印だけのレンズ定義は和を取る互換動作を維持する。
- 描画と画像出力は同じ部品を使う。配置は文字・画像の計測後に行い、ELKの型は既存の窓口に閉じる。

## 計算体系の確認

対象は既存のグラフ・クエリが選ぶ。入力と表示の組み立ては `SemanticTransform` が行う。
専用の条件・集計評価器や書込経路は増やさない。変換の出力は派生物で、原本は変更しない。
同じ入力と定義から同じ表示モデルを得る。不足・競合を診断し、来歴で原本へ戻る。
文字の計測・画像読込・配置・描画は意味の評価の外に置く。

## 影響

共通の型はsemantic-core、定義の読み取りはworkspace-core、原本との接続はapp-core、描画はdesktopに置く。
新しいモジュールや、スキーマ・関係レジストリの外観項目は作らない。
レンズの定義が持つ見え方を増やすが、既存の定義の適用方法は変更しない。
