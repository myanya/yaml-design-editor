# ADR-0001: in-repoマルチモジュール方式で3層コアを切り出す

- 日付: 2026-08-16
- 状態: 承認済み

## 文脈

スキーマ（`Schema.kt` ほか）が構造・意味・I/Oの多くを担当しすぎており、3層（yaml-core / semantic-core / workspace-core）へ分離したい。当初は別プロジェクトへの手動移行を計画したが、境界の再設計が実質リライトを超えるリアーキテクチャへ膨らむと判断した。

## 決定

同一リポジトリ内でGradleマルチモジュール化し、コードとテストを機能単位でモジュールへ**移動**する（複製・再実装はしない）。すべてのステップでアプリを含む `./gradlew test` が成功する状態を保つ（strangler方式）。挙動を変える場合は旧経路を残したまま新APIを併設し、利用者を移してから旧経路を撤去する。移行中はパッケージ改名を行わない。

## 帰結

- 移行中も製品が動き続け、既存テストが継続的な検証装置になる。
- 旧経路と新APIの併存期間が生じる。フェーズ完了ごとに撤去して短く保つ。
- 最終的なパッケージ改名（`dev.toros.yde.*`）は移行完了後の独立した機械的変更とする。
