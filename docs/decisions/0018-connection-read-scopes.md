# ADR-0018: 接続権限の全体閲覧と指定文書を分ける

状態: 承認済み（2026-11-01）

## 背景

接続者の権限を文書ごとに列挙する方式では、登録時の入力に加え、文書を追加するたびに権限の更新が必要になる。
ビュー・検証は全入力への閲覧許可を必要とするため、登録時の全選択だけでは継続利用の手間を解消できない。
利用者は簡単設定と詳細設定の併用、および今後追加する文書を含む全体閲覧を選べる方針を承認した。

## 決定

- ADR-0016 の接続者・機能・ワークスペースに結ぶ許可と、未設定の拒否を維持し、閲覧範囲の表現を補足する。
- SELECTED は具体的な相対 DocumentId の集合とし、空集合は許可なし。WORKSPACE はそのワークスペースの外部読取が採取する保存済み YAML 全体とし、今後の追加も含む。
- 全体閲覧は定義・構成情報を含み、未保存編集・実行記録・任意の添付ファイルは含めない。絶対パスやワークスペース外への許可にはならない。
- 全体閲覧を既存の空集合やワイルドカードで表現しない。範囲と対象の判定は app-core の共通権限モデルに置き、API・MCP・Web の入口で別々に解釈しない。
- 簡単設定の初期値は全体の閲覧のみ。既存登録は変更せず、指定文書から簡単設定への切替は全体閲覧への変更と変更権限の解除を確認し、明示保存で反映する。
- 詳細設定の文書・フォルダー選択は具体的な集合へ展開する。候補の再読込や文書追加では、その集合を広げない。
- 設定は version 2 で範囲を保存する。version 1 は SELECTED のまま復元し、読込だけで書き換えない。新形式の欠落・未知の範囲は拒否する。
- 文書の追加は全体閲覧の登録変更ではないため、トークンは維持する。保存版は更新し、取得中の変更は再確認する。権限設定の変更では資格情報を失効させる。
- 閲覧の簡略化で変更権限を付与しない。変更機能の簡単設定は後続の業務操作の開発で接続し、業務データの範囲と操作名の明示選択を分ける。

## 影響

全体閲覧を選んだ接続者は、後から追加された文書も取得できる。対象とこの意味を登録前に表示する。
部分権限で派生結果を提供するための依存閉包の計算は追加せず、全入力の閲覧許可が必要な制約は維持する。
権限の判定は業務の Query / Predicate ではなく、評価の前後で適用する接続基盤の認可である。Core Calculus の値・検証・変更演算や YAML 語彙、保存経路は追加しない。

## 却下した案

- 現在の全ファイルを入力欄へ埋めるだけの簡単設定: 文書追加時の更新が残る。詳細設定の選択補助としてだけ提供する。
- 空欄を全許可として解釈する: 旧設定や未設定の意味を変え、既存登録の権限を広げる。
- 閲覧と任意編集・全業務操作をまとめて許可する: 利用目的を超える変更権限まで暗黙に付与する。
