# ADR-0026: 図の配置の保存は文書の排他を取らず、外部変更の確認も起こさない

- 日付: 2026-11-05
- 状態: 承認済み

## 文脈

ADR-0021 では、位置の保存に既存の IO 排他（`WorkspaceHost.exclusive`）を使うと決めた。
この排他は文書の一括処理のためのもので、取っている間は画面全体に「処理しています」が出て、編集と接続も受け付けない。
図で箱を置くたびに保存するので、置くたびにこの表示がちらついた。
さらに、保存した配置記録（`.yaml`）をファイル監視が拾い、ワークスペース全体の外部変更の確認を画面のスレッドで走らせていた。
labs/aws-webapp（YAML 276 個）では、置くたびに約 3 秒画面が止まった。
索引はもともと状態領域を無視するので、この確認は毎回「変化なし」で終わる。

## 決定

- 位置の保存は文書の排他を取らない。表示状態の書込の順番（`AppState.stateWrites`）で保存どうしを並べる。
- ワークスペースの切替と終了は、この順番を取って書きかけの記録の完了を待つ。そのあとで旧所有権を手放す。
- 保存の前に対象ワークスペースを照合し、読込済み本文との比較と atomic move で書く。これは変えない。
- ファイル監視の知らせのうち状態領域（`WorkspaceLayout.isState`）のものは、入口（`AppState.noteFileEvents`）で外す。外部変更の確認も、排他中の後回しもしない。ファイル一覧の表示だけ新しくする。

## 既存の決定との関係

ADR-0021 のうち「既存の IO 排他を利用」の部分を上書きする。ワークスペースの所有権を使うことと、外部変更を見つけたら保存を止めることは維持する。
状態領域を台帳・文書集合・索引・文書の Undo から外す境界は維持する。今回は、その境界をファイル監視の入口にも当てた。

## 影響

置いても「処理しています」は出ない。保存中も編集・接続を受け付ける。置いたあとに画面が止まるのは、状態ファイルの知らせによる確認がなくなった分だけ減る。
保存中は同じ図で次の箱をつかめないままにした。これを変えるかは BACKLOG で別に判断する。
文書の外部変更の確認そのものの重さ（数百ファイルで約 3 秒）は変えない。BACKLOG UX-256 で扱う。
