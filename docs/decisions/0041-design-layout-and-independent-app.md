# ADR-0041: 設計を段階ごとに配置し、生成アプリを独立したビルドにする

- 日付: 2026-11-20
- 状態: 採用

## 文脈

確定項目への移行後も、エンティティは `design/basic/`、テーブルは `design/detail/`、ほかの設計書は `design/generated/` に置かれている。
基本・詳細という段階と、生成物という役割が同じ階層に混在し、手書き入力と中間結果と確定項目を場所から判断しにくい。
オーナーは基本設計・詳細設計を最上位で分け、その中で入力・導出・合成・確定を分ける構成を選んだ。
生成するソフトウェアも別のディレクトリとし、通常の Spring Boot プロジェクトの形で、YDE 本体のビルドと競合させない。

## 決定

- `design/basic/` と `design/detail/` の配下に `inputs/`・`derived/`・`composed/`・`final/` を置く。
- `inputs/` は人が書く補正・指定・追加・型対応など、残りは生成物とする。
- ビューと後段の生成は各段階の `final/` を読み、ADR-0039 の確定値の共有を維持する。
- 既存の `design/system/` と `design/generated/` は対象の段階と役割で振り分け、ID と根拠を保持する。
- 形式・変換・ビュー・文字のひな形は `.yde/` の各定義ゾーンに置き、段階別の定義と共用の定義を区別する。
- 生成アプリは同じワークスペースの `app/` に置き、独立した Gradle の settings・build・Wrapper・依存版を持つ。
- YDE の `include`・`includeBuild` にアプリを登録せず、YDE の `buildSrc` や版カタログに依存しない。
- `app/` は生成後に単独でテスト・ビルド・起動でき、通常のビルドでは設計 YAML や YDE を読み込まない。
- YDE の単体テストとアプリのビルド・起動を伴う検証は実行経路を分ける。
- Git は現在のリポジトリで管理し、アプリの中に別の Git リポジトリを作らない。

生成コードだけに補正を残さず、業務モデル・設計入力・生成規則へ戻す。
レビュー用 DDL とアプリ用 SQL の出力規則は共有する。生成物の更新対象と競合を検査し、再生成で手書きファイルを消さない。

## 既存の決定との関係

ADR-0035・0036 の設計項目と手書き入力の分担、ADR-0039 の導出・合成・確定の意味は維持する。
それらを具体化したサンプルの旧配置を、この段階別の配置に置き換える。
ADR-0001 の YDE 本体のマルチモジュール構成へ、生成された利用者のアプリを追加するものではない。

この決定は配置とビルドの境界を定める。設計書の内容レビュー完了や、コード生成の実装完了を意味しない。
移行手順、生成の入力、段階ごとの完了条件は [作業計画](../../samples/todos-sysdev/docs/application-generation-plan.md) に置く。
