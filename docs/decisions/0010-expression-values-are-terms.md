# ADR-0010: 式の値は項とし、集合から値への入口を all に限る

- 日付: 2026-09-27
- 状態: 承認済み

## 文脈

[CORE-CALCULUS.md](../CORE-CALCULUS.md) の §4 と §5 は、意味的な計算対象として scalar・sequence・mapping を挙げている。しかし Expression の実装は、比較と指摘の文面のために「文字 1 つ」を値として運び、集計（`sum` / `min` / `max` / `count`）はその上に「場所を指定して集める特殊形式」として足された。

CALC-12（式は σ を固定した単一値の計算・出現集合の量化は述語の側）は、出現集合＝同じ ID が書かれた複数の文書についての決定であり、1 つの項の中の配列を値から外す決定ではなかった。集計の説明に「集合は項の中にだけ現れる」と書いたことで、配列が値ではなく集合として扱われ、`sum` が式の返す配列を受け取れず、要素ごとに式を当てることもできなくなっていた。家計簿の題材（月×費目の金額の合計・収入と支出の 2 つの合計を 1 つの検査に書く）で、この不便が具体的に現れた。

## 決定

- **式の値は項と出どころ**。項は §4 の Term（スカラー・配列・マップ）。読み出しは項をそのまま返し、`[*]` を含むパスは合う場所の値を並べた配列を返す。配列の各要素が出どころを持つ。
- **集計は配列を受け取る関数**。`sum` / `min` / `max` / `count` は引数を先に評価し、配列でなければ得られない。`count` は配列の件数、`length` は文字数。比較・穴埋め・四則演算はスカラーだけを受け取る。
- **集合から値への入口は `all` の 1 つ**。同じ起点の全ての解にわたる形（`{all: {of, in, path}}`）と、起点を固定した照合の形（`{all: {from, match, where, also, of, in, path}}`）。検査の中でも書ける。
- **要素ごとの式は `each`**（`{each: 配列の式, value: 式}`）。各要素を「いまの要素」として値の式を当てる。名前を付けた引数・ラムダ・高階関数・再帰は入れない（§19 のまま）。
- **古い書き方は残さない**。`sum: {of}`・`count: {of}`・`count: {match}` は定義エラーにし、新しい書き方を文面で案内する。
- **CALC-12 の読み直し**。「式は σ を固定して評価し、出現集合の量化を持ち込まない」の意味に戻す。値集合を式に入れないという読みは撤回する。

## 変わらないもの

Query と束縛の表、σ の固定と述語の量化、判定保留の規則（読めない材料が 1 つでもあれば得られない）、出どころを結果に持つこと、計算値の上の計算をしないこと、`refCount` / `occurrenceCount`、制約の `count: {min, max}`（解の組の件数）。

## 帰結

- Expression の語彙は「関数（先に評価）」と「形を受け取る語（`format` `first` `all` `each`）」に分かれる。語を足すときはどちらかを明示する。
- 検査の 1 つの項目に、絞り方の違う複数の合計を書ける（残高の検査）。ビューの列と検査が同じ式を同じ意味で評価する原則は保つ。
- Construct（§26）の「配列の基本操作」のうち、値の計算で足りる部分は Expression の関数が担う。ひな型の指示として値の式を書く形は変えない。
- 実装は ROADMAP の P32 で段階的に進める（文書 → 値の型 → 集計の関数化 → `all` → `each`）。
