# ADR-0038: 項目固有の制限を保持し、補正後の設計項目をビューと後段の生成で共有する

- 日付: 2026-11-16
- 状態: 承認された足場固めの実装方針（エンティティ定義書・テーブル設計書のレビューは継続中）

## 文脈

論理型への集約後、原本の項目一覧では配列以外の基底が空欄になり、項目だけに書いた文字数の制限と組込み text の複数行指定も失われた。
補正は path 列だけに作用し、参照先を読む式と詳細設計の生成は補正前の値を読んでいた。
CRUD は C・U という文字を数値の最大値として集計し、書込の無い項目も行から落ちていた。

## 決定

- ADR-0036 の「項目は論理型への参照と項目そのものの決まりだけを持つ」を変更する。論理型への参照に加え、解決した基底と、共通型と異なる項目固有の制限を保持する。共通の値は引き続き論理型に置く。要素の基底と要素固有の制限も保持する。
  原本の基底は生成時の導出値である。論理型への参照がある場合、ビューと後段はその型の基底を優先し、型を補正したときも有効な型を使う。
- 業務モデルの項には `overrides`（共通型と異なる有効な制限）と `builtinType`（組込み型の共通の性質）を含める。設計用の ID と写し方は YAML の変換で決める。
- 補正の `target` と `set` を Core Calculus の項の変更へ下ろし、原本を変えない読み取り用の木に重ねる。path 列、値の式、照合、参照解決は同じ木を読む。補正と元の値の座標を来歴に残す。ID の追加・削除・変更は補正では行わない。
- 生成の定義に `dependsOn` と `input` を設ける。依存先を同じ計画で先に生成し、`$view` はその新しい結果を読む。`input` は段を当てる前の入力を変換で作る。入力の `stages` に記録済みの段は再適用せず、その先の段だけを当てる。
- テーブルの生成は、補正を重ねた基本設計のエンティティと論理型のビューから入力を作る。項目固有の値を共通型より先に使う。詳細設計の規則はその後に当てる。
- C/U 表は項目と操作を別々に選び、書込の C・U をそのまま読む。数値の集計に置き換えない。`columns.each.rows` は通常のクエリ行と同じ仕組みで列を選び、ダッシュボードの入力も同じ規則で反映する。

## 結果

生成物の最新判定と検証だけでなく、項目一覧・C/U 表の値を原本と照合する。共通型と項目固有の制限、補正、参照先、詳細生成、DDL までの反映を関連テストで確かめる。
条件付き必須・項目間の規則、R/D への拡張は今回に含めない。人が空欄を埋める方式には変えない。
