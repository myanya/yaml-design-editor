# ADR-0019: 外部作業の提案と直接確定を分ける

状態: 承認済み（2026-11-01）

## 背景

同じ PC の自作ツールや外部 AI にも、利用者が内容を確認したい作業と、自動で保存まで終えたい作業がある。
提案だけを公開すると全ての変更にデスクトップの承認が要る。利用者は両方のルートを選べる方針を承認した。

## 決定

- ADR-0016 の外部任意編集を承認待ちの作業へ限定する部分を上書きし、提案と直接確定の二つの作業方式を設ける。ADR-0017 の検証・競合保護・履歴の扱いは維持する。
- PROPOSE と COMMIT は独立した能力とする。直接確定の許可を明示した接続者だけが直接確定の作業を開始できる。提案権限・業務操作権限・閲覧権限から暗黙に昇格しない。
- 作業開始時に PROPOSAL / DIRECT を固定する。両権限を持つ接続者でも、提案として開始した作業を外部から承認できない。方式を変える場合は破棄して新しく開始する。
- 両方式とも WorkingCopy で編集し、ChangeSetApplier で検証する。直接確定は WorkspaceOperations の計画 ID を取得して明示確定し、提案はデスクトップから確認・承認する。
- 保存する自動値・差分を計画に固定する。古い保存版・編集の版・権限・世代・期限、対象の未保存編集、変更対象と影響先の検証エラーは保存を拒否する。
- 直接確定では作業 ID を要求の同一性に使う。確定の意図を記録してから保存し、同じ作業と計画の再送は既存の結果を返す。記録の照合や復旧を外部へ公開しない。
- ADR-0018 の閲覧の範囲を維持し、変更範囲に SELECTED（指定文書）と LEDGER（今後の追加を含む業務データ）を追加する。LEDGER は WorkspaceLayout の判定を使い、定義・構成・記録への変更を許さない。
- 簡単設定では全体閲覧を初期値とし、提案・直接確定・業務操作を独立して追加する。業務操作名はカタログから具体的に選び、後から追加した名前は自動許可しない。
- 設定は version 3 とする。version 1・2 の変更範囲は指定文書のまま、直接確定は無許可で復元する。作業記録は version 2 で方式を持ち、旧記録は全て提案として読む。
- 外部の計算は全入力への閲覧許可を要求する。権限外の入力を評価してから差分や検証結果だけを濾過する方法は採らない。

## 影響

提案は内容を人が確認したい作業、直接確定は委任済みの自動処理で使い分ける。利用場所や別サーバへの対応とは独立した選択である。
直接確定の結果は作業 ID で照会し、承認待ちの受信箱には表示しない。未提出・未確定の作業コピーは再起動で失われる。
保存失敗や部分保存は一括ロールバックを意味しない。元の要求を再実行せず結果を照合し、必要な修正は新しい作業で行う。
接続機能の ON/OFF・資格情報の発行と権限の保存は独立し、権限の追加だけではポートを開かない。

Core Calculus の変更計画は既存の Rewrite → ChangeSetApplier、検証は既存の Predicate、定義済み操作の選択は既存カタログを使う。
認証・作業方式・要求記録は実行基盤であり、業務評価器や YAML 語彙、新しい保存経路を追加しない。

## 却下した案

- 全ての外部変更を自動承認: 確認してから採用する目的の提案がなくなる。
- 提案権限のままで commit を追加: 既存の接続者に保存権限まで付与してしまう。
- 生の変更セットを即時保存する API: 作業コピー・差分確認・厳格な検証と既存の確定窓口を迂回する。
