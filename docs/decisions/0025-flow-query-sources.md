# ADR-0025: フローの入力をクエリ変換で合成する

- 日付: 2026-11-04
- 状態: 採用

## 文脈

複数の文書に分かれたサービス設定から構成図を導きたい。表示用の接続や設定を別文書へ転記すると、原本の変更と図が一致しない。
従来のflowは対象文書を直接projectionへ渡していた。

## 決定

- `sources` に既存のクエリ変換を並べ、結果を各変換の `id` をキーとする配列としてprojectionへ渡す。対象文書は `document` に置く。
- sourcesを省略したflowの入力と挙動は変えない。適用先・埋め込み・表示状態は引き続き対象文書を基準とする。
- sourcesは独立に同じ索引と未保存優先loaderを使う。sources間の依存、外部params、再帰、原本への書込は導入しない。
- 名前の重複、予約名document、fromの欠落を定義の読取で拒否する。projection自体のfrom・外部paramsは禁止のまま。
- 合成入力からprojection、記法まで、既存のTemplatePlaceとTransformOriginで原本座標を保持する。
- 丸ごと写した単一原本を直接eachで表示する場合だけ、既存のフォーム編集へ渡す。複数原本を組み立てた詳細は来歴への移動で扱う。
- クエリの打切りと未解決参照による経路の脱落を診断する。入力を全件取得したように見せない。

## 計算体系の確認

対象選択と結合はQuery、値の組立てはConstruct、絞り込みと条件は既存Predicate/Expressionである。
集合の再計算・新しいAggregate・Rewriteは不要。新しい演算やAWS専用の評価器は作らず、既存変換を入力と表示の2段で接続する。
順序は既存QueryとConstructの決定的順序に従う。原本への来歴を保持し、参照不明・重複・打切りは診断する。新しい書込経路はない。

## 既存の決定との関係

ADR-0014・ADR-0015のビュー差し込み口と責務を維持する。文書単位の表示という契約を維持し、入力がその文書の内容だけに限られる制約を拡張する。
汎用変換の表面語彙は変更せず、ViewContextに同じ索引で変換する窓口を追加する。

## 検証

文書間参照の変更とUndo、CLI・画面の同じ解決、単一原本の編集適格性、合成した詳細の編集拒否、原本の参照型に基づく診断、空の入力、打切り、未解決経路、定義の不正を検査する。
