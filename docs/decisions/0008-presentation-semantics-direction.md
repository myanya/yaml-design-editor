# ADR-0008: 表記と意味の方向規則

- 日付: 2026-08-16
- 状態: 承認済み

## 文脈

最終的には、ユーザ定義スキーマから構造スキーマと意味スキーマの2層を導出して各層で検証し、意味スキーマ側が表記ポリシー（引用符・ブロックスタイル等）まで担う構想がある。この拡張を可能にしつつ、表記が意味を壊す事故を防ぐ。

## 決定

- **意味 → 表記: 可**。意味スキーマが表記を処方してよい。表記ポリシーのlintがstyleHintを読んで指摘するのもよい（presentation issueとして報告するだけで、意味内容には影響させない）。
- **表記 → 意味: 不可**。styleHintが値・ID・ref・グラフ・検証の意味内容を変えることは永遠にない。
- **往復型安全はyaml-coreの床**。表記ポリシーが型を壊すスタイルを指定しても、yaml-coreのdumpが仕様の範囲で上書き（または拒否）する。ポリシーは提案であり、構文層が強制する。
- スカラーの値域は閉集合 `{String, Boolean, Int/Long, Double, null}`（現行 `PlainDateResolver` 踏襲。日付は素の文字列）。`SetScalar` は「Kotlinの型が正」で、yaml-coreは値を解釈も推測もしない。
- 表記の決定は常にデータとして下へ流れ、styleを明示した `Replace` や正規化パスなど通常の操作として適用する。専用の書込経路は作らない。

## 帰結

- スタイル変更もplan/apply・staging・undo・diffに乗り、レビュー可能な変更セットになる。
- 表記ポリシーは将来 `SemanticDeclarations` への宣言族追加として導入し、最終再設計では構造／意味／表記を独立した宣言カテゴリに分ける。
