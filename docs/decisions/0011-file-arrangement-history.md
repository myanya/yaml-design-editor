# ADR-0011: 一般ファイルの配置変更をセッションの履歴へ統合する

- 状態: 承認済み

## 決定

ファイルツリーの移動・改名・削除・フォルダー作成は `FileArrangementPlan` として計画する。YAML の修正は既存の `WorkspaceTransaction`、一般ファイルの配置は `PathMove`、補助テキストの更新は `FileTextEdit` で表す。

通常の `apply` は従来どおりメモリだけを変更する。明示的な `applyFileArrangement` が計画を適用して保存し、物理変更を同じセッション履歴へ関連付ける。Undo/Redo もこの履歴を通す。

ADR-0005 の書込経路を一般ファイルへ拡張する。文書の書込は `save` と `DocumentStore`、物理移動と失敗時の復元は workspace-core の `FileArrangementJournal` が担う。アプリには別の履歴を作らない。

## 保証と制約

- 適用・Undo/Redo の直前に内容ハッシュで外部変更を検査する。競合時は上書きしない。
- 書込途中の例外では、移動を逆に辿り文面とセッション状態を復元する。電源断・プロセス強制終了を跨ぐ原子性は保証しない。
- 削除はワークスペースの隠し領域 `.yde-trash` へ退避する。履歴はセッション内、退避ファイルは再起動後も残る。
- リンクを含む移動・ルート外・移動先の衝突・親子の重複は拒否する。
- パス修正は Rewrite、対象の判定は既存の配置規則・glob・スキーマ誘導走査を使う。汎用の文字列置換や独自の YAML 書込経路を追加しない。

## 理由

参考資料を含むフォルダー整理と、スキーマ・ビューなどの配置依存の修正を一緒に戻せる必要がある。文書編集の単一履歴を保ちながら、YAML 以外の資源も同じ操作へ含める。
