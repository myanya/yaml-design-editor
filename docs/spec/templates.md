## 変換のひな型の指示

ひな型は、出力の形をそのまま YAML で書いたものです。`$` で始まるキーを持つマップだけが指示で、それ以外は書いたとおりに出力します。値が得られない指示は「無い」になり、マップのキーごと出力から落ちます。文字列 $名前 は受け取った値で、繰り返しの中では $key・$index（0 始まり）・$position（1 始まり）を使えます。$$ は文字の $ です。

## 変換定義

YAML から YAML への変換 1 つ。入力を選び（from）、ひな型で組み立てます（build）。出力は YAML の項で、ワークスペースの文書としては保存しません。ここに無いキーは誤りになります。

- 読む実装: semantic-core/schema/TransformDef.kt の TransformDef
- 実装する機能（[FEATURES.md](../FEATURES.md) の ID）: C-15

| 語 | 必須 | 値の形 | 省いたとき | 意味 |
|---|---|---|---|---|
| `id` | 必須 | 文字列 |  | 変換の ID。 |
| `name` |  | 文字列 |  | 表示名。 |
| `description` |  | 文章 |  | 説明。 |
| `params` |  | 名前の配列（英字で始まる英数字） |  | 受け取る値の名前。ひな型の中では $名前 で読みます。key・index・position は使えません。 |
| `from` |  | {match, also, where, limit} | 呼び出し側が渡した項 1 つが入力です | 入力を選ぶクエリ。書くなら match が必要です。limit を書かなければ、すべての解を相手にします。 |
| `build` | 必須 | ひな型 |  | 出力の中身。 |
| `rules` |  | {id, when, with, build} の配列 |  | 名前を付けた組み立て。 |

| `stage` |  | 段の ID | 業務モデルの項そのもの | どの段（workspace.yaml の stages）の項を読むか。段の項は、業務モデルの項に、その段までの規則と補正を当てたものです。 |

| `output` | 必須 | {パス} を含む文字列 |  | 作る文書の場所（ワークスペース相対の YAML）。穴は要素の値で埋めます。.yde の下と定義の置き場には書けません。 |
| `build` | 必須 | ひな型 |  | 文書の中身。$compose で導出・追加・変更の候補を合成し、$schemaUses で利用箇所の指定場所を用意し、$schemaModel で型を解き、$validate で組み立てた文書の構造・参照・条件を検査できます。いまの場所は要素（each を省けば業務モデル全体）で、業務モデル全体は $of: model、いまの要素は $of: element で読めます。業務モデルの schemas は、読む範囲のスキーマ原文を {id, document, declared} の配列で保持します。viewDefinitions は同じ範囲のビュー定義の原文の配列です。 |
| `rules` |  | {id, when, with, build} の配列 |  | 名前を付けた組み立て。 |
| `dependsOn` |  | 生成の定義の ID の配列 |  | 先に生成する定義。同じ計画の中で先に生成し、その結果をビューから読めます。循環と、存在しない ID は誤りです。 |
| `input` |  | ひな型 |  | 生成の入力の組み立て。段を当てる前に、業務モデルと $view の行から入力を組み立てます（rules も使えます）。入力の stages に記録済みの段は当て直さず、残りの段だけを当てます。 |
