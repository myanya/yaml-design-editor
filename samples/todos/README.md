# YDE TODO管理サンプル

YDE（Yaml Design Editor）で、TODOの一覧と個票を管理するためのサンプルワークスペースです。フォーム編集、同じIDによる一覧と個票の結合、ビューからの個票作成を試せます。YDE本体は含まれていないため、別途用意したYDEでこのディレクトリを開いてください。

## ディレクトリ構成

```text
.yde/
  workspace.yaml              # 台帳の対象をtodos配下に限定
  schemas/
    todo-list.yaml            # TODO一覧のスキーマ
    todo-detail.yaml          # TODO個票のスキーマ
    category-list.yaml        # カテゴリ一覧のスキーマ
  views/
    todo-management.yaml      # TODO管理ビュー
    category-status-matrix.yaml  # カテゴリ×ステータス集計ビュー
todos/                        # サンプルデータ
  todo-list.yaml              # ID・タイトル・概要・カテゴリの一覧
  category-list.yaml          # カテゴリID・名前の一覧
  details/
    TODO-001.yaml             # 一覧から作成する個票（例）
```

`.yde` 配下はYDEの設定です。`todos` 配下にはサンプルデータがあり、以下の手順で追加・編集できます。`.tooldocs` はツールのマニュアル置き場で、Git管理対象外です。必要に応じてYDEから取得してください。

## 使い始める

1. YDEでこのワークスペースを開きます。
2. 編集スペースで `todos/category-list.yaml` を開き、必要なカテゴリを追加して保存します。次に `todos/todo-list.yaml` のフォームの「TODO一覧」で要素を追加し、ID・タイトル・概要を入力します。カテゴリは参照候補から選択して保存します。ファイルがない場合は、以下の記入例を使って作成してください。
3. 台帳スペースの「ビュー」で「TODO管理」を開きます。
4. 個票がない行は、詳細列にある「作成」から個票を作成します。行のIDが引き継がれ、`todos/details/<ID>.yaml` が生成されます。
5. 個票に作成日・詳細などを入力して保存します。以後は同じ詳細列のリンクから個票を開けます。

一覧を作成した後は、ビューの「新規行」からも一覧へTODOを追加できます。編集後は保存してください。作成日は自動入力ではなく、TODOを登録した日を入力します。

## 一覧と個票の書き方

### カテゴリ一覧

`todos/category-list.yaml` の `categories` 配列でカテゴリを管理します。

```yaml
categories:
  - id: CAT-001
    name: 環境整備
  - id: CAT-002
    name: データ登録
```

IDとカテゴリ名は必須です。IDは `CAT-` と3桁以上の数字で指定し、重複させないでください。カテゴリを増やす場合はこの一覧に要素を追加します。

### TODO一覧と個票

一覧 `todos/todo-list.yaml` は、`todos` 配列に1件ずつ記録します。

```yaml
todos:
  - id: TODO-001
    title: 利用手順を確認する
    summary: サンプルの一覧登録から個票更新までを確認する
    category: CAT-002
```

IDは `TODO-001` のように、`TODO-` と3桁以上の数字で指定します。一覧内で重複させないでください。個票では同じIDを使い、ファイル名もIDに合わせます。タイトル・概要・カテゴリは一覧で管理し、個票へは転記しません。

`category` はカテゴリ一覧のIDを1件指定する任意項目です。未分類の場合は省略できます。`type: ref` と `scope.schemaIds: [category-list]`、`idPattern: "CAT-*"` により、参照候補と参照検証の対象をカテゴリ一覧に限定しています。カテゴリ名を変更しても、IDが同じならTODOの参照値は変更不要です。参照中のカテゴリを削除する場合は、先にTODOのカテゴリを変更または解除してください。

個票 `todos/details/TODO-001.yaml` の記入例です。

```yaml
id: TODO-001
status: IN_PROGRESS
created_on: "2026-09-01"
due_on: "2026-09-30"
details: |
  一覧にTODOを登録し、ビューから個票を作成する。
  ステータスとコメントを更新して表示を確認する。
result: ""
comments:
  - date: "2026-09-02"
    body: 個票を作成し、ステータスを対応中に変更した。
  - date: "2026-09-01"
    body: 確認する作業内容を整理した。
```

ID・ステータス・作成日は必須です。期限（`due_on`）は未定なら省略できます。完了時は `status: CLOSED` にして完了日（`completed_on`）と結果（`result`）を記録してください。未完了・中止時は完了日を省略し、中止理由は結果に記録します。コメントがない場合は `comments: []` とします。日付はすべて `YYYY-MM-DD` 形式です。

| 保存するステータス | 日本語ラベル |
| --- | --- |
| `OPEN` | 未着手 |
| `IN_PROGRESS` | 対応中 |
| `CLOSED` | 完了 |
| `CANCELED` | 中止 |

## TODO管理ビュー

| 項目 | 表示元 |
| --- | --- |
| ID | 一覧と個票を結び付ける共通ID（YDEの標準列） |
| カテゴリ | 一覧の `category`（カテゴリ一覧へのID参照） |
| ステータス | 個票の `status` |
| 期限 | 個票の `due_on` |
| 概要 | 一覧の `summary` |
| 作成日 | 個票の `created_on` |
| 更新日 | 個票のコメントの日付 `comments[*].date` の最大値（値がない場合は「未更新」） |
| 個票へのリンク／作成 | 個票があれば開くリンク、なければ作成ボタン（YDEの詳細列） |

カテゴリ・ステータス・期限・概要・作成日はビューから直接編集できます。カテゴリは個票を作成する前でも設定できます。個票がない行のステータス・期限・作成日は空欄です。先に詳細列から個票を作成してください。

### 最終更新日の扱い

最終更新日は「コメントの日付の最新日」です。ビューの「更新日」は、すべてのコメントの日付から最大値を取得し、読み取り専用の計算列として表示します。**コメントの並び順は任意で、日付の降順に並べる必要はありません。** 更新日そのものは個票に重複保存せず、ファイルの更新日時や作成日では代用しません。

実際のビュー定義（`.yde/views/todo-management.yaml`）では、次のように `max` と `type: date` で日付の最大値を取得し、`first` で値がない場合の表示を「未更新」にしています。コメントがない場合も「未更新」と表示します。

```yaml
value:
  first:
    - max: { path: "comments[*].date", type: date }
    - 未更新
```

コメントの追加・日付の修正・削除後は、残っているコメントの日付の最大値が更新日になります。ステータスや詳細の変更を更新日に反映したい場合は、その日付のコメントも追加します。

## カテゴリ×ステータス集計ビュー

台帳スペースの「ビュー」で「カテゴリ×ステータス」を開くと、行がカテゴリ、列がステータスの集計表が表示されます。件数は一覧の `category` と個票の `status` から毎回計算する読み取り専用の値で、どこにも保存しません。

| カテゴリ名 | 未着手 | 対応中 | 完了 | 中止 | 合計 |
| --- | --- | --- | --- | --- | --- |
| 環境整備 | 0 | 0 | 1 | 0 | 1 |
| データ登録 | 0 | 0 | 2 | 0 | 2 |

件数のセルをクリックすると、数えた TODO の一覧が出て、各 TODO の一覧の行へ移動できます。個票のステータスを変えて保存すると、件数はすぐに動きます。

ビュー定義（`.yde/views/category-status-matrix.yaml`）では、行のカテゴリを起点に「このカテゴリを参照している TODO」を状態で絞って数えます。列は状態ごとに 1 つ書き、`where` の値だけが違います。合計の列は `where` を書きません。

```yaml
- label: 未着手
  schemaId: category-list
  value:
    count:
      match:
        - node: { entity: category, bind: cat }   # 起点＝行のカテゴリ
        - edge: { via: category, dir: in }        # カテゴリを参照している要素へ
        - node: { entity: todo, bind: t }         # 数える対象
      where:
        - { of: t, path: status, equals: OPEN }   # 個票のステータスで絞る
```

カテゴリを付けていない TODO はどの行にも数えられません。個票をまだ作っていない TODO はステータスが無いため、合計にだけ数えられます。

## 設定を変更する場合

スキーマの表示ラベルや説明は `.yde/schemas`、ビューの表示項目は `.yde/views/todo-management.yaml` で変更できます。一覧がIDの定義元、個票がその詳細化という構成です。個票の作成はビューの `detail` 設定で行います。

このワークスペースは公開用サンプルです。共有するデータには個人情報や機密情報を含めないでください。
