# YDE TODO管理サンプル

YDE（Yaml Design Editor）で、TODOの一覧と個票を管理するためのサンプルワークスペースです。フォーム編集、同じIDによる一覧と個票の結合、ビューからの個票作成、共通の型による形式と見せ方の統一、日付の検査を試せます。YDE本体は含まれていないため、別途用意したYDEでこのディレクトリを開いてください。

## ディレクトリ構成

```text
.yde/
  workspace.yaml              # 台帳の対象をtodos配下に限定
  schemas/
    common.yaml               # 共通の型（ID の形式・日付の見せ方・文字の長さ・ステータス）
    todo-list.yaml            # TODO一覧のスキーマ
    todo-detail.yaml          # TODO個票のスキーマ（日付の検査もここ）
    category-list.yaml        # カテゴリ一覧のスキーマ
  views/
    todo-management.yaml      # TODO管理ビュー
    todo-by-due.yaml          # 期限順ビュー
    category-status-matrix.yaml  # カテゴリ×ステータス集計ビュー
todos/                        # サンプルデータ
  todo-list.yaml              # ID・タイトル・概要・カテゴリの一覧
  category-list.yaml          # カテゴリID・名前の一覧
  details/
    TODO-001.yaml             # 一覧から作成する個票（TODO-001〜004。TODO-005 は個票を作る前の状態）
```

`.yde` 配下はYDEの設定です。`todos` 配下にはサンプルデータがあり、以下の手順で追加・編集できます。`.tooldocs` はツールのマニュアル置き場で、Git管理対象外です。必要に応じてYDEから取得してください。

## 使い始める

1. YDEでこのワークスペースを開きます。
2. 編集スペースで `todos/category-list.yaml` を開き、必要なカテゴリを追加して保存します。次に `todos/todo-list.yaml` のフォームの「TODO一覧」で要素を追加し、ID・タイトル・概要を入力します。カテゴリは参照候補から選択して保存します。ファイルがない場合は、以下の記入例を使って作成してください。
3. 台帳スペースの「ビュー」で「TODO管理」を開きます。
4. 個票がない行は、詳細列にある「作成」から個票を作成します。行のIDが引き継がれ、`todos/details/<ID>.yaml` が生成されます。サンプルでは `TODO-005` が個票を作る前の状態です。
5. 個票に作成日・詳細などを入力して保存します。以後は同じ詳細列のリンクから個票を開けます。

一覧を作成した後は、ビューの「新規行」からも一覧へTODOを追加できます。編集後は保存してください。作成日は自動入力ではなく、TODOを登録した日を入力します。

## 共通の型（`.yde/schemas/common.yaml`）

IDの形式・日付の見せ方・文字の長さ・ステータスの選択肢は、一覧と個票の両方で同じ決まりです。それぞれのスキーマに同じことを書く代わりに、`common.yaml`（`kind: library`）に**型**として1回だけ定義し、項目の `type` に名前で書いて使います。型を直せば、使っている全部の項目に効きます。

| 型 | 基になる種類 | 決まり・見せ方 | 使う項目 |
| --- | --- | --- | --- |
| `TODO番号` | `id` | 形式 `^TODO-[0-9]{3,}$`。入力欄の案内とサンプル値は `TODO-001` | 一覧と個票の `id`、スキーマの `entity.idType` |
| `カテゴリ番号` | `id` | 形式 `^CAT-[0-9]{3,}$` | カテゴリ一覧の `id`、`entity.idType` |
| `カテゴリ参照` | `ref` | 候補と検証をカテゴリ一覧（`CAT-*`）に限定 | 一覧の `category` |
| `年月日` | `date` | ファイルは `YYYY-MM-DD`、画面は `2026年9月22日` の形（`format`） | 作成日・期限・完了日・コメントの日付 |
| `一行の文` | `line` | 改行を入れられない1行の文。100文字以内 | タイトル・概要・カテゴリ名 |
| `文章` | `text` | 複数行の欄（4行の高さ） | 詳細・結果 |
| `ステータス` | `enum` | 保存する値は英語、画面の表示は日本語（下の表） | 個票の `status` |

使う側はこう書きます（`todo-list.yaml` の抜粋）。

```yaml
entity:
  type: todo
  idType: common#TODO番号      # この文書群の ID は TODO番号 の形式（idPattern の代わりに型の名前で判別）
  defines: true
root:
  type: object
  fields:
    - key: id
      type: common#TODO番号      # 別のスキーマの型は「スキーマID#型の名前」
      required: true
    - key: title
      type: common#一行の文
      role: title
      required: true
```

- **値と見せ方は別**: 日付はファイルに `2026-09-22` と書かれ、フォームとビューでは `2026年9月22日` と見えます。入力中は元の表記に戻り、CLI や書き出しの値も変わりません。見せ方を変えたいときは `年月日` の `format` だけを直します。
- **文字列の種類**: `line` は改行を含む値を誤りにします（タイトルが2行になるのを防ぎます）。`text` は複数行の欄を保証します。普通の `string` は、改行があれば欄が縦に伸びる自由な文字列です。
- **使う側で狭める**: 型を使う項目に `maxLength: 50` のように書けば、型の決まりに加えてさらに狭くできます。緩める書き方（型より長い `maxLength` など）はスキーマの定義エラーになります。
- **IDの型で出現の型を判別**: `entity.idType` に ID の型を書くと、その形式に合う ID がその型（todo / category）になります。形式に合わない ID は「ID の決まり（型 common#TODO番号）のいずれにも一致しません」と警告されます。

## 一覧と個票の書き方

### カテゴリ一覧

`todos/category-list.yaml` の `categories` 配列でカテゴリを管理します。

```yaml
categories:
  - id: CAT-001
    name: 環境整備
  - id: CAT-002
    name: データ登録
```

IDとカテゴリ名は必須です。IDは `CAT-` と3桁以上の数字で指定し、重複させないでください。カテゴリを増やす場合はこの一覧に要素を追加します。

### TODO一覧と個票

一覧 `todos/todo-list.yaml` は、`todos` 配列に1件ずつ記録します。

```yaml
todos:
  - id: TODO-001
    title: 利用手順を確認する
    summary: サンプルの一覧登録から個票更新までを確認する
    category: CAT-002
```

IDは `TODO-001` のように、`TODO-` と3桁以上の数字で指定します。一覧内で重複させないでください。個票では同じIDを使い、ファイル名もIDに合わせます。タイトル・概要・カテゴリは一覧で管理し、個票へは転記しません。タイトルと概要は1行（改行なし・100文字以内）です。

`category` はカテゴリ一覧のIDを1件指定する任意項目です。未分類の場合は省略できます。型 `カテゴリ参照`（`type: ref` と `scope.schemaIds: [category-list]`、`idPattern: "CAT-*"`）により、参照候補と参照検証の対象をカテゴリ一覧に限定しています。カテゴリ名を変更しても、IDが同じならTODOの参照値は変更不要です。参照中のカテゴリを削除する場合は、先にTODOのカテゴリを変更または解除してください。

個票 `todos/details/TODO-001.yaml` の記入例です。

```yaml
id: TODO-001
status: IN_PROGRESS
created_on: 2026-09-01
due_on: 2026-09-30
details: |
  一覧にTODOを登録し、ビューから個票を作成する。
  ステータスとコメントを更新して表示を確認する。
result: ""
comments:
  - date: 2026-09-02
    body: 個票を作成し、ステータスを対応中に変更した。
  - date: 2026-09-01
    body: 確認する作業内容を整理した。
```

ID・ステータス・作成日は必須です。期限（`due_on`）は未定なら省略できます。完了時は `status: CLOSED` にして完了日（`completed_on`）と結果（`result`）を記録してください。未完了・中止時は完了日を省略し、中止理由は結果に記録します。コメントがない場合は `comments: []` とします。コメントの並び順は任意です。日付はすべて `YYYY-MM-DD` 形式で、存在しない日付（`2026-02-30` など）は誤りになります。

| 保存するステータス | 日本語ラベル |
| --- | --- |
| `OPEN` | 未着手 |
| `IN_PROGRESS` | 対応中 |
| `CLOSED` | 完了 |
| `CANCELED` | 中止 |

## 個票の検査

個票のスキーマ（`todo-detail.yaml` の `constraints`）に、日付の決まりを3つ書いてあります。保存すると検証パネルに指摘が出ます（個票に指摘、一覧の行には案内）。

| 検査 | 内容 | 重大度 |
| --- | --- | --- |
| `due-not-before-created` | 期限は作成日以降であること | エラー |
| `completed-not-before-created` | 完了日は作成日以降であること | エラー |
| `closed-has-completed-on` | 完了した TODO には完了日があること | 警告 |

日付どうしの比較は、項目の型が `年月日`（日付）なので**日付として**比べます。検査に `type: date` のような宣言を書く必要はありません。

```yaml
constraints:
  - id: due-not-before-created
    description: 期限は作成日以降であること
    match:
      - node: { entity: todo, bind: t }                  # 対象: todo 型の要素
    check:
      - gte: [ { of: t, path: due_on }, { of: t, path: created_on } ]   # 期限 ≧ 作成日
    level: error
```

試すには、`TODO-004.yaml` の `due_on` を作成日より前の日付（例 `2026-09-20`）にして保存してください。「反例: t=TODO-004（due_on: 2026-09-20） < t=TODO-004（created_on: 2026-10-01）」のようにエラーが出ます。期限を省いた個票は比べる値が無いので、指摘も充足もしません（判定保留）。

## TODO管理ビュー

| 項目 | 表示元 |
| --- | --- |
| ID | 一覧と個票を結び付ける共通ID（YDEの標準列） |
| カテゴリ | 一覧の `category`（カテゴリ一覧へのID参照） |
| ステータス | 個票の `status` |
| 期限 | 個票の `due_on` |
| 概要 | 一覧の `summary` |
| 作成日 | 個票の `created_on` |
| 更新日 | 個票のコメントの日付 `comments[*].date` の最大値（値がない場合は「未更新」） |
| 個票へのリンク／作成 | 個票があれば開くリンク、なければ作成ボタン（YDEの詳細列） |

カテゴリ・ステータス・期限・概要・作成日はビューから直接編集できます。カテゴリは個票を作成する前でも設定できます。個票がない行のステータス・期限・作成日は空欄です。先に詳細列から個票を作成してください。期限・作成日は `年月日` の型の見せ方（`2026年9月22日`）で表示され、編集中は `2026-09-22` に戻ります。

### 最終更新日の扱い

最終更新日は「コメントの日付の最新日」です。ビューの「更新日」は、すべてのコメントの日付から最大値を取得し、読み取り専用の計算列として表示します。**コメントの並び順は任意で、日付の降順に並べる必要はありません。** 更新日そのものは個票に重複保存せず、ファイルの更新日時や作成日では代用しません。

実際のビュー定義（`.yde/views/todo-management.yaml`）では、次のように `max` で日付の最大値を取得し、`first` で値がない場合の表示を「未更新」にしています。`date` の項目を読むので、`max` は日付として比べます（`type: date` は書きません）。計算した値には項目の型が無いので、画面の見せ方（`format`）は列に書きます。コメントがない場合も「未更新」と表示します。

```yaml
format: "yyyy年M月d日"
value:
  first:
    - max: { path: "comments[*].date" }
    - 未更新
```

コメントの追加・日付の修正・削除後は、残っているコメントの日付の最大値が更新日になります。ステータスや詳細の変更を更新日に反映したい場合は、その日付のコメントも追加します。

## 期限順ビュー

台帳スペースの「ビュー」で「期限順」を開くと、TODO が個票の期限の早い順に並びます。`due_on` は日付の項目なので日付として並び（`type` の宣言は不要）、期限の無い TODO（個票が無い・期限が未定）は後ろ、同じ期限は ID の順です。ステータス・期限・完了日はこのビューからも編集できます。

```yaml
order:
  schemaId: todo-detail
  path: due_on          # 個票の期限の順（日付の項目なので日付として比べる）
```

## カテゴリ×ステータス集計ビュー

台帳スペースの「ビュー」で「カテゴリ×ステータス」を開くと、行がカテゴリ、列がステータスの集計表が表示されます。件数は一覧の `category` と個票の `status` から毎回計算する読み取り専用の値で、どこにも保存しません。

| カテゴリ名 | 未着手 | 対応中 | 完了 | 中止 | 合計 |
| --- | --- | --- | --- | --- | --- |
| 環境整備 | 0 | 1 | 1 | 0 | 2 |
| データ登録 | 0 | 0 | 2 | 0 | 3 |

件数のセルをクリックすると、数えた TODO の一覧が出て、各 TODO の一覧の行へ移動できます。個票のステータスを変えて保存すると、件数はすぐに動きます。

ビュー定義（`.yde/views/category-status-matrix.yaml`）では、行のカテゴリを起点に「このカテゴリを参照している TODO」を `all` で集め、状態で絞って `count` で数えます。列は状態ごとに 1 つ書き、`where` の値だけが違います。合計の列は `where` を書きません。

```yaml
- label: 未着手
  schemaId: category-list
  value:
    count:                                        # 配列の件数
      all:                                        # 照合の解を配列にする
        of: t                                     # 集める対象
        match:
          - node: { entity: category, bind: cat } # 起点＝行のカテゴリ
          - edge: { via: category, dir: in }      # カテゴリを参照している要素へ
          - node: { entity: todo, bind: t }
        where:
          - { of: t, path: status, equals: OPEN } # 個票のステータスで絞る
```

カテゴリを付けていない TODO はどの行にも数えられません。個票をまだ作っていない TODO（サンプルの `TODO-005`）はステータスが無いため、合計にだけ数えられます。

## 設定を変更する場合

型（IDの形式・日付の見せ方・文字の長さ・ステータスの選択肢）は `.yde/schemas/common.yaml`、項目の表示ラベルや説明は `.yde/schemas` の各スキーマ、ビューの表示項目は `.yde/views` で変更できます。一覧がIDの定義元、個票がその詳細化という構成です。個票の作成はビューの `detail` 設定で行います。設計スペースでスキーマを開くと、型の名前を項目の「型」から選べ、入力欄の案内・サンプル値・複数行の欄なども画面から設定できます。

このワークスペースは公開用サンプルです。共有するデータには個人情報や機密情報を含めないでください。
