# 図の記法のサンプル

YAMLの原本を、人物カード・クラスの区画・UMLの辺・ER図で表示します。
フォルダをコピーしてワークスペースとして開いてください。

1. 台帳のグラフレンズで「見え方: 標準」を押し、「人物相関図」を選びます。型をpersonに絞ると、画像と下段の名前、画像未設定の代替アイコンを比べられます。
2. 「クラス図」を選び、型をclassに切り替えます。Orderからの白三角、破線の白三角、塗りつぶし菱形と多重度を確認できます。属性・操作の文字を押すと原本の項目へ移動します。
3. レンズの「型」の段で「スキーマの属性」を選ぶと、データを読むことなくスキーマの直下の属性を表示します。これは設計したプログラムのクラスとは別の図です。
4. 台帳の「フロー」で「人物カードのフロー」「クラス図のフロー」「ER図のフロー」を選べます。人物のstatusをawayにした蓮だけ、枠と「留守」が条件付きで変わります。
5. 図の「PNG に保存」で、画像・区画・端点記号を含む出力を確認します。枠を押した詳細欄の編集や、原本の変更は通常の保存・Undoの対象です。

## ER図

台帳のグラフレンズで「実体」の段を開き、記法を「ER図」、型を `er-table` に絞ります。
配置は「階層」を選びます。「応力」では大きなテーブルの枠が重なり、一部の線を描けない場合があります。
「全体」で図を収めると、顧客・注文・注文明細・商品のテーブルと、外部キーの線を見られます。
前の図で起点や関係を絞っていた場合は、その絞り込みも解除してください。

フローでは、台帳 →「フロー」→「ER図のフロー」→ `data/er.yaml` を選びます。
同じ原本と記法で4テーブル・3本の外部キーを表示し、型の絞り込みは不要です。
テーブルの枠を選ぶと詳細欄で列や外部キーを編集できます。辺の詳細は派生表示のため、編集は参照元テーブルの詳細欄から行います。
フローでテーブル間の隙間を狭めると、長い外部キーのラベルが線の近くで折り返されます。移動後も多重度と重ならず、PNGに同じ位置で出ることを確認します。

この図の原本は [data/er.yaml](data/er.yaml) にある**テーブルの設計情報**です。
YDEは設計情報をスキーマで検証し、同じ情報からフォームと図を作ります。
業務の実レコードを管理する [orders](../orders/README.md) や、YDEのスキーマ自体を説明するレンズの「型」の段とは、対象が異なります。

| 見るところ | このモデルの意味 |
|---|---|
| テーブルの枠 | 論理名・テーブル名・列名・データ型を表示します |
| `PK` | 主キーを構成する列です。注文明細では `order_id` と `line_no` の組が主キーです |
| 外部キーの区画と線 | `foreignKeys` の同じ定義から表示し、ポートで参照元と参照先のカラムの行へ接続します |
| 注文側 `0..*`・顧客側 `0..1` | 顧客は未注文でもよく、注文はゲスト購入なら顧客を持ちません |
| 明細側 `0..*`・注文側 `1` | 入力途中の注文には明細がなくてもよく、各明細は必ず一つの注文に属します |
| 明細側 `0..*`・商品側 `1` | 未注文の商品も登録でき、各明細は必ず一つの商品を参照します |

注文と商品は注文明細を介した多対多です。明細に数量と受注時の単価を持ち、商品の現在価格とは区別します。
同じ商品を一つの注文で複数行に分けられるよう、明細番号を主キーの一部にしています。

### 原本と表示の分担

- `.yde/schemas/er.yaml` は設計情報の形です。列を表示済みの文字列にせず、列名・型・主キーの印を別々の項目として編集します。
- 外部キーは参照元テーブルに一度だけ記述する属性付き参照です。`to` はYDEのテーブル設計IDで、列名やDBの実レコードのキーとは別です。
- `.yde/views/er-lens.yaml` と `er-flow.yaml` が適用先、`er-table.yaml` と `er-reference.yaml` が共通の表示記法です。Construct（変換ひな型）で組み立てます。
- フローでは `$each` の `$bind` で親テーブルに名前を付け、`$flatten: true` で各テーブルの外部キーを一つの辺の配列にします。テーブルや外部キーの件数・IDを表示定義に固定していません。
- カラムの行に `port: {$copy: name}` を付け、辺の `sourcePort`・`targetPort` へ `column`・`targetColumn` を渡します。カラムはYDEのエンティティにせず、共通の表示記法だけで行へ接続します。
- 端点の多重度は、DBに格納するレコード間の設計上の制約です。YDEの関係レジストリの `cardinality` は設計ID間の参照本数を数えるため、この意味には使いません。

### 試し方と範囲

1. 図の列名 `quantity` を押し、原本の列名の項目へ移動できることを確認します。名前を変えると図にも反映され、通常のUndoで戻せます。
2. 注文の外部キーの `targetMultiplicity` を `0..1` から `1` に変えると、顧客側の端点ラベルが変わります。会員購入だけを認める設計への変更です。
3. 外部キーの `to` を存在しない `ER-MISSING` に変え、参照切れの指摘を確認してからUndoします。
4. 「PNG に保存」で共有用の図を出力できます。列と多重度が読みやすいか、フォームでの編集箇所へたどりやすいかを確認してください。
5. 注文の `customer_id` を行ごと並べ替えたりテーブルを移動したりして、線が同じカラムの高さについてくることを確認します。参照属性の列名を存在しない名前へ変えると図にポートの診断が出ます。確認後はUndoします。

現在の端点記号にはカラスの足がないため、実線と数値の多重度を使っています。
このサンプルは単一列の外部キーを扱い、複合主キーは複数列に `PK` を付けて表します。
必須項目・選択肢・参照先テーブルの存在を検証し、図ではポート名の重複と接続先の有無を診断します。DBの型の一致・キー制約・実データの件数は検証しません。
DDL生成や概念・論理・物理の段階的な詳細化は [テーブルモデルのサンプル](../todos-sysdev-tablemodel/README.md) を参照してください。

## CLIと定義の場所

CLIでも記法と射影を読めます。リポジトリのルートで実行します。

```text
./gradlew runCli -q --args="view samples/diagrams"
./gradlew runCli -q --args="view samples/diagrams uml-class"
./gradlew runCli -q --args="view samples/diagrams class-flow"
./gradlew runCli -q --args="view samples/diagrams er-table-card"
./gradlew runCli -q --args="view samples/diagrams er-reference"
./gradlew runCli -q --args="view samples/diagrams er-flow data/er.yaml"
./gradlew runCli -q --args="validate samples/diagrams"
./gradlew runCli -q --args="schema-graph samples/diagrams"
```

`.yde/views/` が適用指定と独自記法、`.yde/schemas/` が業務の構造です。
`data/` が原本で、`assets/` のSVGはこのサンプル用の単純な図形です。
クラス図・ER図の多重度は、モデルが表す対象の件数を示す参照属性です。
YDEの設計ID間の参照本数を検査する場合に限り、関係レジストリで制約を宣言します。
詳しい構文は[図の記法](../../docs/manual/diagram-notations.md)を参照してください。
