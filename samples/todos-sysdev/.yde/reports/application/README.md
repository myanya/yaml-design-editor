# {config.name}

詳細設計の確定設定から生成した、独立した Spring Boot プロジェクトです。
物理テーブルの Java 行モデル、Mapper と XML、DB の初期作成、状態型と業務例外、全操作の Service、入力検査付き Form、業務の Controller と一覧・詳細・入力・確認の画面を生成します。サイバーパンクの配色と部品の CSS はデザイン台帳から生成します。

同時更新の方式は `{config.writeConcurrency}` です。アプリ共通の `OperationRunner` が、採番前からトランザクションの確定・取り消しまで順番を保ちます。
操作は既存のトランザクションの外から呼びます。複数アプリから同じ DB を更新する構成には対応していません。

## ビルドと起動

Java {config.javaVersion} を用意し、このフォルダで実行します。依存関係の初回取得にはネットワークが必要です。

```powershell
.\gradlew.bat test bootJar
java -jar build/libs/{config.name}.jar
```

macOS・Linux では `sh ./gradlew test bootJar` を使います。
待受ポートは {config.port}、DB は作業ディレクトリ内の `data/{config.databaseName}` に保存します。
終了は起動した端末で Ctrl+C。別のポート・DB は Spring Boot の起動引数で指定できます。
空の DB には `schema.sql` を適用します。既存 DB に必要なテーブルがあれば、そのまま使います。
必要なテーブルが欠けていれば起動を止めます。既存テーブルの列や制約の変更・移行は未対応です。設計変更の検証には別の DB 名を指定してください。

このフォルダだけを別の場所へコピーしても同じ手順でビルドできます。YDE や親の Gradle 設定は不要です。
生成物を直す場合は設計の入力か生成規則へ変更を戻して再生成します。

## 画面デザインの確認

起動後に `http://localhost:{config.port}/design-preview` を開きます。
ゲーム風のサイバーパンクの配色・入力欄・通知・一覧の部品を確認できます。
タイトルを空にする、または 101 文字にして「入力検査を試す」を押すと、確定したフォームの制約と日本語の文を確認できます。
この画面は DB を更新しません。画面幅を狭めた場合と Tab キーでの移動も確認してください。

## 業務画面の確認

`http://localhost:{config.port}/` で TODO ダッシュボードを開きます。
カテゴリとタグを追加してから TODO を登録し、確認・入力へ戻る・確定を試してください。
詳細からコメントと作業項目を追加し、着手・中断・再開・作業の完了・TODO の完了を確認できます。
編集ではコメント行の追加・削除、値の消去、確認画面の変更前後を確認してください。
絞り込みや集計セルからの移動、入力エラーの再表示、別タブで状態を変えた後の断り、二重送信時の非更新も確認できます。

業務の HTML は `src/main/resources/templates/` の画面別フォルダにあります。
`fragments/business.html` は共通部品、`web-model.json` は確定した表示項目と呼出しの対応です。
行の部分更新に使う htmx は同梱しているため、実行時に外部 CDN を使いません。
