# ドキュメント同期チェック

現在の変更（未コミットの差分。指示があればコミット範囲）をドキュメント体系と突き合わせ、更新漏れを検出・修正する。各ドキュメントの役割分担は docs/CONVENTIONS.md §6 の表が正であり、**同じ内容を複数のドキュメントに書かない**。

## 手順

1. `git status` / `git diff`（必要なら `git log`）で変更内容を把握する。
2. 変更を次の観点で分類し、対応するドキュメントの該当箇所を実際に開いて照合する:

   | 変更の種類 | 確認・更新するドキュメント |
   |---|---|
   | 機能の追加・変更・削除 | docs/FEATURES.md の該当行（状態・実装ファイル・テスト列）。新機能は行を追加 |
   | 利用者から見える仕様・操作・UI・スキーマ定義構文 | README.md の該当節（画面構成図・ショートカット表・スキーマリファレンス・既知の制約を含む） |
   | クラス／パッケージの追加・移動・責務変更、データフロー・設計方針の変更 | docs/ARCHITECTURE.md §2（依存図）・§3（クラス表）・§4（方針）・§6（拡張ポイント） |
   | テストの追加 | docs/FEATURES.md のテスト列（`手動` → `単体`） |
   | 未実装項目（L-xx）の解消・着手 | docs/FEATURES.md §9 と README.md「既知の制約」の両方 |
   | ロードマップ項目（Rx-xx）の着手・完了、方向性の変更 | docs/ROADMAP.md §6 の状態表・該当項目（完了時は docs/FEATURES.md へ機能として登録） |
   | 規約・ビルド手順の変更 | docs/CONVENTIONS.md、CLAUDE.md のコマンド節 |

3. ドキュメント間の相互参照（リンク）が切れていないか、記述が矛盾していないかを確認する。
4. 見つかった漏れを修正する。修正時の注意:
   - 詳細は役割を持つ1つのドキュメントにだけ書き、他からはリンクする。
   - 行番号や件数など変わりやすい値は書かない（クラス名・ファイル名で参照）。
   - 日本語で、既存の文体・表形式に合わせる。
5. 結果を報告する: 更新したドキュメントと理由、更新不要と判断した理由。
