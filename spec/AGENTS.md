# AGENTS.md

仕様のワークスペース。定義に書ける語・位置・基底の種類の原本。運用は [README.md](README.md)「運用」。

- **原本はここ**。docs/spec/ の参照文書は生成物で、直接直さない。YAML を直したら `./gradlew specDocs` で作り直し、一緒にコミットする（作り直し忘れは `SpecTest` が止める）。
- 仕様は今の実装の記述。語彙を変えるコミットでは、パーサ・メタスキーマ・設計画面・manual（CONVENTIONS「スキーマ語彙と編集UIの同期」）に加えて、ここの語も直す。食い違いは `SpecTest` が止める。
- ID は名前で付ける（`KW-位置.キー`・`CTX-位置`・`BT-種類`）。番号を振らない（並行の作業で重ならないように）。
- 1 語 1 ファイル。同じキーが基底の種類で意味を変えるときは、語を分けずに `forms` を分ける。
- 意味は、実装（パーサ）とメタスキーマの説明を読んで書く。manual の言い回しを写さず、決まりだけを短く書く。使い方の説明は manual に置く。
- 見つけた実装のずれは、ここで直さず devtrack に登録する。
- 定義（`.yde/`）を変えたら `validate spec` を通し、`./gradlew specDocs` で生成物の変化を確かめる。
